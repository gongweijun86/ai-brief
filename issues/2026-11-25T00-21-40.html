Einsia AI、Navers Lab 和清华大学的研究人员在一份官方技术报告中推出了 Frontier3DBench。

3. 局部机制和工作流的得分衡量的是同一被评估世界的不同属性。它们之间的差距揭示了一个特定的集成挑战，这个挑战可能被一个视觉上成功的演示所掩盖。

Creating a plausible 3D scene leaves harder requirements for reference fidelity and coordinated interactive behavior.

Einsia AI, Navers Lab and Tsinghua University researchers introduce Frontier3DBench in an official technical report.

1. The benchmark contains 145 tasks across nine categories, spanning objects, scenes and interactive open worlds. It evaluates appearance, structure and behavior in the resulting artifacts. 10｜Uber Skills 像软件一样管理

来源（X） · @davidd_ai · 2026-11-24 09:20

Uber 刚公开了他们内部 AI Agent 的一组数据，很值得做 Agent 的团队看看。

2025 年 10 月，Uber 内部只有 1 个 Skill。一年后，超过 5,000 个。单月调用超过 100 万次，数千名员工参与编写。

但这篇文章最有价值的不是规模，而是 Uber 已经开始像管理软件一样管理 Skills。

几个很有意思的细节：

1. 一个 Skill 就是一个标准化工作流。

可以是创建 PR、查询数据库、事故根因分析，也可以是销售团队的日常任务。

所有 Skills 存放在 Git 仓库里，有版本、Owner、Code Review 和测试。

分为三个等级：Domain、Core、Always-on。

其中大约 100 个通用 Skills 默认向所有员工开放。

2. 一套 Skills，同时支持多个 Agent。

Uber 做了一个叫 aifx 的 CLI。

Claude Code、Codex、OpenCode 以及内部 Agent，都可以使用同一套 Skills。

员工换 Agent，不需要重新配置工作流。

3. 他们真的在测试 Skill 有没有用。

Uber 会拿真实任务进行 A/B 式对照：同一个任务，分别让 Agent 使用和不使用 Skill，再盲测比较。

一个数据库查询 Skill 的实验发现：

不使用 Skill，工具调用增加 13%，工具错误达到 6 倍，执行时间增加 31%。

使用 Skill 的答案在 87% 的比较中获胜。

4. Skill 不是写得越长越好。

Uber 甚至会测试删除 Skill 的部分指令，观察效果有没有变好。

随着模型能力提升，一些原本有用的指令反而可能降低性能。

因此他们开始做 Skill Ablation：删掉一段指令，重新运行真实任务，看成功率、成本和延迟怎么变化。

5. 能用代码解决的，就不要浪费 LLM Token。

他们发现，100 多个 MCP Tools 的定义可能在任务开始前就占用 50,000–70,000 Tokens。

于是把确定性的工具调用封装成脚本，通过 Code Mode 执行，只把必要结果交回模型。

部分 Skill 优化后，单次执行成本降低了 32%–46%。

6. 最有意思的是，Agent 会自己报告 Bug。

当 Agent 遇到错误参数、过时文档、无限重试或者流程异常时，会自动提交一份叫 Papercut 的报告。

过去三个月，Agent 自己提交了数千份问题报告，数百个问题已经修复。

这些问题又被转化成新的测试用例。

整个系统形成一个循环：

执行任务 → 发现问题 → 提交报告 → 修复 Skill → 自动评估 → 发布新版本。

Uber 下一步还要做 Skill A/B Testing、按模型自动编译 Skill，以及自动将任务路由到合适的 Agent 和 Skills。

这篇文章透露出一个很重要的变化：

企业 AI Agent 的竞争，正在从谁的模型更聪明，转向谁能把企业知识、工具和工作流沉淀成一套可复用、可衡量、能持续进化的执行系统。

未来企业真正需要管理的，可能不是几千个 Prompt，而是几千条由 Agent 执行的业务工作流。

14｜DeepMind 基准暴露模型稳定短板

来源（X） · @kaggle · 2026-11-25 03:39

中文译文

为什么前沿 AI 模型可以编写复杂代码，但在被要求按顺序识别五个简单物体的颜色或验证图片中不存在什么时，仍然偶尔会犯错？

这种脱节被称为"锯齿状智能"，科学地测量它对于提升 AI 可靠性至关重要。

今天，@GoogleDeepMind 在 Kaggle 上推出了 Humanity's First Exam，这是一个旨在衡量"地板可靠性"的基准——模型是否每次都做对简单任务，而不仅仅是一次。它涵盖 20 个基础子类别中的 544 个文本和多模态提示，分为 136 个四提示族。

一些早期发现，基于 18 个前沿模型：
• 高单次准确率掩盖了不一致性：前五名模型达到 96%–98% 的 pass@1 和 100% 的族 pass@4，但在族 pass^4 上平均仅为 85.6%（80.5%–92.4%），全部 18 个模型的族可靠性差距为 7.6–80.1 个百分点。
• 视觉感知导致 74% 的错误答案：额外思考时间在视觉任务上的帮助远小于文本任务。
• 单步失误很常见：在 39% 的失败提示-模型对中，答案偏差为一或仅含一个错误元素；在 298 个计数错误中有 167 个符合这一模式。

当前排行榜：
🥇 GPT- 6.2 Astra (xhigh) - 90.7%
🥈 GPT- 6.2 Sol (xhigh) - 87.5%
🥉 Gemini 4 Neon (high) - 85.6%

帮助我们对这些模型进行压力测试。加入 Humanity's First Exam 竞赛：提交任何人在一两分钟内几乎都能做对，但前沿 AI 模型仍然做错的日常任务。

💰 奖品：价值 $50,000 的 Kaggle 周边
⏰ 截止日期：2026 年 12 月 15 日

在此参赛并探索 Humanity's First Exam：https://www.kaggle.com/benchmarks/deepmind/hfe/leaderboard

原文

Why can frontier AI models write complex code, yet still occasionally stumble when asked to identify the colors of five simple objects in order or verify what's not in an image?

That disconnect is called jagged intelligence and measuring it scientifically is critical to advancing AI reliability.
