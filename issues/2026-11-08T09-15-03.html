01｜Harness-S 修复Agent失败

来源（X） · @AChaiNotes · 2026-11-08 15:58

Agent执行失败，很多人第一反应是换更强的模型。可有时错误发生在工具调用、状态管理或验证流程里，模型参数根本没动。

Harness-S研究观察到，从共同基础改造出来的不同执行框架，常常能修复彼此不同的失败案例。作者尝试让系统选择合适的“兄弟框架”帮助补救，再将能力迁移到统一策略。

它给开发者一个提醒：优化Agent不一定要同时推倒模型和工程系统。先定位错误是理解失败、工具失败还是流程失败，再决定该改哪里。

我会保留每个版本通过的任务集合，重点看新框架是否真正补上老框架的短板，而不是只比较一个综合平均分。

复制：先加 Dr Eggbot，告诉幕僚长「新 Bot 干什么」让它去造；每个 Bot 只给一个职责，共享记忆里写好「花钱/发送/删除先问我」。
“Bot 负责帮忙，拍板永远是你”！

2️⃣ 品牌社媒号全自动（https://x.com/Texas_Twins_Dad/status/2118510922108907750）

作者让 Grok Bot 接管自家 App 的品牌账号：每天自己做一条短视频、自己上传、自己填好标签和设置，全程不用人。
复制：建一个运营 Bot，写一条每日 routine「做一条短视频 → 上传 → 补齐标签和设置」，先手动审几天再放手。
“老板睡觉，账号照样日更”！

3️⃣ 巨鲸热力图一句话生成（https://x.com/mobyagent/status/2118420780799430801）

Moby Agent Marketplace 上新 Grok Bot Pages 技能：问一句「whale heatmap for TICKER」，Bot 用 Moby 链上数据搭一页实时看板：谁在买卖、何时、逐个钱包，外加价格、持币和安全信息。
复制：去原帖里的 http://moby.win/marketplace 装上这个技能，对 Bot 说「whale heatmap for 你关注的代币」。
“大户一动，你的 Page 先亮”！

4️⃣ Grok Bot 直接指挥 Codex 干几小时（https://x.com/clanhj611/status/2118288424440631645）

试玩新游戏发现十几个优化点，以前自己当传话筒，现在让 Grok Bot 出方案后用 codex exec 直接操控 Codex，几个小时的优化全程不用他参与。
复制：在装好 Codex CLI 的电脑上，对 Bot 说「把这些问题拆成方案，用 codex exec 逐条交给 Codex 实现，做完汇报」。
“别再当 AI 之间的人肉传声筒”！

08｜Pi Agent上下文分页替代压缩

来源（X） · @AISuperDomain · 2026-11-08 16:08

AI Agent 长时间执行任务，最怕的就是上下文爆满后触发 Compaction，导致早期的代码细节、错误日志和关键决策被摘要压缩。

pi-context-paging 提供了一种新思路：不压缩历史，而是让上下文像操作系统内存一样动态分页。

它为 Pi Coding Agent 设置滚动上下文窗口，默认达到 128K Tokens 时裁剪至 80K。旧历史不会被删除，模型可以通过搜索、浏览和读取工具，按需恢复原始记录。

无需频繁 Handoff，也不用重新解释之前做过的工作。

GitHub：https://github.com/rochecompaan/pi-context-paging

13｜Pi接入Claude Code复用订阅

来源（X） · @AISuperDomain · 2026-11-08 15:49

如果你喜欢 Pi 这个轻量级 AI 编程 Agent，但又想使用 Claude Opus、Sonnet 等模型，可以试试这个开源项目：pi-claude-bridge。

它通过 Claude Agent SDK，将 Claude Code 接入 Pi，让你直接在 Pi 的终端界面中调用 Claude 模型，同时保留 Pi 原有的工具调用与交互体验。

更重要的是，它可以复用 Claude Code 的 Pro/Max 订阅额度，不需要单独配置 Anthropic API Key。项目还支持 Skills 转发、会话续接、上下文同步等能力。

另外，配合 AskClaude 扩展，还能让其他模型将任务委派给 Claude Code，实现多模型协作。

安装只需一条命令：

pi install npm:pi-claude-bridge

GitHub：https://github.com/elidickinson/pi-claude-bridge
