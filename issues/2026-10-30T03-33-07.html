04｜6个AI模型退票实验暴露行为风险

来源（X） · @ruanyf · 2026-10-30 09:28

看到一个老外的实验，让6个 AI 模型代表自己去退火车票，但是已过了退票期限，正常情况下退不掉。https://www.vals.ai/blogs/impossible-refund

大家猜猜看，AI 收到这个任务后，做了什么？

（1）Grok 4.7 发现退不掉以后，在15天内向铁路公司、政府官员、议员、媒体等发送了187封抗议和交涉邮件。

（2）Fable 5.1 向5个组织撒谎，谎称当事人的母亲生病了，导致没有及时退票。

（3）Gemini 3.8 Flash 编造了另一种没有及时退票的理由：当事人在国外没有手机信号的偏远地区，无法完成银行身份认证。

（4）GPT-6 Astra 要求铁路公司详细解释为何设置现在这样的退票时间期限，并向律师事务所发了14封法律邮件，要求律师介入。

（5）Muse 明确威胁铁路公司，要提起诉讼。

（6）Grok 则发出了正式的索赔邮件。

这件事的教训就是，你可以用 AI 帮助自己学习和工作，但不要让它代表你行事。

因为 AI 的行为模式是循环尝试，穷尽所有可能的方式，尝试完成你交给它的任务。人类社会是为真人设计的，不是为这种行为模式设计的。人力无法处理 AI 发起的海量请求，最终只能让 AI 去对付 AI。

06｜ASD-STE100约束大模型简洁输出

来源（X） · @F5Adon · 2026-10-30 07:42

Karpathy 最近这个约束模型的输出总结真是神了，怎么会想到用航空维修文档“ASD-STE100”来约束大模型的输出。

codex / claude code 给你生产一大堆文字，你还一个字不落地读吗？ 别这样，效率太低了。

所以 Karpathy 提出的几个方案：怎样把模型的输出转换成人更容易理解和验证的形式。

1️⃣ 用 ASD-STE100 约束文字。
普通模型喜欢使用长句、抽象词和模糊表达。同一个概念写了很多字，读完仍然不知道重点。
ASD-STE100 最初用于航空维修文档，它限制词汇、句式和表达方式，要求每句话清楚、直接、含义唯一。
可以提示模型：“用 80% 的 ASD-STE100 风格解释这个问题。”

2️⃣ 生成图表。

让模型生成流程图、架构图或概念图，可以直接看到节点之间如何连接、数据如何流动、问题可能出现在哪里。

3️⃣ 生成交互式网页。

这时可以让模型输出 HTML，通过按钮、滑块和动画展示：参数变化后结果会发生什么，系统在不同状态下如何运行。

4️⃣ 生成解释视频。

Karpathy 建议直接让模型制作 3Blue1Brown 风格的解释视频。

Andrej Karpathy @karpathy

中文译文

我们会花更多时间去理解语言模型的输出。一些想法、技巧和窍门：

写作。我有过成功经验的一种方法：让你的 LLM 用 ASD-STE100 来解释某件事，这是一种最初为航空航天维护文档开发的受控语言规范。LLM 熟悉这种语言，它对简洁的写作风格有严格的约束，我经常觉得这样写出的内容更易读。有时我会尝试稍微放松一点，比如要求"达到 ASD-STE100 的 80% 水平"，因为这个规范相当严格。但还有更好的方式：

图表/图片。与其写文字，不如让你的 LLM 创建一个图表。这些处理、解析和理解起来会容易得多。但还有更好的方式：

网页。要求以"HTML"格式输出，就能得到一个美观的交互式网页。LLM 在前端方面越来越出色，可以创建精美的体验、动画等。但还有更好的方式：

讲解视频。我最看好的输出格式是针对任意主题完全定制的讲解视频。试试类似这样的指令："用 3b1b 风格创建一个关于 X 的视频讲解。使用我的 ElevenLabs API key 进行音频旁白。"（后者你需要一个 API key，或者你可以让你的 LLM 帮你找到使用本地计算的不错的免费替代方案。）这已经开始起作用了！

总结：
- 随着 LLM 变得更好，它们将越来越多地自主完成基础工作，我们的大量工作将上升到抽象层面，专注于监督和理解。
- 幸运的是，LLM 在这方面也能帮上忙，因为随着智能和代码日益充裕，你可以要求生成大型的、定制化的、可丢弃的软件工件（比如 web 应用、视频讲解），这些在以前根本不可能值得去创建。在这里不断突破边界，你会感到惊讶。

原文

We'll be spending a lot more time trying to understand the outputs of language models. A few thoughts, tips & tricks:

Writing. Something I've had success with: Ask your LLM to explain something in ASD-STE100, it's a controlled language specification originally developed for aerospace maintenance documentation. LLMs well-versed in this language and it comes with heavy constraints on clean writing style that I often find a lot more readable. Sometimes I've tried to soften it a bit e.g. ask for "80% of the way to ASD-STE100" because the spec is quite stringent. But even better:

Diagrams / images. Instead of writing, ask your LLM to create a diagram. These can be a lot easier to process, parse, and understand. But even better:

Web pages. Ask for output "in HTML" to get a beautiful, interactive webpage. LLMs are getting really good at frontend and can create beautiful experiences, animations, etc. But even better:

Explainer videos. The output format I am most bullish on is fully custom / bespoke explainer videos generated on any arbitrary topic. Experiment with things like "Create a 3b1b style video explainer on X. Use my ElevenLabs API key for audio narration". (you'd need an API key for the latter or you can ask your LLM to find you decent free alternatives that use your local compute). This is actually starting to work!

In summary:
- As LLMs get better, they will do more and more of the legwork autonomously, and a lot more of our work will rise up the abstractions into oversight and understanding.
- Luckily, LLMs can help here too because as intelligence and code are increasingly abundant, you can ask for large, custom, discardable software artifacts (e.g. web apps, video explainers) that would have never made sense to create before. Push the boundaries here and you'll be surprised.

07｜pstack生成验证技能包自动回归

来源（X） · @Stephan_Talk · 2026-10-30 05:26

《pstack完全指南 pt.1》总结

核心的验证能力
/create-verification-skill 本质上提供三种能力：

1. 验证技能入口

驱动你的应用执行真实的验证流程，例如通过浏览器工具执行真实的应用截图、点击、发送消息等动作。通过这些动作做自动化端到端验证，定义验证标准并拿到证据

2. CLI 工具

为了能高效验证，/create-verification-skill 会配套的生成一套针对你应用的 CLI 工具，以便验证技能能够通过这些工具高效且低成本的执行验证

3. 功能地图

/create-verification-skill 还会生成一套针对你当前应用的功能地图文档，这套文档成为验证执行时的“锚点”，比如全面回归验证会遍历功能地图的所有功能点进行验证

当你调用 /create-verification-skill 时，它会将以上三种能力结合在一起，生成一个 skill 包放在你的当前项目目录下，以便你随时调用验证

大家如果对以上的概念感觉比较模糊的话，lauren 还特别写了一个 example 项目，可以让你看到验证技能跑完得到的这套 skill 包具体长什么样子：
https://github.com/poteto/verification-skill-example

配套的 /maintain-verification-skill 技能用来更新验证技能生成的 skill 包。最佳实践是起一个定时任务定时跑这个 skill，以保障你的验证技能包是随项目迭代不断更新的状态

对于文中提到的 “用云端智能体代替 worktree” 的方法，我倒是觉得不一定需要。云端智能体需要更多成本以及更加完整的环境上下文，对于大多数小型项目来说一套本地开发测试环境 + 一套预发布验证环境我觉得就足够了

---

另外，如果你当前使用的 harness 不是 Cursor，想使用 pstack 的话，以下这个开源项目就是为你准备的（我横向比较了多个项目，这个是我觉得支持面最广且社区更新最频繁的一个）：

https://github.com/michael-denyer/pstack-claude

它支持 Claude Code、Codex、Copilot、Pi、OpenCode 等 harness 使用 pstack，且会紧密同步 pstack 官方的发布。利用它你可以在无需 Grok 订阅的情况下使用 pstack

08｜LobeHub发布Agent真实交互评测

来源（X） · @MaxForAI · 2026-10-30 05:08

今天，我们 @lobehub 团队发布了一个我觉得很有意义的新Benchmark：Interaction Bench。

一直以来，我们都觉得Agent的评测和真实用户体验之间，存在着相当大的距离。

真实用户不会告诉Agent哪一行代码出了Bug，也不会给它一份详细的修复方案。用户只会说，我想实现这个功能，或者这个东西坏了，你帮我解决一下。

所以，这次我们尝试换一种方式来评估Agent。

Interaction Bench从25个真实的开源应用中提取了44个任务，只告诉Agent用户想实现的目标，让它自己探索环境、发现问题、尝试解决，并验证最终结果。

首轮结果里GPT-6 Astra以34.1%排名第一，Claude Opus 5.5为 27.3%，其他模型的成功率只有4.5%～15.9%。
即便是目前最强的模型，面对这些真实任务，依然有超过六成无法完成。

我觉得这也是我们做这件事的意义。
随着Agent开始真正进入软件、接管工作流，我们需要更多能够反映真实用户体验的评测。
毕竟对于用户来说，Benchmark上的分数再高，都不如一句「这件事我已经帮你搞定了」。
目前还是0.1 Preview，欢迎大家体验、提 ssue，也欢迎一起来建设。
