01｜magpie 改用 agy CLI 登录

来源（X） · @magpie_router · 2026-11-16 02:19

magpie 内置的 Antigravity 和我们官方的 Antigravity 插件（opencode-antigravity-auth）都已下线（v0.1.4232 起）。

原因：它们模拟客户端直连 Google 的接口，账号容易被封。现在 magpie 不再用这种方式向 Google 发任何请求。

想继续用 Antigravity，请改装社区插件「Antigravity (local agy CLI)」：通过 ACP 驱动你本机登录好的 agy CLI，请求由官方客户端自己发出。风险更低，但不是零，别多号同时高频跑。

安装：Plugins 页搜 agy，或
magpie plugin add @magpie-community/opencode-agy-cli-auth

05｜magpie 换 Claude 订阅排障

来源（X） · @zi_xiang5806 · 2026-11-15 13:37

今天用magpie连接我刚刚买的的CC发生了一系列的事情：刚用 magpie 接好了新买的 Claude 订阅账号
把这次遇到的几个坑分享一下，给同样卡在登录步骤的人参考。

magpie 接入新 Claude 订阅账号：登录卡住的排查记录（Mac）

刚用 magpie 接好新买的 Claude 订阅，把遇到的坑记一下，给卡在登录步骤的人参考。

排查顺序：恢复 magpie → 查 Claude Code 版本 → 确认实际调用路径 → 添加新账号并授权

① magpie 点不开
多半是进程卡住了。打开「活动监视器」，搜索 magpie，强制退出后重新打开。我这样处理后恢复了，没有重装。
② 提示"登录未完成"，先看具体报错
我的报错是 error: unknown option '--claudeai'，原因是本机 Claude Code 太旧（2.1.38），不认识登录参数。执行 claude update 更新，再用 claude --version 确认实际运行的版本。

③ 更新成功了，版本却没变
提示已装 2.1.325，查版本仍是 2.1.38。原因是电脑里有两份 Claude Code，新版装进了另一套 Node 环境，终端和 magpie 还在调用旧版。用 which -a claude 查看所有路径，再把调用入口指向新版。路径因人而异，别照抄别人的。
④ 网页登录了，不代表 magpie 换号了
还要在 magpie 的「供应商」里添加 Claude 账号，并在浏览器授权时确认选的是新账号。成功的表现：新账号显示「使用中」，能读到订阅额度。

⑤ 只想在 CC 里用 Claude 订阅
选「只切换 Claude Code 的登录」模式：magpie 管账号切换，CC 走 Claude 官方服务。保存后要新开一个 CC 会话，旧会话可能还留着原来的账号。
"登录未完成"可能有多种原因，先看具体报错，再对症处理。

08｜OpenCodeReview 阿里开源

来源（X） · @Gorden_Sun · 2026-11-15 19:52

OpenCodeReview：阿里开源的代码审查工具

阿里将内部打磨两年的官方工具开源，可以通过API使用，也能接入Claude Code或者Codex。

它能直接针对具体的代码行号写出修改意见，精准抓出安全漏洞和逻辑错误，也能在接手陌生项目时直接对整个文件夹做全面体检。对比通用AI检查工具，准确率明显更高，检查速度更快，且更省token。这套工具已经在阿里内部服务了数万名开发者，提前拦截了数百万个代码缺陷。

GitHub：https://github.com/alibaba/open-code-review
