07｜GUARD稳定Agent自我改进

来源（X） · @omarsar0 · 2026-11-19 22:18

中文译文

Google 发布了一篇关于自我改进智能体 harness 的重磅论文。

（收藏它）

它解决了自我改进智能体 harness 中的常见问题，如局部过拟合、灾难性遗忘和记忆污染。

他们提出了 GUARD，该方法冻结基座模型，让智能体编辑自己的提示词、技能、工具规则和记忆。只有当编辑带来的收益超过其破坏的行为时，该编辑才会被接受。

- 在 43 个托管 SDK 任务上，GUARD 达到 80.80% 的准确率，比初始 harness 高 8.89 个百分点（p = 0.008）。
- 它比 Meta-Harness 高 6.28 个百分点，且每个任务使用的 token 减少了 54.5%。
- 在程序性记忆任务上，它以 90.1% 的更新正确率领跑，且零记忆污染。激进的重写器得分相似但污染增加了两倍。

它如何知道什么被破坏了？每个任务在执行前被拆分为自检项。每一轮都根据这些自检项对轨迹进行评分，固定智能体已经处理好的规则，并将新被破坏的行为排在优先位置。在测试时，一个冻结的 harness 以单次通过运行。

https://arxiv.org/abs/2611.23476

Chat with Paper: https://academy.dair.ai/papers/guard-stabilizing-recursive-self-improvement-with-regret-guidance-2611.23476

原文

Banger paper from Google on self-improving agent harnesses.

(bookmark it)

It addresses common issues in self-improving agent harnesses like local overfitting, catastrophic forgetting, and memory pollution.

They propose GUARD, which keeps the base model frozen and lets the agent edit its own prompts, skills, tool rules, and memory. An edit is accepted only when its gains outweigh the behaviors it breaks.

- On 43 hosted SDK tasks, GUARD reached 80.80% accuracy, 8.89 points over the starting harness (p = 0.008).
- It beat Meta-Harness by 6.28 points and used 54.5% fewer tokens per task.
- On procedural memory tasks, it led update correctness at 90.1% with zero memory pollution. Aggressive rewriters scored similarly and tripled pollution.

How does it know what broke? Each task is split into self-checks before execution. Every round grades trajectories against them, pins rules the agent already handles, and ranks newly broken behaviors first. At test time, one frozen harness runs in a single pass.

08｜LangChain开源设计Agent

来源（X） · @shao__meng · 2026-11-20 10:12

LangChain 开源 Design Agent，把公司在用的 Content Studio 公开，用每线程沙箱和品牌检查在 Slack 交出平面、演示文稿和影片

@LangChain 把公司内部在用的 Design Agent「Content Studio」开源。它建立在 Deep Agents 上，默认用 Managed Deep Agents 部署到团队 Slack：在线程里说明需求、附上文件，就会拿回符合品牌规范的平面、多尺寸广告、演示文稿、图表、分镜和影片。也可以用命令行、HTTP API，或自己用 Docker 托管。自 8 月起它已为公司交出 3000 多件物料，演示文稿超过 80 份；带这些视觉的帖文在 X 上大约有 450 万次浏览。四分之三的需求来自市场部门以外。单次请求的模型费用中位数大约是 0.5 美元，9 月中旬还大约是 8 美元。

开源地址：https://github.com/langchain-ai/design-agent

一条 Slack 线程、一台设计用电脑

Managed Deep Agents 负责 Slack、记忆、定时任务，以及每条线程一台 LangSmith 沙箱；仓库补上设计工作流、品牌包和渲染工具。沙箱是一台 Linux 机器，里面有 Chrome、FFmpeg、HeyGen 的 HyperFrames、D2 和团队字体，由 sandbox/setup.sh 搭起来。成品都以代码写在项目目录里：幻灯片是 HTML，影片是动画时间线，改完再渲染即可。密钥不进沙箱，默认也没有外网；图像、语音、音乐在沙箱外调用，Notion、GitHub、Figma 一类 MCP 经 MDA 接入，每个人用自己的账号登录。

一条 Slack 消息会随步骤更新，页脚显示进度和目前费用，中途补的意见也能进正在进行的工作。大任务由主 Agent 拆开，在同一沙箱里后台启动子 Agent；做完、失败或卡住时，MDA 会叫醒主 Agent，它不用空等，还可以继续对话。影片按分镜、动态预演、正式制作推进，每一段先过检查再组装。HyperFrames 把影片当成时间线上的网页来做，Paper 是可以改分镜或版式的共享画布。

技能路由、品牌检查，以及它怎么变好

常驻提示很短。每次请求先读路由技能，再从 35 项技能里选出对应流程，由 Context Hub 按需加载。设计维基里是字体、色彩、版式、图表这类手艺，品牌包里是颜色、字体、标志和语气。渲染之后会先看成品再发出；颜色、字体、对比、尺寸和图表计算由代码在每次渲染时检查。规则可以说一次就记下，分成全员共享的团队记忆和每人一份的个人记忆。任务结束后，learn_from_job 按所用技能记下有依据的经验，后续任务会阅读并评分，站不住的会被丢掉。

他们写到，早期为了补模型短板做过 115 个可复用界面组件；Claude Opus 5.5 出来后质量明显提高，他们删掉了大部分硬编码规则，留下设计原则和高层指引。默认模型就是 Claude Opus 5.5，也支持 OpenAI、Google 和 LangSmith Gateway。Managed Deep Agents 在 LangSmith Cloud 上仍是公开测试；代码免费，模型和托管要另付。本地可以用脚本化模型、不配密钥跑演示，走真实的 Agent 图、沙箱和检查。

10｜Claude Code重构用差分测试

来源（X） · @ai_suxiaole · 2026-11-20 10:00

用 Claude Code 重构代码，一定要学会差分测试。

哪怕测试用例全部通过，也不能保证重构后的代码和原来的业务逻辑一致。

老代码里对空值、重复订单、跨月日期等特殊场景的处理逻辑，可能根本就没覆盖到测试用例里。

差分测试的操作很简单。

重构之前，挑选 20 个有代表性的测试样本，包括正常场景、边界场景、异常场景，以及历史上出过 Bug 的场景。

用旧代码跑一遍，记录输入和实际输出。
用重构后的代码再跑一遍，对比两次的输出结果。
找出所有差异，逐一分析原因，确认是否符合预期。

可以直接把下面的提示词交给 Claude Code：

我要重构【模块】，先不要修改代码。

1. 梳理模块的输入、输出和可运行入口。
2. 从现有测试和历史问题中挑选正常、边界、异常样本。
3. 运行旧实现，记录每个样本的输入、输出和运行条件，建立测试基线。
4. 重构完成后，使用相同的样本和运行条件重新执行测试。
5. 对比新旧实现的输出，列出所有差异、产生原因，判断是预期变更还是功能回归。

遇到无法判断的差异，先向我确认，不要擅自修改原有业务逻辑。
这种方式适用于老项目重构、编程语言迁移、框架升级和依赖替换。

即使旧代码本身存在 Bug，也要先识别出差异，再决定是否修复。

别让 AI 在重构代码的时候，顺手把业务逻辑也给重构了。
