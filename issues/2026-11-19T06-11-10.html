03｜AI系统设计指南覆盖推理到监控

来源（X） · @Zen_with_AI · 2026-11-19 12:19

AI 系统设计指南，面向 AI 工程师和系统设计面试。

调用一次 API 只要十行代码。要扛住十万用户、首 token 一秒内出来、不泄露数据、不超预算，才算系统设计。这份指南帮你回答这些实战问题。也是面试经常考到的。

主线：Tokens -> 推理服务与 GPU -> Prefill 与 Decode -> 缓存与路由 -> RAG -> Agent 与 MCP -> Guardrails -> 评估与监控

推理。Prefill 受算力限制，决定首 token 延迟；Decode 受显存带宽限制，决定后续出字速度。长 prompt 的 prefill 会卡住别人的流式输出，所以有 chunked prefill，规模大了再把两个阶段拆到不同 GPU 上。

估算。示例：1000 万日活，每人每天 5 次对话，每次 2000 输入加 500 输出，一天 1250 亿 token，大约需要 60 到 100 张 H100。

安全。Prompt injection 的硬规则要写进代码，不能只写在 prompt 里。

面试。给了 8 步框架：需求、AI 目标、数据、架构、模型与提示词、评估、部署、监控。另有 Claude Code、Cursor、实时语音 Agent 三个案例。

https://github.com/amitshekhariitbhu/ai-system-design

06｜new-api本地网关统一模型用量

来源（X） · @dapeng667 · 2026-11-19 12:44

别等月账单来了，才发现 Claude Code 通宵都在用最贵的那一档，而且你对不上是哪次对话烧掉的。

QuantumNous/new-api，约 52195 星，日增约 80。一句话：在自己机器上搭一个网关，把各家模型接口收在一起，路由、用量和花费都能看见，Claude Code 这类助手改个地址就能接上。

以前每换一家模型，就要在每个助手里改一遍地址和密钥，账单散落在各家后台，对都对不齐。现在本机有 Docker 的话，可以先运行 docker run --name new-api -d --restart unless-stopped -p 127.0.0.1:3000:3000 -e TZ=Asia/Shanghai -v "$(pwd)/data:/data" calciumion/new-api:latest。然后用浏览器打开 http://localhost:3000，按向导建管理员账号。在控制台把自己合法拿到的上游密钥加成渠道，再生成一把网关自己的密钥。Claude Code 或其他 OpenAI 兼容助手，把接口地址改成 http://localhost:3000/v1，密钥换成这把新的就行。生产环境也可以用仓库里的 Docker Compose，把 PostgreSQL 和 Redis 一起拉起来。

能干嘛：
- 把 Claude Code、Codex 接到同一个网关，换供应商不用每个客户端再配一遍
- 按优先级和权重做模型路由，这条渠道挂了就重试下一条
- 在面板里看用量、花费和日志，给额度设上限，避免某个助手把钱烧光
- 同时兼容 OpenAI、Claude、Gemini 这些常见协议，自己写的脚本也能走同一套地址

钱要花在刀刃上，先得看得见花在哪。提醒一句：要用自己合法取得的官方密钥，并遵守各家条款，官方写明这是给合法授权的网关和私有部署用的，不要拿去对外转卖接口。开源许可是 AGPLv3。上面这条启动命令默认只绑在本机 3000 端口；要是暴露到公网，先配好 HTTPS 和鉴权。

https://github.com/QuantumNous/new-api
