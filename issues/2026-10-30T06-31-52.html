01｜Grok Bot用Agent群管软件发布

来源（X） · @xiaomovps · 2026-10-30 09:12

Grok Bot 背后的女工程师，一个月交付 2500 个 PR，到底有多强？🔥

最近一直在研究 Grok Bot，发现它背后有一位非常厉害的女工程师 Lauren Tan，X 账号是 @poteto

她之前在 Meta 参与过 React Compiler 的核心开发，后来加入 Cursor，现在又成了 Grok Bot 的核心工程师

最夸张的是，她在今年 9 月分享了一场演讲，说自己上个月往生产环境交付了 2500 个 PR，而且很多代码已经不需要她亲自编写和审查

我又翻了一下她以前的经历，发现这个人确实挺有意思的

她从小就开始自学网页设计，大学读的是金融，后来转行成为程序员，在 Netflix 做过技术负责人和工程经理

但是她当了两年管理者之后，发现自己还是更喜欢亲手创造产品，于是主动辞去管理岗位，重新回到了工程师的位置

后来去了 Meta 的 React 团队，参与 React Compiler 的架构重写，2025 年 React Compiler 1.0 正式发布时，她也是官方文章的署名作者之一

今年她又去了 Cursor，最后开始参与 Grok Bot 的开发

比较有意思的是，她以前放弃过管理工程师，现在却开始用 Grok Bot 管理一整个 AI 工程团队

她最近分享的几个玩法，我觉得非常值得学习

第一个是直接用 Grok Bot 管理软件发布

她创建了两个 Team Bot，一个叫 sandcastle，专门负责发布管理，另一个叫 poteto，负责工程问题

需要发布新版本时，她只要通知 sandcastle，它就会自动联系相关开发者，确认本次要合并哪些 PR，有没有需要处理的问题

确认之后，Bot 会启动构建，再派出 10 多个 Grok Agent 模拟真实用户操作产品，有些专门测试指定功能，还有一些会随机乱点，看看能不能找出新的 Bug

发现问题后，再交给工程 Bot，通过 Cursor Projects 调用 Agent 定位和修复，最后根据问题严重程度决定是否需要补丁版本

相当于把以前需要好几个人协调的发布、测试和修复流程，交给了一组 Bot 来完成

第二个是用 Grok Bot 管理自己的 X 账号

10 月 27 日，她还公开了自己一直在用的 Tibot

这个 Bot 可以监控别人有没有提到自己，或者讨论自己关注的关键词，不一定非要 @ 你

还可以自动过滤垃圾信息、翻译外语内容，每天定时把值得看的帖子整理成摘要，甚至按设置处理骚扰账号

不过她自己也强调，所有帖子和文章仍然是自己写的，Bot 只负责收集信息和整理内容

这个思路其实挺适合我们这些长期在 X 创作的人，不需要让 AI 替你写内容，先把素材收集和信息筛选自动化就够了

第三个是让 Bot 自己管理 Bot

她还做过一个叫 Dr. Eggbot 的机器人，专门帮用户设计、检查和改进其他 Bot

在她的工作流里，Grok Bot 更多负责连接 Slack、X、邮件这些外部信息，收集需求和问题，再把任务交给 Cursor 的工程 Agent

真正写代码、运行测试和修复问题的是另一套系统，而她自己开源的 pstack，则负责把工程规范和验证流程沉淀下来

所以前面提到的 2500 个 PR，并不是 Grok Bot 一个月独立开发了 2500 个功能，而是她通过这整套 Agent 工作流完成的交付，其中也包含大量重构和维护工作

我觉得她身上最值得学习的，并不是同时开了多少个 Agent，而是她很早就意识到了一个问题

如果 Agent 每次做完事情都需要人去检查、修正、重新解释需求，那么开再多的 Agent，其实还是人在管理整个流程

所以她一直在做的事情，就是把测试、验证、工程规范和任务分发逐步自动化，让 Agent 能够自己发现问题，也能自己证明任务完成了

这也是我最近越来越看好 Grok Bot 的一个原因

它不只是一个可以聊天、帮忙执行任务的 AI 助手，而是可以通过连接其他工具，把不同的 Bot 组织起来，长期处理一整套工作流程

对于普通用户来说，可能不需要她那套复杂的软件工厂，但完全可以从一个负责收集信息的 Bot 开始，再逐渐扩展到自动整理、任务分发和执行

相比单纯追求 AI 能做多少事情，我觉得让它能够长期、稳定地把一件事情做好，可能才是 Personal Agent 真正有价值的地方

02｜Anthropic模型自主编写0day

来源（X） · @ScarletKc · 2026-10-30 10:55

这太夸张了

Anthropic 一个还没发布的模型，自己写出了一个 Linux 内核的远程 root 漏洞利用。不用账号，不用你点任何东西，只要服务器开着 MPTCP 监听，隔着网络就能拿到 root。

漏洞是 CVE-2026-98432，9.8 分，TCP 握手里的一个竞态，从 Linux 4.4 就在了，藏了十年。它先花 48 分钟泄露内核地址，再 5 分钟拿到 shell，失败了机器也不会崩，可以一直试。

以前这种远程拿内核 root 的完整利用链，是极少数顶尖团队才做得出来的。现在模型给点提示就能做，同一份报告里还有 Chrome、Safari、Windows 的。

更离谱的是上游早就修了，补丁谁都能看，可到现在 Ubuntu 和 RHEL 还没发修复内核。以后补丁已经公开，但你还没打上的这段时间，大概就是最危险的时候。

有服务器的先 uname -r 看一下。Debian、SUSE、Oracle、Amazon Linux 2023 已经有新内核了，升完记得重启。Ubuntu 和 RHEL 暂时只能先把用不到的端口关掉，盯着官方公告等更新。

03｜币安热钱包被盗33亿USDT

来源（X） · @LabSpeculation · 2026-10-30 07:35

币安自己的钱包往一个被黑客控制的热钱包里转了 2 亿 USDT，72 秒后，这 2 亿就被黑客扫走了，这是北京时间凌晨 5 点 42 分的一次异常。

这次被盗，我把以太坊链上的记录一笔一笔翻完了，有一笔 2 亿 USDT 的转账，我来回看了好几遍。

被控制的这个钱包叫 Binance 14，光是发出去的交易就有 1891 万笔，是币安的主力热钱包之一。

黑客用的是 EIP-7702，这是以太坊去年加的功能，普通钱包可以把执行权委托给一个合约，委托以后，合约让它转什么它就转什么。凌晨 4 点 20 分，黑客给 Binance 14 设上了委托，不到 4 分钟，一笔交易就把里面的钱扫空了。这一笔大概 25 亿，再加上后面通过它从另一个钱包转走的 8.2 亿 USDC，就是大家说的 33 亿。

可钱被扫空以后，币安的系统好像没反应过来。

用户充到币安的钱，会先进各自的充值地址，再定时归集到这种热钱包里，被盗之后这套归集还在照常跑，又进来 2199 个 ETH，黑客分三次扫走了 2198 个。

那 2 亿 USDT 是 Binance 124 补进来的，这是币安自己的钱包。好在黑客收这笔钱的地址已经被 Tether 拉黑，钱现在冻在里面。

6 点 22 分，何一发推说暂停提币。

17 分钟后，黑客又扫了 Binance 14 一次，这次拿走 128 个 ETH 和 122 种代币，换了个新地址收。

我最后一次查是 6 点 57 分，Binance 14 上的委托还挂着，指向的还是黑客的合约，币安从 6 点 55 分开始，把这个钱包里剩下的币往自己的冷钱包里转，等于在跟黑客抢剩下的那点东西。

我最注意的还是 4 点 20 分那笔交易。

里面一次塞了 50 个授权，每个都得用 Binance 14 的私钥签名，它们只是序号不一样，最后对上了 1 个，也就是说，黑客手里提前就有 50 个币安私钥签好的授权。

主扫之后 24 秒，另一个热钱包 Binance 16 用自己的私钥签了几笔转账，2.8 万个 ETH 和 5574 万 USDT，就这样直接转给了黑客。

所以我觉得黑客能让币安的私钥替他签名，问题多半出在签名系统上，等币安出了调查结果，我再拿链上记录对一遍。

稳定币能冻，ETH 现在还冻不了，所以真正跑掉的主要是 ETH，黑客光一个地址里就躺着 19.5 万个，到现在一个没动。

黑客的地址现在已经被人刷爆了，有要钱的，骂人的，刷经文的，还有发链接说黑客还要打另外 3 家交易所的，这几天肯定会混迹很多钓鱼链接，一定小心。

这些记录链上都查得到，有兴趣自己去查查。

黑客的技术也越来越成熟，这就是AI时代，交易所要跟上时代的脚步啊！！

04｜Claude Code状态栏烧Token

来源（X） · @KobinFlow · 2026-10-30 00:41

作为一个天天吹 Claude Code 的死忠粉，今天看到这个抓包直接给我干沉默了……

我一直纳闷自己的 Token 额度怎么见底这么快，以为全烧在写代码上了，结果真相竟然是：终端底下那行小小的状态栏，在疯狂偷我的 Token！

翻开后台机制才发现有多离谱：它每隔约 30 秒，就会把整段对话上下文原封不动塞给模型跑一轮，大费周章烧一堆输入 Token，就为了刷新状态栏那 3、5 个词（比如什么 “Thinking...”）！

根据 flamerix 的测算，光这个纯装门面的操作就吃掉了 16.4% 的 Token；在冲上热榜的 Hacker News 讨论区 里，甚至有人测出高达 26%。

相当于你的 Token 额度里，有五分之一纯粹是在给一个打字机动画买单。

现在 GitHub Issue #86879 已经被大家喷麻了。真心建议大伙在官方出补丁前，长对话千万别开着挂机发呆，纯纯给它送钱！

Kobin @KobinFlow

现任 Anthropic Claude Code 核心成员、前 Google Chrome 工程总监 Addy Osmani刚发了篇长文，直接点破了很多人现在的 AI 编程误区：你大概率一直在“过度提示”（Overprompting）Claude。

最扎心的一个事实是：Anthropic 官方把 Claude Code 的系统提示词直接砍掉了 80%，结果模型代码跑分一点都没掉！

很多人还在用一两年前伺候老模型的那套“保姆式习惯”写 Prompt，字数越堆越多。面对 Opus 5.5 这代新模型，真正高手都在做减法：

1. 别教它怎么走，只给两件事： 一句话说清「终极目标是什么」+「怎么验证做对了」。只要你给它一个能跑出 Pass/Fail 的单测或判定脚本，它自己就能死磕闭环到底，根本不用你寸步不离地盯着。

2. 别迷信复杂的多 Agent 架构： 很多人喜欢无脑堆 Subagents，但 Addy 直言：子智能体不仅不会让事情变聪明，还会让延迟和账单成倍暴涨。从实测来看，「单个带 Skills 的 Agent」在代码质量和性价比上往往完胜多 Agent 编排。

3. 不知道怎么做，就让它反向面试你： 需求不明确时，别硬憋 Prompt。让 Claude 提问面试你，直到它能整理出一份完整的需求 Spec；然后开个新会话，拿着这份 Spec 丢给它直接开工。

4. 别当人肉代码扫描机： 代码写完，先调一个没看过聊天记录的独立 Agent 去把 Diff 审一遍、改一轮。把低级问题全甩给机器，人类只留着精力给核心业务风险做最终裁判。

一句话总结： 模型每升级一代，你最该做的第一件事不是拼命加规则，而是赶紧去提示词里“删代码”。每隔几个月给你的 Prompt 瘦一次身，别用伺候老模型的旧习惯，束缚了新模型的发挥。

05｜DeepMind提出AI经济的协作门槛

来源（X） · @Zen_with_AI · 2026-10-30 00:40

小路读了 DeepMind 今天发的《The Economics of Intelligence》，推荐给您。作者是 Alex Imas、Andrew Koh 和 Shane Legg，文章基于论文《Organizational Intelligence》。

主线可以压成一条链：

单个 agent 是错的单位->组织在竞争->能力和协作两道门槛->工资先变，结构后变

先看问题。AI 的能力在指数增长，经济却几乎没变：职位、人数、生产率都和几年前差不多。作者的回答是，市面上的基准大多测单个 AI 在真空里做题，但经济转型是组织竞争的均衡结果。一个模型在一对一比赛里超过每个人，照样可能输给一支互补的团队。

他们做了个小实验。100 人做六个领域的测验（数学、语言推理、科学、模式、文化、经济），一个领域的成绩，对预测另一个领域的成绩帮助不大。人是各有短板的专才。组织的作用，是把互补的专才拼起来，补上彼此的缺口，作者叫它 mosaic intelligence。互补配对完成任务，比随机配对高 32%。

团队里还有第三种人：协调者，也就是经理。单看基准，他们是最弱的，写代码和写文章都只是平均水平，但他们让所有人更高效，所以工资也很高。

AI 和人有两点不同：

可复制。模型一旦到了某个能力，就能按算力价格随便租，一旦 AI 能匹配人的能力，人的工资就被锚定在算力成本上。而且 AI 的短板彼此很像，再复制一份，只增加容量，不增加广度。

协调。限制公司规模的是人类的带宽和激励错位，AI 没有这些限制，同一个模型的副本能直接传递完整的工作状态。不过今天的 AI 协调得很差。
由此得出两道门槛。能力提升会平滑地改变工资、价格和人机配比，行业结构基本不变。协作越过 supercooperative 阈值，才会引发集中度、就业和工资的突变。作者把组织规模分成三个阶段：协作太差时单干更好，中间是我们熟悉的、规模有上限的世界，越过阈值之后每多一个成员反而让团队更高效，科斯天花板被打破。

我们知道两个维度交叉可以得到四种状态：

Minimal AGI：结构几乎不变，变的是工资。技能被 AI 匹配的人，工资向算力成本靠拢，专才和协调者反而涨。

Supercompetent AI：公司更高效，但更小，作者的说法是"富足而不集中"，人转向判断和协调。
Supercooperative AI：规模报酬由凹变凸，深市场里出现少数大型 AI 公司，工资骤降。小众市场受需求限制，暂时保得住，但涌入的工人会压低工资。
ASI：两道门槛都过了，小众市场也不再保护人类。作者推测财富会流向关系型部门（医疗、教育这类人的参与本身就是价值），并出现今天想象不到的新工作。
再看现实。能力强，协作弱：OpenAI 的 Noam Brown 说，让大量 agent 协作很难，他不会把 10% 的功劳归给多 agent。劳动力市场也对得上：更精简的创业公司、更扁平的组织、入门岗位的招聘变软，有经验的人需求稳定。

所以两个结论：第一，要盯协作，需要给"agent 组织"做基准。第二，AI 的影响先出现在工资上，早于就业和市场结构，所以光看就业率，不能证明 AI 没有影响。

简单总结一下就是：单项能力变强，经济变得平滑，协作过了阈值，经济才会突变。不能只盯着 benchmark 分数，也看看 agent 能不能一起干活。

原文：
https://institute.deepmind.com/essays/the-economics-of-intelligence/

06｜Agent记忆系统不如原始记录RAG

来源（X） · @Xudong07452910 · 2026-10-30 11:27

RAG 又杀回来了。

最近 Agent Memory 越做越复杂，但这篇《Memory Tax》发现了一个挺尴尬的结果：

很多专门设计的 Memory 系统，最后还不如直接对 raw history 做 RAG，而且成本更高。

作者把 Memory 的价值拆成两部分：

Memory Benefit：RAG 答错，但 Memory 答对的问题。

Memory Tax：RAG 本来能答对，经过 Memory 处理后反而答错的问题。

问题就出在「整理记忆」这一步。

历史被摘要、重写和结构化以后，一些细节会直接丢失；另一些虽然还在，却变得更难检索。

比如在 LongMemEval 上，Qwen3.6-27B 用两轮 RAG 能做到 81.4%，GPT-5.6 Luna 达到 90%，都高于对应的复杂 Memory 方案。

一个简单的修补反而很有效：

Memory 继续用，但同时保留 raw history 的检索通道，再把两边结果一起 rerank。

这篇工作也给我们做了一个提醒，给 Agent 加 Memory 之前，最好先拿最简单的 raw-history RAG 做个 baseline。

有时候，真正昂贵的并不是「没记住」，而是过早把原始信息总结掉了。

07｜微软开源Token插件省三成成本

来源（X） · @TiagerBao · 2026-10-30 12:34

微软搞了个专门给 Claude Code、Codex 省钱的开源插件，实测成本降低 18.4%～30.9%。

项目叫 TokenEconomizer，不换模型，也不用修改 Agent 本身。

主要做三件事：

记住经验：同一个项目踩过的坑，下次不再重复
精简工具：自动移除长期不用的工具，减少 Token 消耗

09｜智元用Worken度量机器人真实产能

来源（X） · @AI_Whisper_X · 2026-10-30 12:16

智元 AI Day，讲了好多行业大实话。

1/ 他们想把行业推到一个新的竞争维度。
会上提了一个新的概念，叫worken。
Worken = 活跃机器人数量 × 自主工作时长 × 产出效能比
为什么需要？造了多少台不等于多了多少生产力，度量不清楚就没法定价，行业只能继续比谁的 demo 好看
说白了，智元想让行业开始比：你部署了多少台真在干活的机器人，每台能顶几个人。
他们甚至把自己的“一台机器人现在只抵半个到 0.7 个人”拿出来了，龙旗 0.7×、长隆 0.6×、广州地铁 0.5×。

2/ 具身智能的临界点还没到
长隆是智元最大的部署点，9 月 24 日开园，300 多台机器人分在 100 多个点位，有的跟人下三子棋、猜拳，有的带一队游客讲解。王闯说最开始“几乎就是机器人跟工程师一比一，有几百个机器人，就有几百个工程师入场”。后来降到 3 比 1，今年压到 10 比 1，明年目标 20 比 1。
几百台机器人配几百个工程师，王闯在群访时候特别直白，“这本质上就做成了一个个项目，而不是一个能够规模化的生意”。人机比降不下来，效率就上不去；效率上不去，Worken 就算不过来。
他说 20:1 是临界点，按他的估算，这个岗位只需新增约 5% 的支持人力预算，客户就能接受。

3/ 服务业反而比工业先跑通。工业对性价比、节拍、稳定性、安全的要求比服务业高得多；服务业客户看的是机器人能不能带来流量、情绪价值和营收，不会像工厂那样要求节拍必须超过人。长隆飞船乐园开了之后客流量提了将近 40%，客户直接续了二期，现场机器人往 500 台扩。

4/ 灵巧手还不敢上真实场景。10 自由度以上带触觉的灵巧手里 OmniHand 出货最多，但“说实话大部分的客户并不敢在真实场景中作业”，成功率还没夹爪高。

5/ 2 万台下线，几千台在岗。 智元 9 月第 2 万台机器人下线，工信部说中国今年人形机器人整机产量要破 10 万台。王闯被问到今年部署态能有多少，答的是“我自己觉得今年真的部署态能有几千台就很厉害了”。
他还预计机器人以后会是比手机流量和总数都更大的通讯终端，跟人抢流量。长隆里机器人跟游客抢流量，最后做了机器人专用的网络，“碳基人类有他的网络，硅基的机器人有它自己的网络”。
6/ 姚卯青的演讲也很有意思。 “有人说 AI 已经要击穿具身智能了，你看怎么办？我说这能怎么办？很简单，AI 要击穿物理、AI 要击穿具身智能，那我们就成为 AI，我们要成为 AI 那边，不要成为被击穿的那边。”

他引了 GPT-6 Astra 的数：120 项仿真任务平均成功率 66.3%，能力集中在语义理解、动作规划和离散决策，“通用模型越强，具身行业起点会越来越高，这是明确的行业利好”。但单次推理 18 秒多，高动态、精细作业做不准，这是大模型现在落不了地的原因。GO-3 Preview 在 RoboDojo 同一个榜单登顶，靠的是模型加 Genie Master 的组合。
7/ GO-3 Preview，这部分很有意思，探索了机器人能不能复制大模型的 Scaling
预训练 scaling，数据和模型一起扩大，简单任务可以 Zero-shot，像拼乐高这种复杂任务，给少量示范也能学会。

后训练 scaling，真机这条叫 CEL，96 台机器人共享经验，失败了就去成功轨迹里检索相似片段，拿来当监督，人只负责说成或败、把场景复位。在世界模型上叫 Rollback，能倒回决策点，换动作推演后果，冰壶、投球几小时后就超过了人类玩家平均成功率。
部署之后持续学习，精灵 G2 在真便利店补货，无人工示范，自己找失败原因、自己改动作，完整任务成功率首日 28.6%，第五天 85.7%。Physical RSI，机器人自己迭代自己。
