03｜craft-anything逆向还原软件

来源（X） · @fishjar · 2026-11-02 01:16

逆向工程界这两天迎来了一个极其亮眼的 Rust 开源新项目：craft-anything。

它的定位非常硬核：帮助工程师彻底理解手头任何封闭软件的底层工作原理，并在理解的基础上重新构建出属于自己的原生版本。

不同于传统的 Ghidra 或 IDA Pro 只专注于将汇编语言反编译成伪代码，craft-anything 的切入维度是在系统行为层面做全景观测。

你给它输入一个未知的可执行文件或前端打包应用，它会在沙箱内自动Hook该软件所有的系统调用、内存状态机迁移以及网络底层协议封包；
接着利用内置的符号执行引擎，自动将散乱的 API 请求和内部事件流，拓扑重构出一张完整的业务架构交互图；
最后直接生成一份结构清晰的模块化规范与骨架代码。

对于想要学习优秀开源项目、或者需要逆向对接遗留系统私有协议的工程师来说，这套工具几乎把原本需要几天的人工抓包分析压缩到了几分钟之内。

源码用纯 Rust 编写，内存占用极低，跨平台运行丝滑顺畅。

开源地址：https://github.com/storytold/craft-anything

05｜Spec Kit强制AI先写规范再编码

来源（X） · @echoecho1996 · 2026-11-01 06:04

GitHub 刚刚解决了 vibe coding 的最大问题。

他们推出了 Spec Kit，短短时间就积累了 +120K 颗星。

它是什么？

与其抛出不精确的提示，然后交叉手指祈祷代理不会毁掉你的项目……

Spec Kit 强制 AI 在动一行的代码之前，先起草一份结构化的规范。

首先 AI 会：
→ 理解你想构建什么
→ 询问它缺少的信息
→ 构建项目结构
→ 然后才开始编程

这意味着更少的时间修复荒谬的错误，更少的无序代码，以及在使用代理时结果更可预测。

流程很简单：

/constitution → 规范和标准
/specify → 你想构建什么
/clarify → 启动前的疑问
/plan → 架构和技术栈
/tasks → 有序的任务
/implement → 执行

它适用于 Claude Code、Cursor、Copilot、Codex、Gemini CLI 以及其他 +25 个代理。

• 120K 颗星。
• 10K 个 fork。
• 开源。
• 由 GitHub 发布。

06｜Magpie改用TUI降低Token消耗

来源（X） · @yetone · 2026-10-31 21:38

大家好，Magpie 今天有一个很重要的更新，就是 Magpie 中的 Claude Code Provider 的实现方式，从之前的使用 claude -p 改为了直接使用 Claude Code TUI。当然这是可配置的，你可以设置回以前的方案。

关于为何做这个改动，其实一开始我是不太情愿的，因为使用 Claude Code TUI 去做这个实现的话，会特别多额外的工作。收益不是很高，甚至 streaming 没法完美实现。但是最近发生了一件事情，让我觉得我不得不得不做这个改动了，就是有人发现直接使用 claude -p 在 5 小时窗口情况下，会比用 Claude Code TUI 多花两倍的 Token（虽然 Claude 今天已经取消了5小时窗口，但是我不确定 Anthropic 以后会不会有其他的区别对待）

换成直接用 TUI 方式实现，除了能够让我们的额度消耗跟直接使用 TUI 一模一样之外，另外一个更大的优势就是在 Magpie 使用 Claude Code Provider 跟用户直接使用 Claude Code TUI 是一模一样的，几乎没有了被检测出来在第三方使用导致封号的风险。
