02｜LoopForge 管控 Agent 开发交付

来源（X） · @Xudong07452910 · 2026-11-17 09:20

推荐腾讯开源的 LoopForge，一个面向 Coding Agent 的软件开发与交付工作台。

它把 Agent 的开发、代码评审、测试和人工验收组织成可重复执行的 SOP（标准工作流程）。

比如，一个需求进来后，可以让不同 Agent 分别负责设计、实现和 Review，脚本负责运行测试，最后由人来审批。如果某一步没通过，还能退回指定节点重新执行，整个过程的日志和产物都会保留。

它支持 Codex、Claude Code、Pi、DeepSeek Harness 等 Coding Agent，可以在 Docker 沙箱中运行，也提供直接集成到现有 Coding CLI 的本地工作流。

我比较关注这类项目对 Agent 工程化落地的价值。

Coding Agent 能力越来越强，如何让多个 Agent 按照稳定的流程协作，让每次代码修改都有检查、有记录、失败后能够恢复，可能会成为团队大规模使用 Agent 的关键。

💻 GitHub: https://github.com/Tencent/LoopForge

03｜Harness 以硬约束替代提示词要求

来源（X） · @shao__meng · 2026-11-17 08:50

Reddit 有一个热门讨论：已经有 Claude Code/Codex 了，企业为什么还要招聘 Harness Engineer、自建 Agent Harness？难道是在重复造轮子？

https://www.reddit.com/r/ClaudeCode/comments/1xxk5ak/what_actually_is_an_ai_harness_and_why_are/

# Harness 是让模型持续工作的配套系统

讨论中一个比较清晰的解释是：模型负责推理和生成，harness 则负责把模型接进实际工作。

它管理上下文、提供并执行工具、保存运行状态、处理失败和重试，并决定什么时候停止、什么时候需要人工批准。Claude Code 本身就包含这样一套面向编程的运行框架，并不是“裸模型”。

因此，自建 harness 未必是在复制聊天界面或代码编辑器，也可能只是为特定任务设计更合适的执行循环、工具接口和控制规则。这里讨论的是 Agent 运行框架，不是负责出题和打分的评测框架。

# 为什么不把规则都写进 CLAUDE. md？

发帖人也追问：把仓库规范、测试要求和权限限制写进说明文件，不就够了吗？

高赞回应强调了一个重要区别：告诉模型应该怎么做，与由系统限制它只能怎么做，不是一回事。

例如，“生产操作前必须审批”可以写进提示词，但真正可靠的限制，需要工具或权限系统拒绝未经批准的操作。类似地，费用预算、数据访问范围和审计记录，也不能只依赖模型记住要求。

不过，这不意味着 Claude Code 只有提示词约束，它自身也有权限控制。企业真正需要判断的，是现成机制能否覆盖自己的要求，而不是一看到硬约束就必须从零开发。

# 企业需要的，可能只是适配而非重写

支持定制的评论主要关注内部系统、持续集成、评审流程、数据权限和成本控制。这些需求未必能直接套用通用编程助手。

一个很具体的例子是处理测试输出：先截取与失败有关的信息，避免把整份冗长日志交给模型，既减少上下文占用，也降低费用。这类工程工作不改变模型，却会影响它完成任务的效率。

# 我自己的想法

需要把两个问题分开：模型有没有能力完成任务，系统能不能让它在规定条件下可靠完成任务。

Harness 主要处理后者。企业是否需要自建，应从现成工具覆盖不了的具体约束出发。能通过配置、扩展工具和接入内部流程解决，就不必重写整套框架；只有运行方式确实不同，定制才有明确价值。

05｜Alpine 线程栈128KB 引发段错误

来源（X） · @fishjar · 2026-11-16 20:50

很多开发团队为了追求极致精简的 Docker 镜像，习惯把基础镜像一律换成仅有 5MB 的 Alpine Linux，然而这往往是生产环境神秘崩溃噩梦的开端。

代码在本地 Ubuntu 开发机上跑得稳如磐石，一旦打包成 Alpine 容器上线，高并发下服务就会频繁发生无预警的 SIGSEGV 段错误与直接退出。

很多人第一反应是内存泄漏，但真正的元凶是底层 C 运行时库的隐藏硬限制。标准的 Ubuntu/Debian 采用 glibc，通过 pthread_create 创建的每个新线程，默认会慷慨分配 8 MB 的栈空间（Stack Size）。

而 Alpine 出于极致轻量化的目标，采用了小巧的 musl libc，其线程默认栈空间被暴力砍到了只有区区 128 KB。

当业务代码调用了嵌套深层的 JSON 序列化库、执行了复杂的递归 AST 解析，或者在局部函数内声明了较大的缓冲区结构体时，128 KB 的内存栈瞬间发生溢出击穿保护页，操作系统内核毫无商量余地直接下发 SIGSEGV 强杀进程。在轻量化与工业容错之间，盲目削减基础镜像往往会付出沉重代价。

06｜Colab CLI 一条命令跑通云端 GPU

来源（X） · @Ryrenz · 2026-11-17 10:02

🚀 Google Colab 团队刚开源了 Colab CLI，在自己电脑的终端里一条命令就能借云端 GPU 跑脚本。

Colab CLI 上了 GitHub 热榜，GitHub 上已经 2400 多 star。

以前用 Colab，得打开浏览器、新建笔记本、把代码一段段贴进去、手动选 GPU，跑完再把结果一个个下载回来。

现在在本地终端里一条命令搞定：开一台新的云端机器，把本地脚本传上去跑、参数照转，跑完把输出文件取回来，再自动把机器销毁，不用惦记着关。

GPU 从 T4、L4 一直到 A100、H100 都能选，还有 TPU；想多折腾可以开交互式 REPL 或直接 SSH 进去，Google Drive 也能挂上。目前只支持 Linux 和 macOS，Windows 用户还得等等。

本地写代码、云端借 GPU，这下真的只隔一条命令了。
