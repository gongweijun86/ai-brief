01｜Kimi 注意力残差一作陈广宇离职

来源（X） · @0xLogicrw · 2026-10-15 11:36

17 岁的 AI 研究员陈广宇（Nathan Chen）宣布，自己最近已离开月之暗面 Kimi 团队。他于 2025 年 11 月加入，当时只有 16 岁，任职不到一年。陈广宇称，过去一年是自己迄今最美好的经历，但没有透露离职原因和下一站。

陈广宇曾因 Kimi 的 Attention Residuals（注意力残差）论文受到关注。这项获得马斯克公开称赞的研究，由他与张宇、苏剑林共同担任第一作者。苏剑林最初提出用注意力机制替代传统残差连接，并验证了初步效果。陈广宇和张宇随后加入研究，共同提出更省显存和通信开销的 Block AttnRes，使这套架构能够用于大规模模型训练，后来被 Kimi K3 采用。

离职帖中，陈广宇还回顾了其他工作。他曾与张宇优化 Kimi Delta Attention 的 GPU 计算内核，研究模型训练优化器，并参与制作 K3 发布时的展示案例。他感谢团队在自己只有 16 岁时就给予机会，并表示还想继续探索更多方向。

06｜Claude Code 新增会话空闲压缩

来源（X） · @ai_suxiaole · 2026-10-15 13:56

Claude Code 长会话又多了一个很实用的优化

上下文聊到几十万 Token 以后离开电脑一小时

回来接着干活，不用再把那么长的历史重新处理一遍了

2.1.299 加了空闲自动压缩（Idle Compaction）

上下文超过 20 万 Token、会话又空闲了 54 分钟左右的时候，它会赶在一小时的 Prompt Cache 过期之前自动把历史对话压缩掉，下次回来直接用压缩后的版本，全程不用手动 /compact，非常省心

先看下版本：

claude --version
不想要这个功能的话，在 settings.json 里加上：

{
"idleCompaction": false
}

触发压缩的 Token 门槛也可以用 CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS 调

不过我觉得默认的就够用了

有一点要注意，压缩后留下的是摘要，不会逐字保存全部历史，重要的报错、文件路径、技术决策这些，最好还是及时写进项目文件里。

经常跑长会话的伙伴可以留意一下

07｜制造业实测 AI 提效多在 50%

来源（X） · @bojie_li · 2026-10-15 11:27

非常赞同 “智力不是解决重大问题的瓶颈，与现实的交互才是瓶颈”。

最近我去小米、大疆、华为、一些芯片制造产业链公司交流，发现 AI 对大部分员工的效率提升只有 50%，只有少数 “超级个体” 员工做 prototype 的时候能 10x、100x。

AI 作为助理工程师写代码、调研分析这些 2025 年的 agentic 任务都没问题。但是 agent swarm 全自主推任务这种 “数字员工” 都很难做。

因为制造业有大量的约束，有物理约束，有成本约束，有路径依赖约束，有供应链约束，有内部组织约束。这些约束还很难蒸馏成 skills。Agent 往往不是忽视这个约束就是忽视那个约束，就算 pass@k 都很低。

现在模型的持续学习能力有限，直接拿失败的 trajectory，模型团队用不上；要构建 RL 环境也很难，总不能尝试流片个几千次，或者造几千个不能用的工件吧。

形成反差的是，做数学、理论、网络安全的都觉得自己快被 AI 取代了。OpenAI 的几百篇 paper 虽然有错误，但大多数可能会被承认是对的。

我之前以为 AI 不擅长解奥数题这种 “巧思”，做理论的老师告诉我，AI 最擅长的就是这种巧思，它可以遍历上万种可能的巧思。在可形式化验证且验证成本低的领域，AI 是远远超过人类的。

这就是 raw intelligence 和在现实交互中持续学习的鸿沟。
