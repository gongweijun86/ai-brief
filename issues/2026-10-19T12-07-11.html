01｜RoPE用旋转让注意力只记相对距离

来源（X） · @antiAIvo · 2026-10-19 19:05

「从零手写大模型」系列补充零件 · RoPE

RoPE 的核心公式，先说说作者
RoPE 的提出者是苏剑林，圈内叫他苏神 @Jianlin_S

我按自己的理解，从头推一遍

先说要算什么？
一个 token 在位置 m，提供 q
一个 token 在位置 n，提供 k
注意力分数就是 q 和 k 的点积
目标：让位置对分数的影响只取决于相对距离

RoPE 的想法很直接
把 q、k 看成平面上的箭头
第几个位置，就转几格，每格转 θ
q 转 mθ，k 转 nθ，两个箭头各转各的
但它们之间多岔开的角度，只有 (n−m)θ

下面用公式证明：
1. 写出旋转
转 α 角可以写成乘一个矩阵 R(α)
q 转完是 R(mθ)·q，k 转完是 R(nθ)·k
2. 写出分数
分数 = (R(mθ)·q)ᵀ · (R(nθ)·k)
3. 拆开转置
规则：(AB)ᵀ = Bᵀ Aᵀ
分数 = qᵀ · R(mθ)ᵀ · R(nθ) · k
q 在最左，k 在最右, 只需要化简中间两个矩阵
4. 用旋转矩阵的两个性质
性质一：转置等于反向转, R(mθ)ᵀ = R(−mθ)
性质二：连续转，角度相加, R(−mθ) · R(nθ) = R((n−m)θ)
5. 合起来
分数 = qᵀ · R((n−m)θ) · k

到此完毕：m 和 n 不再单独出现，只剩 n−m。

03｜CLAUDE.md每半年清一次过时规则

来源（X） · @vincemask · 2026-10-19 18:49

你精心维护的 CLAUDE.md，可能限制 Claude Code 的发挥。

Claude Code 的创建者 Boris Cherny。他在 YC Startup School 上给出了一个建议：

每隔 6 个月，删除你的 CLAUDE.md、Skills 和 Hooks。看看模型会怎么做，结果可能让你惊讶。

为什么？

因为很多规则，原本就是为了弥补旧模型的能力缺陷。

模型升级了，缺陷可能已经消失，但那些规则还在。它们不仅占用上下文，甚至可能干扰新模型的发挥。

Claude Code 团队自己就做过类似实验：删掉超过 80% 的系统提示词，重新评估模型表现。
Boris 建议定期做一次「减法实验」：
1备份并暂时移除 CLAUDE.md、Skills 和 Hooks。
2用真实任务测试模型表现。
3观察哪些问题仍然存在。
4只把确实必要的规则逐条加回来。
安全、权限和合规约束需要保留。项目中特殊的业务规则，也不能指望模型凭空理解。
至于目录结构、依赖清单，以及模型读代码就能理解的内容，值得优先清理。

以前，我们不断给 Agent 添加规则，让它少犯错。现在，模型越来越强，我们反而需要检查：这些规则是否已经过时。

04｜Claude Pro子Agent跨号路由

来源（X） · @AaronYiaazw · 2026-10-19 19:19

被 Claude Pro 单账号额度撞墙折腾了很久，终于解决了，方案开源！

一句话：主对话只管统筹，干活的子 Agent 派到别的账号上跑。 主对话不烧自己的额度，就能一直跑长任务。

我现在订了 8 个 Pro，已经稳定跑了好几天，没出过问题。

它是一套子 Agent 路由规则，每个号都是自己正常订阅、正常登录。一个 Pro 一个月 140，灵活加减，不用担心 Max 的高封号风险和折腾 KYC

方案的逻辑：
1主对话只统筹：拆任务、派单、验收。读日志、翻代码、跑脚本这些重活都派出去。

2自动选号：按各号剩余额度挑，避开主号和正在用的号，周额度快重置的号先用，免得额度白白浪费。

3撞限额不丢活：对话记录自动搬到另一个号，接着原来的进度跑。

4多号自动一致：所有号共用同一套规则、技能和记忆，加新号不用重新配置。
5一行命令安装：加号就是在浏览器里登录一下。

开源地址：https://github.com/aaronyi97/claude-pro-pool

05｜AI代写代码致调试能力降47%

来源（X） · @xiaomovps · 2026-10-19 13:53

为什么把写代码全交给 agent，会让你失去指挥 agent 的能力？🔥

最近在看一篇文章，是 PI 作者推荐的：Agentic Coding is a Trap

原文地址：https://larsfaye.com/articles/agentic-coding-is-a-trap

原文用了不同的角度和测试数据，在一遍遍地告诉我们使用 AI 但是不能完全使用，需要保留一定的摩擦和思考过程，我把整个文章提炼成了五个观点：

1、"监督悖论"。 用好 agent 需要你有能力审查它的代码，可过度用 agent 恰恰会让这种能力退化。他引用了 Anthropic 自己研究里的这个说法，还提到另一项 Anthropic 研究显示调试能力下降了 47%

2、这次跟以往"换一层抽象"不一样。 从汇编到 FORTRAN、从 C++ 到 Python，程序员没人抱怨过脑雾。现在连有近 30 年经验的 Simon Willison 都说，自己对应用越来越没有清晰的心智模型。新人更难，只审代码、不亲手写，等于只学了一半

3、AI 加速的是不重要的部分。 好开发者原本的优先级是：先理解代码，再看规范，然后代码越少越好，速度排最后。agent 把这个顺序整个倒过来了，最先追求的是快速生成大量代码

4、写代码本身就是在思考。 很多人是边写边想清楚要做什么的（OpenCode 作者 Dax 也这么说）。spec 写得再完美，概率模型也照样会幻觉，替代不了确定性的思考

5、会被厂商绑住，成本也不可控。 Claude 宕机时整个团队停摆，token 成本也一直在变。他的做法是让 AI 退居二线：让 AI 帮忙出方案，自己亲手写 20%–100% 的代码；一次只生成自己审得完的量；自己不会做的事，不交给 agent 做。原话是"把它当飞船电脑，而不是 Data"（Data 是《星际迷航》里那个能独立行动的人形机器人）。

如果你对这方面研究感兴趣，一定要看一下这篇文章，让我觉得非常有意思
