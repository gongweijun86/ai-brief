原文

Apple has pulled an iPhone app that used a real Linux kernel to boot full Android.

Andarium runs on Kernarium, an open-source runtime that compiles the mainline Linux 6.18 LTS kernel to native arm64 code through User-mode Linux. Userspace is emulated iSH-style, and GPU acceleration goes through Mesa's KosmicKrisp Vulkan-to-Metal layer. It can run Docker containers, Linux desktops and Wine/Proton.

Apple's reason, quoted in the project's README: "your app allows users to replicate Android operating systems on iOS platforms" (Guidelines 2.5.2 and 1.1).

11｜注释清理提示词四类分级加Lint

来源（X） · @hungryturbo · 2026-11-21 00:27

Matt Pocock 这个提示词不错，他现在也彻底站队到注释有害论这一派了，在 AI 智能体编程的时代，代码注释的副作用确实被急剧放大了，不妨试试用下面的提示词，来给项目做个大扫除吧。

提示词：

检查 <我的代码库 | 这段代码> 中的每一条代码注释。

将每条注释归为以下类别：

- 同义反复：只是简单重复从代码本身就能直接看出来的内容。
- 借口：许多注释让智能体得以用取巧凑合的实现蒙混过关，进而导致这种写法在代码中不断扩散。
- 过时：引用了已不再相关的代码或实现信息。
- 决策记录：记录了关于代码的重要且非显而易见的决策。

针对每条注释，执行以下操作：
- 同义反复 / 过时：删除注释。
- 借口：删除注释，并提交一个 Issue 来修复这种取巧凑合的实现。
- 决策记录：将其迁移到架构决策记录（ADR）中。

完成上述步骤后：

- 为 <我的代码库 | 这段代码> 创建一条禁止写注释的 Lint 规则。
- 采用棘轮策略（渐进收紧），假设本次 PR 不会一次性删光所有注释。
- 在本仓库中创建一个 /delete-comment Skill，以便我们后续重复这一流程。
- 帮我估算一下，删掉所有注释后我们能减掉多少行代码。

原文

Prompt of the day (a long one):

Take a look at every code comment in <my codebase | this section of the code>.

Categorise each comment as:

- Tautology: simply repeats what is already visible from the code
- Excuse: many comments allow the agent to get away with a hacky implementation, which then gets propagated through the code
- Stale: references code or implementation information that is no longer relevant
- Decision Record: documents an important, non-obvious decision about the code

For each comment, take this action:

- Tautology/Stale: delete the comment
- Excuse: delete the comment and file an issue to fix the hacky implementation
- Decision Record: move it into an ADR

Once this is done:

- Create a lint rule banning comments for <my codebase | this section of the code>
