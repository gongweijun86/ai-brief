02｜Magpie脱敏致Agent查询失真

来源（X） · @0x0_air · 2026-11-07 08:22

Magpie 开了脱敏后，有些查询任务会失真。因为 AI 实际看到的是脱敏后的信息，它会拿着这份信息去执行后续查询，自然就可能查出错误结果

AI 内部看到脱敏信息、输出显示用户输入的真实信息，这也是脱敏的特点

和 DeepSeek 吵了半天，最后才发现是 Magpie 的脱敏导致的

我当时发了一个公网 IP，让 AI 帮我查线路，结果 AI 说这不是公网 IP......

在我质问它之后，它又把这个公网 IP 原样返回给我，然后再次指明：这个不是公网 IP....

不过脱敏还是挺好用的，目前我单独把 公网IP地址 脱敏关闭了，感觉优化到目前已经很难有更好的优化了

04｜Claude用dreaming整理记忆

来源（X） · @Xudong07452910 · 2026-11-07 10:30

很推荐 Anthropic 刚发布的《The components of agent memory》，尤其是最近在研究 Agent Memory 的朋友。

之前看过不少 Memory 相关论文，这次可以从 Claude 的工程视角，看看它到底怎么管理、压缩和维护长期记忆。

文章有个很重要的设计，就是分层存储。

原始会话记录保留作证据，关键经验写入 Memory Notes，再通过 Dreaming 整理成相互关联的 Wiki。新会话只加载少量索引，需要时再查找详细内容。

比如 Claude Code 的 Auto Memory，每次只预加载 "MEMORY.md" 前 200 行或 25 KB，避免把大量历史信息塞进 Context。

文章中提到的 Dreaming 机制非常有意思。

Claude 可以在会话之外回查原始记录，合并重复经验、纠正错误记忆，甚至重新组织 Wiki，让过去积累的信息更容易被后续任务使用。

不过，维护这些记忆也需要额外计算。文章还发现，有些 Wiki 最后甚至比原始文档更大。

感觉 Agent Memory 还有很多值得探索的地方。如何让 Agent 留下真正有价值的经验，并在下一次任务中准确用上，可能比单纯追求记忆容量更重要。

原文：https://www.anthropic.com/research/components-of-agent-memory
