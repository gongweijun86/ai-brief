- 支付方式（尤其是之前封过的卡，几乎秒封）
- 和 Agent 聊的内容（测试过一些敏感内容，基本上是小时级封禁）

- IP
- 时区
- 使用语言

04｜pstack清理无用代码注释

来源（X） · @vikingmute · 2026-10-15 15:49

非常实用，让 AI 写代码的过程中，实际上可以产生非常多的无用注释，因为 Agent 很喜欢复制已有代码和注释，比如一个临时无害的 workround 类型的注释，会影响之后的 agent 的代码生成，滚雪球一样越来越多。

虽然现在根本不怎么代码了，之前抽查，会发现记录代码修改历史记录的注释，TODO的注释，还有把代码用英文重复一遍的注释，而且其他 agent 发现以后，会毫不犹豫的加进去。

所以大部分的注释应该删除，留下好注释，比如一些宏观层次的架构 公共 API/接口说明等等。

OP 的 /no-comment 的这个 skill 做这个工作很不错，而且他还抽象出了他平时的工作流 skill，他自己的用来让 AI coding agent 的工作流，大家可以看看 https://github.com/backnotprop/pstack

引用内容

lauren @poteto

中文译文

禁止并删除大部分、如果不是全部代码注释！

agents 喜欢复制已经存在的东西。一条看似无害的、解释某个临时变通方案的注释，是你代码库中最糟糕的病毒之一。它像杂草一样会迅速蔓延，成为 agents 快速完成任务的工具。在你意识到之前，你的代码库已经被各种临时凑合和过时的注释所淹没。兄弟，就再多一个变通方案

你可以使用 pstack 的 /no-comments 技能作为除草剂。它会找出无用的注释，同时保留那些确实应该存在的注释（比如解释浏览器怪癖的注释），并从第一性原理出发思考如何解决这些问题

以下是一个你可以尝试向 @bot 提出的提示：

创建一个项目 agent，使用 /poteto-mode 生成一个 /swarm，使用 /no-comments 识别我们仓库中可以修剪的无用代码注释。回来时给出一个高层计划，说明这些变通方案中哪些最好通过重构来解决，哪些我们可以直接删除

https://x.ai/bot/plugin/9717366

原文

ban and delete most if not all code comments!

agents love copying what already exists. a seemingly harmless comment explaining some temporary workaround is one of the worst viruses you can have in your codebase. like a weed it'll spread quickly as a tool for agents to quickly get their job done. before you know it, your codebase is overrun with hacks and stale comments. just one more workaround bro

you can use pstack's /no-comments skill as a weedkiller. it'll seek out useless comments while keeping the ones that actually should exist (like explaining a browser quirk), and figure out how to solve them on a first principles basis

here's a prompt you can try asking @bot:

create a project agent that uses /poteto-mode to spawn a /swarm to use /no-comments and identify useless code comments we can prune in my repo. come back with a high level plan of which of these workarounds would be best solved by refactoring and which we can straight up delete

09｜ManimGX GPU渲染快90倍

来源（X） · @GitHub_Daily · 2026-10-15 15:30

3Blue1Brown 那种数学动画是用 Manim 做的，画面是真好看，就是渲染一段视频得等挺久。

ManimGX 沿用了 Manim 社区版的 Python 写法，底层换成 Rust 加 GPU 来渲染，原来会写 Manim 的上手没什么门槛。

官方测试里，36.2 秒的 1080p60 视频 3.08 秒就渲染完了，比 Manim 社区版快 90 多倍。

GitHub：https://github.com/academa-labs/manimgx

它是冲着 Agent 设计的，把一句提示词贴给 Claude Code、Codex 或 Cursor，Agent 会自己装好环境，做出一段 3D 动画。

我觉得对 Agent 最友好的是它能自动出分镜图、检查画面排版，做完自己就能看一眼哪里挤了，不用人盯着。

公式用 LaTeX 写，不用另外装 LaTeX，旁白也能跟动画对上，浏览器里同样能跑，做数学物理讲解视频能少等很多。
