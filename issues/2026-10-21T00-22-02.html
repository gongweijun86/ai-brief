01｜先建设计系统再让AI生成前端

来源（X） · @dotey · 2026-10-21 01:36

我的经验，通常像 Claude 这样前沿模型，你不指定它默认就是这一套东西，已经被训练的够够的，完全不需要太刻意提示。

反而因为 AI 喜欢用 shadcn/ui，做出来都一个样，看的人审美疲劳。

所以 Claude Design 在设计的时候，它为了不做出来千篇一律，特别强调设计系统在其中的作用，引导你去先导入也好制作也好搞一套设计系统（Design System）出来，然后你做 PPT、做网页、甚至做视频，都用这一套设计系统，那么你的风格就会和设计系统保持一致，不会出现千篇一律的 AI 默认风格。

即使你不用 Claude Design，这种先引入设计系统的方式也是可以借鉴的，可以避免你做出来的网页风格大众化，而且可以很好的保证风格的一致性。

而且有很多开源开放的设计系统可以选，比如我直接用的 Adobe 的设计系统，做出来的东西至少不算难看。

谷歌刚刚放出一门 60 分钟的官方课，手把手教你打造一个7 * 24小时完全自动化的生产级 Agent 。

很多人学 Agent 看了几十个小时零散教程依然搭不出可用的东西，核心是没有搞清玩具 Demo 与工业级架构的边界。

谷歌这门 1 小时课程没有任何水分，只聚焦 5 个真正的工程核心：

1. 从 0 跑通首个 Agent：拆解模型调用、工具绑定与执行环境的基础闭环。

2. 状态持久化（Persistent Memory）：告别单次对话即失忆，构建跨会话的记忆索引与上下文回填。

3. 长时自主循环（Agentic Loops）：摆脱线性问答，让 Agent 具备自我反思、容错重试与多轮状态流转能力。

4. 吃透 MCP 核心架构：彻底理清 Model Context Protocol 与传统 API 的本质区别，学会构建标准化的上下文协议。

5. 多智能体协同系统（Multi-Agent）：把分散的专职 Agent 串联成高协作度的自动化系统。
