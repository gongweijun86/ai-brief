01｜Airbnb用Presidio去标识数据

来源（X） · @shao__meng · 2026-11-18 15:38

Airbnb 用 Presidio 做文本去标识：把真实信息换成可训练的假数据

训练模型前，Airbnb 会先处理消息、评价和客服对话里的个人信息：按公司统一分类，把姓名、住址、支付信息等替换成尽量逼真的模拟数据，既减少真实信息的副本和泄露，也尽量保留训练价值。政策由 Privacy Architecture 团队会同法务、政策和工程制定，再落实为代码。
https://medium.com/airbnb-engineering/de-identifying-text-at-scale-how-airbnb-protects-personal-data-in-ai-training-32f3ff8ff7d0

做成共享训练步骤，不另建中心服务

他们以开源库 Presidio 为基础。它最初由 Microsoft 开发，现已交由社区治理，以 Python 包在调用进程内运行。但只有每条流水线都使用当前版本和合规配置，保护才会生效。因此它被做成共享机器学习工作流中的可复用步骤，使用方只需标明哪些字段含有个人信息。

处理后的数据集会打上去标识标记，进入模型注册表，用来把关生产部署，并记录所用版本和配置。训练前还会先过滤已选择退出的记录。

用模式匹配和 GLiNER 识别，再用假值填回

Analyzer 先标出疑似个人信息的片段和置信度，Anonymizer 再处理重叠并替换。有固定形态的标识，用正则加上下文词识别。多种编号都可能是一串数字，他们扩展了短语级匹配，让更具体的词组优先得分。

默认的 spaCy 会把城市、地标也标成地点，在他们的评测中往往覆盖不到带门牌号的完整住址。姓名和地点因此改用可在推理时指定「街道地址」的 GLiNER。团队写道，两类实体的精确率都有提升；GLiNER2 已接入评测，只有基准证明有增益时才会换上。语言按整条记录或区域元数据判断，不稳时改用更保守的配置。

替换不用占位符或空白，以免模型把「这里被删过」也学成一种模式，大多数类型用 faker 生成自然假值。同一轮内，假值由真实值和当次密钥生成，同一真值始终对应同一假值，跨次运行则不同，且不保存对照表。房源自身链接会保留，电话保留国家码和区号；结构化字段中，标识符用调用方提供的盐值做哈希，坐标按隐私团队设定的精度截断，64 位内部编号用保形加密，以便通过原来的结构校验。

质量按语言和类型分开衡量

衡量时看召回、精确和吞吐，并优先保证召回，因为漏检就是泄露。指标按实体类型和语言分开统计，评的是重叠处理之后真正输出的结果。新语言要有标注数据才会上线，已稳定的类型发版时不能回退。

他们给出的评测图显示：电子邮件、信用卡和房源编号在英、西、法、德、日、波兰语上表现完整，姓名和地址在英语、西班牙语、法语、德语上较好，在日语和波兰语上明显偏弱，总体评分为 9/10。目前仍只交付文本，其他介质的去标识已经开始做。

03｜数仓补数未登记血缘致报表分叉

来源（X） · @zcswl7961 · 2026-11-18 16:25

数仓值班交接时，一个同行说他们补一次数，下游两张报表补成了两个版本。

上游任务改了口径重新跑，DAG 调度里依赖没写全，一张报表接到了新数据，另一张还挂在旧链路上，一张是新口径，一张是旧口径。

两个组各拿各的数开会，谁也说服不了谁，最后翻回刷记录才发现，差的那一层是当天临时补的，没走血缘登记。

治理的同事补了句“表是对的，链路是断的”，把两张截图钉进了质量周报。

数据本身不会错，错的永远是那条没登记的路。

04｜Qwen用LoRA适配pi编码Agent

来源（X） · @yibie · 2026-11-18 13:03

给一个 coding agent 单独训练模型

Hugging Face 给开源模型 Qwen3.8-27B 配了一个 LoRA，只在 pi 这个 coding agent 里用强化学习训练，不动基座权重。

做法上有两个值得看的点。训练在没改过的 pi 里跑，模型每发一次工具调用，中间的 safeagents 代理先用规则查一遍，明显在钻奖励空子的调用直接拦掉、记 0 分。任务是从公开 agent 会话重建的可验证环境，分修 bug、问答、从零搭建、扩展代码四类，对错由任务自带的验证器判，不靠人打分。奖励里还专门加了一项：答对的前提下工具调用越少加分越多。

效果是准确率和效率一起涨。SWE-bench Pro 最难的 51 题，基座模型 pass@1 是 29.4%，适配器到 62.7%，工具调用少 55%。Terminal-Bench 2.1 从 39.5% 到 55.8%，工具调用少 62%。评测是同任务配对、温度 0.8、关思考，显著性也给了。

模型卡里有个真实例子：同一个 SWE-bench 任务，基座反复搜索、重跑片段，撞到 100 步上限没过；适配器找到函数、改掉、跑测试、补最后一个用例，一共 8 次调用。

我觉得真正的信号是 LoRA 把适配成本压到了小团队够得着的程度：不用重新训一个 agent 模型，给自家工具和 harness 单独训一个小适配器就行。权重已经开放，vLLM、llama.cpp 都能挂。

两点保留。数字都是 Hugging Face 自测，没有第三方复现；最终检查点是看着评测子集的分数挑的，而且训练计划 1000 步、第 191 步就提前停了。
