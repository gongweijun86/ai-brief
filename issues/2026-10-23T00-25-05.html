01｜JIT-Agent 动态生成任务专属执行框架

来源（X） · @Manorgw · 2026-10-23 08:06

眼下 AI Agent 都在拼模型，可 Harness 到底怎么搭，其实同样关键。

JIT-Agent 换了个玩法：先让一个 27B 模型按任务即时生成一套专属 Harness，再交由另一个模型去执行。

换句话说，模型不用动，任务一变就重新生成一套执行框架。

按官方实验，这种动态 Harness 在部分任务上能贴近、甚至反超人工设计方案，Token 消耗也明显下降。

项目全部开源，想琢磨 Agent 工作流的可以去看看。

04｜agent-beacon 沉淀跨工具会话轨迹

来源（X） · @kafkaup · 2026-10-23 06:45

你昨天在 Claude Code 里纠正过一次的做法，今天换到 Cursor 还得重新教一遍吗？大多数人的答案都是要。agent-beacon 想解决的就是这件事。

它是个用 Go 写的本地记忆层，在后台持续采集你的 agent 会话历史，覆盖 Claude Code、Cursor、Codex、OpenCode、Cline 在内的二十多种 harness。装完之后你照常用自己的工具，不改工作流。

采到的不是摘要，是完整轨迹。prompt、模型回复、工具调用、执行过的命令、文件改动、审批记录、MCP 活动和 token 消耗都在同一条 trace 里，可以精确回放。数据落在 ~/.beacon/endpoint/logs/runtime.jsonl，想看就跑 beacon traces 开一个终端浏览器，或者 beacon endpoint dashboard 看本地网页版。

再往上一层才是它说的自我改进：从这些历史里识别出有用的工作流、纠正和调试模式，以及仓库自身的约定，经过审阅后变成知识库，后续 agent 通过 MCP 或 Agent Skills 直接检索。同一个问题不必被第二个 agent 从零学一遍。

两点要讲清楚。一是它是系统级的端点 agent，macOS 走 brew，Linux 有 deb/rpm，Windows 是 MSI，另外提供 MDM 和 CI 的无交互安装路径，侵入性比一个 npm 包高；好在 release 带 build provenance，可以用 gh attestation verify 核验。二是交互式安装默认预选了 Beacon Cloud 并要求登录，想完全留在本机需要手动选 Local，这个选择最好别点快了。

05｜多 Harness 配置提升 Agent RL 泛化

来源（X） · @omarsar0 · 2026-10-23 01:03

中文译文

在使用多种 harness 配置来扩展 agentic RL 方面，这项工作做得非常出色。

许多方法主要使用单一固定的 harness，这会让模型过于特化而无法很好地泛化。这项工作将多种 harness 配置作为一个扩展维度。

但最大的问题是，模型能否泛化到训练中从未见过的 harness 配置。

他们选择了一个具有平衡因子覆盖的紧凑训练子集，并在同一任务上每次只改变 harness 的一个部分。

在各种基准、模型规模和 RL 算法上，这种方法在训练中从未见过的 harness 配置上提升了结果。以这种方式训练的模型在迁移到未见过的外部黑盒 harness 时，也比通过单个复杂黑盒 harness 训练的模型表现更好。

如果你的模型将运行在你没有用来训练它的 harness 中，请将 harness 多样性视为一个独立的扩展轴。

https://arxiv.org/abs/2610.29458

与论文对话：https://academy.dair.ai/papers/harness-scaling-for-generalizable-agentic-reinforcement-learning-2610.29458

原文

Brilliant work on using many harness configurations to scale agentic RL.

Many approaches use mainly one fixed harness, which specializes the model but doesn't generalize well. This work uses many harness configurations as a scaling dimension.

But the big question is whether it can generalize to harness configurations never seen in training.

They pick a compact training subset with balanced factorial coverage, and vary one part of the harness at a time on the same task.

Across benchmarks, model sizes, and RL algorithms, this improves results on harness configurations never seen in training. Models trained this way also transfer to unseen external black-box harnesses better than models trained through one complex black-box harness.

If your model will run inside harnesses you did not train it in, treat harness diversity as its own scaling axis.

https://arxiv.org/abs/2610.29458
