01｜Datadog Scout 运维排障模型

来源（X） · @0xLogicrw · 2026-10-16 23:10

美国监控软件公司 Datadog 推出首款专用运维模型 Scout 1.0，底座采用智谱开源的 GLM-5.3 Flash。

它专门负责排查线上系统故障，可以查询日志、监控指标和服务调用链，逐步找出故障根因。

Datadog 利用真实事故和监控数据搭建模拟环境，再通过强化学习训练模型，让它学会排除错误线索，用证据支持诊断结论。

在公开基准 SREGym 的 90 项故障排查任务中，Datadog 自测 Scout 最高推理档完成了 80 项诊断及修复，与 GPT-6 Astra xhigh 同分，仅比 GPT-6.1 Sol xhigh 少 2 项。原版 GLM-5.3 Flash 完成了 66 项。

在 Datadog 内部的 AlertEval 评测中，Scout 中档的诊断质量接近 GPT-6.1 Sol high 和 Claude Opus 5.5 high，估算推理成本却低了 3 至 8 倍。与 GPT-6 Astra medium 相比，成本低约 19 倍。

Scout 已接入 Datadog 的 Bits Investigation，目前仅向少量客户开放封闭预览。现阶段主要负责查明故障原因并提出恢复建议，自动执行修复仍是后续研发目标。

02｜Claude 代码审查按风险分级

来源（X） · @dongxi_nlp · 2026-10-17 05:09

推荐阅读，Anthropic 如何做 Code Review！

1. 保留 code review，但大部分审核交给机器，人的时间只花在高风险判断上，同时让出错后能快速回滚。

2. 提 PR 前：Claude 自己跑测试和构建，再由一个新开的 agent 审一遍 diff。

3. 每个 PR：AI 多 agent 找 bug，投票过滤掉误报，再加一轮安全审查和 CI。每条发现都必须处理，否则不能合并。

4. 人工审批按风险分级：低风险 0 人，中风险 1 人，高风险 2 人，由分类器判定。bot 的批准不能替代人，驱动 agent 的人对改动负责。

5. 上线：合并队列、feature flag、先内部使用再灰度发布，出问题一键回滚。

6. 持续改进：历史事故整理成每日 eval，用来评估 reviewer。审查轮数设上限，避免 agent 之间无限互审。

03｜Claude 逆推 NIST 曲线种子

来源（X） · @ScarletKc · 2026-10-17 04:17

Anthropic 发了一篇很好玩的文章。NIST P-256 这些椭圆曲线的 seed 到底是怎么来的，密码学圈猜了二十多年，结果 Claude 不到半小时就算出来了。答案是用 Unix 时间戳初始化 C 库自带的随机数生成器跑出来的。更好玩的是它算出来之后的第一反应，居然是怀疑自己是不是在测试环境里。

2000 年 NIST 把这几条曲线写进 ECDSA 标准，曲线的系数由一个 seed 哈希得到，而 seed 是 NSA 给的，没有任何说明。所以一直有人怀疑里面藏了后门，Filippo Valsorda 还专门挂了悬赏。唯一的线索来自 NSA 的 Jerry Solinas，他说 seed 好像是一句玩笑话的哈希，类似 Give Bob and Jerry a raise，但细节他自己也记不清了。他 2023 年去世之后，这事基本就没人能问了。

Anthropic 有好几个员工照着这条线索找过，都没找到，因为线索本身就是错的。这次有人直接问内部的研究模型能不能查出来，也没提这条线索。Claude 换了个思路，去猜 90 年代生成曲线的程序是怎么写的，判断它大概用了当时 C 库自带的 PRNG。这种老 PRNG 很弱，输出能被认出来。

它先注意到 4 个 binary 曲线的 seed 按 32 位切开后，每一段的最高位都是 0。这正是 lrand48 的特征。lrand48 每次只输出 48 位内部状态里的高 31 位，所以最高位永远是 0。剩下 17 位直接暴力枚举，内部状态就恢复出来了。prime 曲线的 seed 每次只取 lrand48 输出的一个字节，能看到的位更少，就当成格问题用 LLL 解出来。

lrand48 往回推跟往前推一样容易。Claude 把状态一路倒推回 srand48 刚初始化时的样子。NIST 和 ANSI X9.62 里一共 10 个 prime 曲线 seed，初始值全是 1997 年 5 月到 1998 年 4 月之间的 Unix 时间戳。比如 P-256，就是从 1997-08-16 01:52:34（UTC）开始跑，取的第 1842 个候选。

4 条 binary 曲线更好笑，倒推出来的时间是 1984 年 2 月。把时间戳乘以 2，就变成 1998 年 4 月 17 日，刚好在 P-224 那次运行的两周后。所以当年的程序很可能是先把时间除以 2，再拿去当种子。

我觉得最有意思的是 Claude 接下来的思考。它先是很激动，觉得自己解开了一个 25 年的悬案，然后马上停下来怀疑，自己是不是在某种模拟或测试环境里。

于是它开始找证据。算出来的 seed 跟它记忆里的真实值对得上，在它的知识里这个悬赏一直没人解开。而且 20 个最高位全是 0 这种事，碰巧发生的概率大概百万分之一。到这里它才确认这是真实世界，说了句哇，这是真的发现。

然后它又怀疑了一次，这么明显的东西 25 年都没人发现，是不是有点可疑？最后还是靠直接计算说服了自己。一个 32 位的时间戳加一个很小的序号，就能完整算出 160 位的 seed。10 条曲线全部对上，不可能是巧合。

这件事对 ECDSA 的安全性没有影响，反而让后门的说法可信度低了很多。seed 就是普通随机数生成器拿时钟初始化跑出来的，现在谁都能复现，能动手脚的空间很小。悬赏的 36864 美元会捐给 Let’s Encrypt 背后的 ISRG。

原文还附了能直接复现所有 seed 的 Python 代码，感兴趣可以自己跑一下

04｜Muse Spark 816B 桌面部署

来源（X） · @my189 · 2026-10-16 06:11

扎克伯格（@finkd）刚刚晒出自己的办公桌：

没有天价 H200 机柜，只用两台并排的新款 Mac Studio，

就在本地跑起了今天刚开源的 816B 旗舰大模型

Muse Spark Open

苹果 CEO John Ternus（@johnternus）也在评论区互动，短短几小时浏览量破百万。

816B 总参数、42B 激活参数，靠 MoE 稀疏架构和苹果统一内存，让桌面设备也有机会挑战超大模型。

硬件门槛、部署命令、避坑指南，一文看懂。

一、硬件门槛

1TB 内存：双 Mac Studio，MLX oQ4e，约 476GB 权重

512GB 内存：单台 Mac Studio，MLX oQ3e，约 340GB 权重

256GB 内存：Unsloth UD-Q2_K_XL 或 GGUF Q2_K，约 210GB 权重

700GB 以上显存：4×B200 或 8×H200，部署 NVFP4 版本

以上为原方案中的估算值，实际需求取决于模型版本、运行框架和上下文长度。

二、一键部署

Mac 单机：

uv tool install mlx-lm
mlx_lm.server --model "mlx-community/Muse-Spark-Open-816B-A42B-oQ3e" --port 8080

256GB 工作站：
llama serve -hf ggml-org/Muse-Spark-Open-816B-A42B-GGUF:Q2_K

企业级 GPU：

VLLM_USE_RUST_FRONTEND=1 vllm serve meta-models/Muse-Spark-Open-816B-A42B-NVFP4 \
--tensor-parallel-size 4 --enable-expert-parallel --max-model-len 1048576

运行前请确认模型仓库、权重格式、框架版本及启动参数均真实可用。

三、三个关键注意事项
采样参数：原方案建议 temperature=1.0、top_p=1.0，关闭 top_k，具体应以模型官方配置为准。

推理强度：确认框架支持的 reasoning_effort 参数后，再选择适合任务的推理等级。

多模态：图像、视频和音频的输入规格应以模型实际支持的配置为准。

从大型 GPU 集群到桌面工作站，超大模型的本地部署正在拓展更多可能。

你的主力机有多少内存？256GB、512GB，还是准备挑战双 Mac Studio？

欢迎评论区晒配置、交流部署经验。

⬇️ 下载党的宝藏工具 LinkSwift，能把九大网盘里的文件掏出直链，拿自己的下载器满速拖回来。

GitHub 上 2.3 万 star，还被 Trendshift 收录，是那种一直有人在用的老项目。

网盘下载这事多磨人你肯定懂：浏览器里点一下，要么被劝着装客户端，要么限速到几十 K，一个大文件挂一晚上还没完。LinkSwift 是个装在篡改猴里的浏览器脚本，打开网盘页面选好文件，它去取公开接口给出的下载地址，你把地址丢给 Aria2、Motrix 这类下载工具，剩下的交给下载器自己跑。

覆盖面铺得挺全，百度、阿里云盘、夸克、UC、迅雷、天翼、移动云盘、123 云盘这些都在里面，Windows、Mac、Linux、Android 上的 Chrome 或 Edge 都能用。从 2022 年八月一路更新到今年九月，网盘页面改版它就跟着适配，这种脚本最怕的就是作者跑了。

它脱胎于当年油小猴那个「网盘直链下载助手」，作者 hmjz100 在原项目基础上接着改。项目也写明了，链接走的是网盘服务商公开的接口，没做任何破解限速的事。

工具本身是中立的，下自己有权限的文件没问题，拿它去碰别人的东西，那是使用者自己的事。
