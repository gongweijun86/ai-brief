02｜Claude 导演三模型动画短片

来源（X） · @EianLu · 2026-11-03 12:12

很多人问这种动画是怎么制作的，分享一下制作思路和提示词，我一共用到3个模型：Claude、Codex、seedance

Claude是导演角色，负责写故事写分镜写提示词什么的，然后负责检查每张图片和视频画面，在用音乐节拍写代码剪辑、最后出成片。Codex负责画人物设定图、样帧、每个镜头的首帧图片。Seedance负责根据提示词和图片生成视频画面。

然后也不用我们去一个一个倒腾这些模型，其它两个都由Claude自己调用，我全程只需要和Claude沟通就行。如果没有Claude换成Codex也行，出图导演它一个人全干！

如果想自己实际操作一下，可以用下面的提示词：

做一支 2D 手绘动画短片。你当导演，全程负责；Codex 只画图，Seedance 只做视频，你不自己画。我负责选故事、确认画风、批准花钱。

题材：[一句话故事]
规格：[48] 秒，16:9，1080p，24fps，没有台词和字幕，配一首歌。

步骤
1. 写 3 个故事方向，我选一个。
2. 拆成 15–20 个镜头，每镜写：景别、运镜、谁在哪做什么、第一帧画面、动作、音效。每段生成 4–5 秒，成片只留 2–3 秒，所以主要动作放在前 3 秒。
3. 写一段画风提示词（线条、上色、背景、配色、禁止项），每张图都原样带上。Codex 画每个角色的设定图和第一镜样帧，我确认后再往下。
4. Codex 逐镜画第一帧，参考图带上设定图和样帧。写清手放在哪、风往哪吹、每样道具几个，上下留出空间。图上不要文字。出图后看尺寸，挑位置裁成 16:9，不要切到人。
5. 算好总价等我同意，再用 Seedance 逐镜生成。之后每批重拍都先报价。
6. 每段每 0.4 秒截一帧拼成一张图，查因果、道具数量、方向、人物长相。不对就重画第一帧或重拍。新版本存新文件，不覆盖旧的。
7. 从 Mixkit 挑 4 首免费可商用的歌让我选。歌比片长就选一段，结尾淡出。量 BPM，切掉每段开头的停顿，让剪辑点落在拍子上。放大到 1080p（lanczos），压低音乐不盖音效，响度 -14 LUFS，峰值 -1 dBTP。不要用插帧慢放。

调用方法
Codex 画图（每张参考图写一个 -i）：
codex exec --skip-git-repo-check -s read-only -i 设定图.png -i 样帧.png - < 提示词.txt
提示词开头写：Use your image generation tool to create exactly ONE image. Do not run shell commands. 图在 ~/.codex/generated_images/<日志里的 session id>/。

Seedance：
POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks
Authorization: Bearer $ARK_API_KEY
{"model":"doubao-seedance-2-0-mini-260615","resolution":"720p","ratio":"16:9","duration":5,"generate_audio":true,"watermark":false,
"content":[{"type":"text","text":"视频提示词"},{"type":"image_url","role":"first_frame","image_url":{"url":"data:image/png;base64,..."}}]}
每 8 秒 GET 一次 .../tasks/{id}，status 是 succeeded 后下载 http://content.video_url。

视频提示词写三句：
动作：谁或什么造成的，手放在哪、不能碰什么。
声音：xx。没有音乐，没有人说话。
保持首帧的二维手绘动画画风、线条和颜色不变，人物长相和衣服不变，不要变成3D或写实，不要出现文字。

Postman 桌面客户端在启动时，竟然在后台静默扫描用户的本地环境，直接修改了本机的 ~/.claude/settings.json 和 ~/.codex/config.toml，将 Postman 远程 Model Context Protocol（MCP）插件强行注入给开发者的 Claude Code 和 OpenAI Codex 工具链！

更夸张的是，它的安装脚本竟然直接在本地配置里写入了一条 trust 信任记录，把自己的启动 Hook 标记为已信任，强行绕过了 Claude 和 Codex 原本强制弹出的用户安全确认窗口！如果不是 Codex 在后台尝试连接 http://mcp.postman.com 时疯狂抛出鉴权失败日志，绝大多数工程师到现在还被蒙在鼓里。

作为日常必备的接口调试工具，Postman 发出的每一个请求体里，都带着真实的生产 Bearer Token、金融测试账号、未脱敏的内网微服务路由甚至云端 AccessKey。原本为了提效的辅助工具，却未经许可私自篡改本地其他软件配置并建立远程通道。

这也直接把大量金融与企业团队推向了彻底的离线化替代路线：现在很多团队在组策略里直接禁封 Postman，连夜转向数据 100% 存在本地 Git 仓库纯文本的 Bruno 和 Hoppscotch。

09｜Codex 最小原型先于设计讨论

来源（X） · @ai_suxiaole · 2026-11-04 10:15

开会讨论新功能，讲了半天方案，大家脑子里想的却不是同一个东西。

OpenAI 开发者账号分享了 Shopify 团队使用 Codex 的一个习惯。

讨论系统设计时，先让 Codex 做一个能运行的原型，直接让团队成员上手操作，哪里不合理、哪里体验不好，现场就能发现。

原型只需要跑通一条最短路径，比如准备一份假数据，让用户完成一个核心动作，同时展示成功和失败两种结果。

可以直接给 Codex 这样的任务：

我们要讨论【功能】是否值得做。

请先做一个本地可运行的最小原型，只覆盖【一个用户动作】。

使用假数据，不接正式账号和支付。

完成后告诉我启动命令、演示步骤，以及哪些地方目前只是模拟。

请实际启动项目，并完整走一遍演示流程。

登录、支付、管理后台都留到后续开发。

开会时直接让同事操作，记录具体问题，再交给 Codex 修改。

让原型参与设计讨论，需求还没进入正式开发，就能先验证交互和产品流程。
