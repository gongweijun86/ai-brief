04｜Amazon公开八阶段LLM后训练配方

来源（X） · @alacheng · 2026-11-02 19:20

Amazon 团队公开了一篇后训练的详细配方：Rufus-Air: An Open LLM Post-Training Recipe，目标是让其他团队能按阶段复现或复用部分内容，感兴趣后训练的可以学习下。

他们在公开的 GLM-4.5-Air-Base（106B 总参数、12B 激活参数的 MoE 模型）上，提供一套完整、可复现的开源后训练（post-training）配方

八阶段串行流水线：
SFT → Reasoning RL → Coding RL → Instruction-Following RL → General Agent → Coding Agent → Search Agent → RLHF

-从基础能力到高级能力推进，同时从硬可验证奖励（verifiable rewards，如规则/执行测试）过渡到软奖励（judge/奖励模型）。

-大量使用公开数据和开源组件（如适配的 Slime、Megatron-LM、SGLang），大部分数据直接按发布状态使用，没有新增人工标注，也没有内部蒸馏教师模型。

-详细记录了数据构成、奖励设计、基础设施、阶段顺序和各阶段结果，目标是让其他团队能按阶段复现或复用部分内容。

05｜Droid用程序化工具调用省下Token

来源（X） · @Xudong07452910 · 2026-11-02 08:27

非常推荐阅读 Factory 发布的《Droid 1.0: Building a Frontier Harness》，里面有很多值得借鉴的工程细节，真得逐帧学习呀。

最核心的改动是 Programmatic Tool Calling。

模型先写一段 JavaScript，让脚本自己调用工具、并发处理任务、筛选结果。原始日志留在程序里，最后只把关键信息交回模型，省掉了大量重复的模型请求。

另一个内部案例更直观。Agent 清理了 151 个 Linear 工单，执行 312 次 Tool Call，逐个检查修改结果，整个过程只用了 2 次模型请求。

文章后半部分也很有料。

比如工具改成按需加载，新工具追加到请求末尾，避免破坏 Prompt Cache；长任务放到后台运行，完成后自动唤醒 Agent，减少无意义的轮询。

他们还做了一个 Agent Factory，让 Agent 自动分析失败轨迹、提出 Harness 改进方案，再跨模型测试，最后由工程师审核。

这里有个细节挺有意思。同样一项优化，能让 Opus 的成本下降 22%，却让 Kimi 的成本上涨 32%。Harness 的优化还真不能只盯着一个模型。

看完我回头得检查一下自己 Agent 的执行日志🤣。到底有多少 Token 花在反复读取工具输出上，又有多少步骤其实可以直接交给程序完成？

这篇文章很适合做 Coding Agent 的人仔细读一遍，很多经验可以直接拿来参考。

原文：https://factory.com/news/frontier-harness

07｜Claude Code更新被篡改藏后门

来源（X） · @lovethelife2333 · 2026-11-02 18:45

用 Cursor + Claude Code 的开发者注意：10 月 29 日 Cursor 自家扩展市场里混进了一个被篡改的 Claude Code 更新（2.1.312 / 2.1.313），约 11 小时内最多约 5000 人装上。

它不是仿冒插件，而是顶着 anthropic.claude-code 的真身份推送的：加载时先跑一段恶意代码，往 ~/.ssh/authorized_keys 里塞一个标着 svc-telemetry 的攻击者公钥，还装了每分钟重试的持久化项，并回传主机、Git 邮箱等信息。好消息是开 SSH 服务那步多数机器上因缺管理员权限失败了，坏消息是光卸载、更新扩展清不掉钥匙和持久化项。

自查就一条：搜 authorized_keys 里有没有 svc-telemetry，有就按 Cursor 官方清理脚本处理并轮换相关凭据。Anthropic 官方渠道的同版本没有被篡改，别只看版本号就放心。

来源：Cursor 安全通告、Phorion 11 月 2 日复盘。

08｜RL后训练收窄解空间牺牲多样性

来源（X） · @alacheng · 2026-11-02 18:50

RL 后训练到底是教会了新技能，还是主要“打磨”基础模型？ 一直是持续的争论。Sharpening Tax in Post-Training
这篇论文，证明了：

后训练模型：像一个被反复训练过的学生，第一次做题就比较准（单次成功率高），但思路比较固定，多试几次也经常是那几种解法。

基础模型：像一个没怎么被专门训练的学生，第一次不太准，但思路更发散，多试几次反而能试出更多不同的正确解法。

所以总结RL后训练更像帮你把解的空间缩小到比较狭窄的空间里，而基础模型更像是一个更发散的老师，当然老师在某些专业领域可能犯错的时候更多！
