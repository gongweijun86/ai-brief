02｜主动式Agent评测需记录每次判断

来源（X） · @Xudong07452910 · 2026-11-20 11:36

像 Muse，Grok Bot 这类主动式 Agent 怎么评测？这篇讲得蛮清楚的。

它和普通 Agent 的区别其实就一步。普通 Agent 收到触发就执行，主动式 Agent 会先判断要不要做、什么时候做、做到哪一步。比如航班延误了两小时，它可以直接提醒你、等航司改签、帮你找新航班，甚至直接订好。

难点在于，普通 Agent 每次回答都有人看，答错了马上会被发现。主动式 Agent 不一样，它大部分时候判断「不用管」，就悄悄过去了，判断错了也没人知道。所以文章建议把每一次判断都记下来，包括被什么事情触发、参考了哪些信息、最后怎么决定的、为什么这么决定，连没行动的那些也要留着，这样回头才查得出问题。

评测的思路也值得参考。它每次判断其实就是在回答一个问题：这件事该不该出手。所以可以分两头看，一头是该出手时有没有漏掉，一头是出手的时候是不是多余。门槛也可以分开设，随手就能忽略的提醒可以宽松一点，买东西这种花钱又难撤回的操作就要严格得多。

我感觉主动式 Agent 好不好用，是该打扰的时候打扰我，不该打扰的时候别打扰我🧐。

03｜个人Agent异步运行分五条技术路线

来源（X） · @realchendahuang · 2026-11-20 10:50

把市面上正在跑的 Personal Agent 和 Super Agent 项目全拆了一遍，真正支撑后台异步运行的技术路线，目前主要分化成了五条。

第一条是云端持久虚拟机加专属浏览器，代表是 Grok Bot、OpenAI Dots、Claude Duet 和 Manus Cloud Computers。
做法是给每个用户或每个 Bot 开一台 24 小时开机的 Linux 云主机，合上笔记本任务照跑，靠独立沙盒隔离风险。
代价是云端空转算力开销大，订阅动辄每月 100 到 500 美元，而且机房 IP 在国内登录常见消费软件很容易触发异地风控。

第二条是云手机与端侧 GUI 模拟点击，代表是阿里千问 Go、豆包手机助手和智谱 AutoGLM。
针对不开放 API 的 App，靠截屏识别页面再模拟点击去比价、找客服交涉或填表。
问题在于链路脆弱，页面微调或弹出验证码就会卡住，而且高频模拟点击与外挂特征重合，国内目前仍有 155 款主流 App 明确拒接外部 Agent 访问。

第三条是开放协议与接口直连，代表是海外推的 Poppy 1.0 和 UCP 协议加 Meta Muse，以及国内的蚂蚁灵光 2.0。
放弃模拟点击，直接走 MCP、OpenAPI 和 OAuth 授权调用外部服务，把密钥交由独立安全层托管这条路上限完全取决于生态开放度，海外靠 Shopify 这类独立商家生态推标准，国内超级 App 彼此封闭，实际权限很难跨出自家院子。

第四条是自托管全通道网关加双层路由调度，代表是 OpenClaw、Hermes Agent、DeepSeek 的 DSH Super-agent 原型以及 Rakazo、OpenDots。
做法是在个人主机、VPS 或 Docker 里跑常驻守护进程，对接 Telegram、飞书、Slack 等聊天软件。由于跨会话长程记忆至今没有共识，DSH 这类架构选择在干活会话之上再加一层 Router 路由器，先用确定性规则过滤事件，再拆出独立工单派给隔离 Worker.
数据与模型完全自控，但运维成本偏高，数据库膨胀、版本升级破坏配置以及恶意 Skill 投毒，是目前最集中的问题。

第五条是纯本地桌面工作台加文件级上下文共享，代表是 n8n 的 Nod、Linger 和 Orbital。
不做 24 小时云主机，直接在个人电脑上接管本地目录、浏览器或统一调度本机已装好的 Claude Code、Codex 与各家模型，把状态、决策和技能以纯文本留在本地文件夹，再挂载日历、GitHub 或办公群事件流。
避开了云主机月费、公网暴露和消费 App 风控，适合有明确验收标准的开发与本地工作流，代价是依赖电脑开机在线。
