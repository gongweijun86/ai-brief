claude-fixer 复现了问题，添加了回归测试，修复了差一错误（off-by-one error）。然后它在同一个会话中让 codex-reviewer 审查分支，订单页面显示出了修正后的结果。

两个 agent 都在我的本地机器上运行，我从未在它们之间传递过任何上下文。

03｜Mirage虚拟终端分离数据与算力

来源（X） · @siddontang · 2026-11-25 04:56

中文译文

非常喜欢这个方向。Agent 需要终端、持久化状态和按需计算——不一定要专用沙箱。

原文

Love this direction. Agents need a terminal, durable state, and compute on demand - not necessarily a dedicated sandbox.

引用内容

Zecheng Zhang @zechengzh

中文译文

沙箱已经成为"AI agent 应该在哪里运行"这个问题的默认答案，但 agent 从来不需要沙箱，只需要它们后训练时所使用的终端界面。

今天我们发布 Mirage 0.1.0，一个将终端与其背后的数据和计算分离的虚拟终端。

- Mirage shell。一个 bash 兼容的 shell，Unix 类工具用 Rust 重写，保留 agent 训练时所学的语义。
- 统一虚拟文件系统。S3、Google Drive、Slack、Gmail 以及大约 60 多个数据存储，全部在相同的 Unix 类命令后面。
- 虚拟 CLI。每个工具（包括 MCP 服务器）都变成了一个 agent 已经知道如何使用或可以渐进式发现的 CLI。
- 可脚本化策略。每个命令和文件访问都可以由一个能查看完整终端上下文的脚本来检查。
- 机器路由。命令仅在需要真实计算时才被发送到本地或远程机器（如沙箱）。
由于终端与其背后的数据和计算分离，Mirage 轻到可以住在 agent 所在的任何地方——在一个应用中、一个浏览器标签页中、一个 FastAPI 或 Express 服务器中，每增加一行命令行仅占用 KB 级别的内存。
同时以 Python 和 TypeScript 完全开源。
https://github.com/strukto-ai/mirage

原文

Sandboxes have become the default answer to where AI agents should live, but agents never needed the sandbox, only the terminal interface they were post-trained on.

Today we're releasing Mirage 0.1.0, a virtual terminal that separates the terminal from the data and the compute behind it.

- Mirage shell. A bash-compatible shell with Unix-like tools rewritten in Rust, keeping the semantics agents were trained on
- Unified virtual filesystem. S3, Google Drive, Slack, Gmail and about 60 more data stores, all behind the same Unix-like commands
- Virtual CLIs. Every tool, MCP servers included, becomes a CLI the agent already knows how to use or can discover progressively
- Scriptable policy. Every command and file access can be checked by a script that sees the full terminal context
- Machine routing. Commands go to local or remote machines, such as sandboxes, only when they need the real compute
Because the terminal is separated from the data and the compute behind it, Mirage is light enough to live wherever the agent does, in an app, a browser tab, a FastAPI or Express server, with each command line adding only KBs of memory.
Also fully open sourced in Python and TypeScript.
https://github.com/strukto-ai/mirage

14｜Starcloud太空散热器轻10倍

来源（X） · @PhilipJohnston · 2026-11-25 00:08

中文译文

在 @Starcloud_，我们正在太空中建造数据中心，我最常被问到的问题是：
"在真空中你怎么散热？真空瓶之所以用来保温是有原因的！"

这是个好问题，因为在太空中我们没有对流冷却。所以答案是：红外辐射。

它比听起来简单。任何比周围环境更热的东西都会在红外线中"发光"。如果你脸上现在有一台红外相机，你会看到它在发光。物体发射的能量与物体和周围环境之间的温度差的四次方成正比。这是一个很了不起的事情，因为太空是零下 270 摄氏度。这意味着如果你将散热器保持在 50 摄氏度（芯片的最低温度），你可以每平方米至少发射 800 瓦！太阳能电池板每平方米大约产生 200 瓦，所以这意味着你最多只需要太阳能表面积的四分之一作为散热器。所以如果你有 100 平方米的太阳能板，你最多只需要额外 25 平方米的散热器。

关键在于，这些都不是新东西。

国际空间站（ISS）在过去 28 年里一直有一个散热器散散热 70 kW，其运行完全符合预期。

那么它在轨道数据中心上是如何工作的呢？和国际空间站完全一样，我们将冷却液流过芯片，然后流向更大的表面积（散热器）。陆地数据中心使用水作为冷却液，但由于水在结冰时会膨胀，我们为自身需求配制了自定义冷却液。

但不是很贵吗？国际空间站的散热器目前既昂贵又笨重。但这就是 Starcloud 的价值所在。经过 2 年的研发，我们设计并制造了一个散热器，几个月后发射，其每瓦散热量的质量比国际空间站散热器少 10 倍，每瓦散热量的成本低 500 倍。💪🚀

原文

At @Starcloud_, we are building data centers in space, and the most common question I get is:
“How do you get rid of the heat from the chips in a vacuum? Vacuum flasks are used to contain heat for a reason!”

It’s a good question since in space, we don’t have convective cooling. So here’s the answer: Infrared radiation.

It’s simpler than it sounds. Everything that is warmer than its surroundings ‘glows’ in infrared. If you had an infrared camera on your face right now, you would see it glowing. The amount of energy that something emits is proportional to the 4th power of the temperature differential between the object and its surrounding. Which is a biiig deal given that space is -270 degrees C. This means that if you keep your radiator at 50 degrees C (the minimum temperature of the chips), you can emit at least 800 Watts per square meter! The solar panels generate around 200 watts per square meter, so that means that you need at most, a quarter again the surface area of the solar in radiator. So if you have 100 square meters of solar, you need at most an additional 25 square meters of radiator.

And here’s the thing, none of this is new.

The international space station (ISS) has had a radiator that dissipates 70 kW for the last 28 years and it has operated exactly as expected.

So how does it work for orbital data centers? Exactly the same way as the ISS, we flow coolant past the chips, and out to a larger surface area (the radiators). Terrestrial data centers use water as their coolant but since water expands when it freezes, we have formulated our own custom coolant for our needs.
