02｜Baseten 按需加载降本62.5%

来源（X） · @Xudong07452910 · 2026-11-20 08:59

不换模型、不改 Harness，Agent 成本可以降 62.5%。

Baseten 这篇讲的是「按需加载工具」。平时挂的 MCP 越多，每次请求塞进上下文的工具说明就越多，他们只挂了 3 个 MCP，就多出约 14 万 token。

换成按需加载以后，一开始只给工具名和一个搜索工具，约 1.3k token，模型用到哪个再加载哪个。

他们用 GLM 5.3 测下来，编码任务成本降了 62.5%，速度快了 26.2%。另外有个小坑，Claude Code 和 Codex 接第三方开源模型时会默认关掉这个功能，要记得打开。

工具越挂越多的时候，先别急着换模型，可以先看看上下文里装了多少用不上的东西。

03｜Pi Chord 执行与通信分离

来源（X） · @fttt007 · 2026-11-20 15:15

今天继续学习 Pi 的 Chord v2，对分布式 Agent 架构有了更深入的理解。

Chord 的 Host 主要有三种角色：

Client Host：客户端，例如浏览器或终端 UI，负责发起请求。
Server Host：中央服务器，负责连接、请求路由，也可以承载 Object。
Worker Host：实际执行任务的节点，可以按需启动，承载 Agent 和其他 Object。

需要注意：这三种是 Host Role（角色），并不代表 Host Kind（类型）只能有三种。开发者可以定义 server、session 等不同的 Host Kind。

一个重要发现是：Server Host 并不是 Agent 执行任务的必经节点。

Worker 访问本地 Object，不需要经过 Server。
在文档描述的 Node 架构中，Worker 之间的远程通信需要通过 Server 转发。
Server 崩溃，不一定导致 Worker 上正在执行的 Agent 任务立即停止。
但依赖 Server 的通信可能中断，相关任务也可能阻塞或失败。

这让我理解了一个重要区别：

Agent 的执行 ≠ Agent 的通信。

Chord 负责分布式对象的定位、路由与通信，Pi Durable 则进一步关注 Agent 任务的持久化与恢复。

一个可靠的 Agent 系统，不仅要让 Agent 能执行任务，还要考虑节点故障、通信中断以及任务恢复。
