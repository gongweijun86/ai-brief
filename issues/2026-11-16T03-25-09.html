02｜Pi Durable组装常驻Agent

来源（X） · @verysmallwoods · 2026-11-16 00:45

结合这篇文章，整理了一套用 Pi Durable + Pi AI SDK 组装 always-on Agent 的架构。

Agent 平时等待，收到消息、Webhook 或定时事件后唤醒，推进任务、保存进度，再决定何时继续，以及是否通知用户。

各个组件可以这样组合：
- Conversation 保存讨论，Submission 接收输入，用稳定 requestId 关联重复请求。
- Harness 调度 GenerationTask 和 ToolTask，完成模型生成、工具调用与后续执行。
- Durable Storage 保存历史、检查点和结果，进程重启后重新打开存储并恢复。
- Pi AI SDK 统一接入模型服务。

应用层负责事件收件箱、长期任务、记忆、审批和通知；定时唤醒可结合持久任务实现，周期规则由应用管理。外部操作还需要幂等或结果核对。

配图分三层：全局架构、主动调度循环、可恢复执行核心。

或许我会尝试在 ChatOllama 中实现一下。

03｜Jane Street开源苏格拉底导师

来源（X） · @mylifcc · 2026-11-16 10:02

在几乎所有公司都在教员工怎么用 AI 一键生成现成答案的时候，华尔街最赚钱、技术品味也最硬核的量化交易巨头 Jane Street 反手在 GitHub 上开源了他们内部的 janestreet/agent_skills 仓库，其中冲上 HN 榜首（712 分）的技能叫 Socratic Tutor（苏格拉底式导师）。

点开这份只有几百行的 SKILL.md，你能看到顶级工程团队对“AI 让人脑退化”这件事有多警惕。它给大模型立下了几条极其严苛的铁律：

只要你对它说出 teach me、quiz me 或 drill me，它被绝对禁止直接给你讲课或甩出长篇解释。它必须先拆出 4 到 10 个子技能树，每次只问你一个问题，连摸底带追问，把你在每个子技能上的真实水平钉死在 0 到 5 级（0 级是闻所未闻，3 级是在提示下能做对，5 级是不靠任何提示且隔轮复习依然对答如流）。

在教学循环里，哪怕你答错了，它也不准直接告诉你正确答案，而是必须顺着你的错误推理反问一句：如果按你说的这样，那当边界条件变成 X 时会发生什么？ 逼你自己推导出矛盾点。直到连续两轮卡死，它才允许给一个最小化的脚手架提示，而且一旦给过提示，这道题就绝不算你掌握（最高只能记 3 级）。在随手一问就能拿到几千字总结的今天，这种故意给大脑制造阻力、逼人自己走完推导闭环的提示词设计，反而成了最稀缺的工程资产。

05｜test-value清理废测试提速单测

来源（X） · @t20000622yy · 2026-11-15 17:15

这两天被开发跑测试和 CI 的速度折磨得实在受不了了。改两行代码，本地跑个测试干等半天，推上去 CI 动不动跑全量，写代码五分钟、看进度条半小时……

忍无可忍顺着耗时扒了一遍，全是 AI 攒下来的无效测试：有拿 grep 源码充当测试的，有测几条参数规则在循环里串行冷启动几十次 node 和 git init 的。最离谱的是个工作区测试，起服务才 13ms、关库 2ms，结果 server.close() 在那傻等 3.47 秒，就因为挂载时顺手发了个查新版本的请求没关干净 😅

把废测试和闲杂请求一清，快慢测试拆池跑完，本机单测直接从 39s 干到 8.8s，Web 测试从 200s 降到 68s，CI 也不瞎跑全量了；效率一下子高太多了

我写了个叫 test-value 的开源 skill 来治这种慢测试和废断言，刚把这次踩的新坑也塞进去了：
https://github.com/tt-a1i/test-value
最近也被测试和 CI 慢得想砸键盘的朋友可以试试
