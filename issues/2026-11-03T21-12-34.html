01｜Auto Ontology 让查询不编造

来源（X） · @Gorden_Sun · 2026-11-03 22:11

NVIDIA Auto Ontology：让AI查企业数据时不再瞎编乱造

企业让AI查数据时经常遇到麻烦，AI往往分不清各种业务术语的具体含义，算出的收入和指标经常出错，普通人根本不敢信任AI给的财务和业务结果。

针对这个痛点，NVIDIA开源了Auto Ontology项目，利用FastAPI、Postgres、Better Auth和NVIDIA NIM模型搭建了一套语义理解层，把复杂的数据库表结构自动整理成清晰的业务关系图谱，并接入统一的查询接口。

接入这套系统后，团队成员只要在网页端用日常大白话提问，AI就能精准理解问题背后的指标定义，自动生成严谨的SQL语句去数据库查出准确数据，每次回答还会附带清晰的数据来源与逻辑依据，避免凭空胡编。

GitHub：https://github.com/NVIDIA/auto-ontology

02｜大厂AI编码工具credit额度化

来源（X） · @mr_easonyang · 2026-11-03 21:37

统一回复下，我知道的国内大部分厂的情况：

1. 几乎都有自己的 AI Coding 产品，做的早的就是 cursor 的变体，做得晚的就是 claude code 或 codex 的变体，做的好点的对外对内用一套。

2. 理论上都要基于上面的内部产品来工作，不过实操中很多人会反代出来用在别的工具上。

3. 都有额度上限，基本都 credit 化了，不同模型同样有倍率概念，其实本质就是个内部中转站。

4. 可用模型层面国产模型是绝对主流，本厂模型强的也会优先推本厂模型，一般也能用古早的 GPT ，反而 Gemini 能用的还挺新，绝对没有 Claude 系模型。

5. 几乎都默许使用自己订阅的 plan ，有的提供有限度报销，有的给固定比例报销，也有的一点不报。报销的那些，不一定是公司层面的，也可能是部门自己决定的。

6. 据我了解各厂的信安部门对个人用自己订阅的 plan 这个事都认为太扯了，但又因为 AI 风潮政治正确敢怒不敢言，所以其实是个灰色地带。

7. 不管报销不报销，真的有好多人自费订阅 plan 用于工作，其实大多也不是出于内卷吧，更多的是觉得内部工具拉胯，或者觉得 SOTA 模型能大幅提高效率。

个人觉得至少在公司里用中转站这个事应该很快会被全面禁止，确实太危险了。

中文译文

我们提出了深度混合注意力（Depth Hybrid Attention, DHA），它将深度值混合（depth-wise value mixing）引入混合架构，仅需极少量额外计算和缓存开销。通过允许各层在深度维度上混合信息，DHA 拓宽了每层的视野，增强了模型的表达能力。

我们的 DHA 方法可适配多种混合架构，包括针对 GQA + SWA 的深度窗口注意力（Depth Window Attention, DWA），以及针对 MLA + KDA 的深度 Delta 注意力（Depth Delta Attention, DDA）。

在损失曲线、短上下文基准测试结果和长上下文检索评估中，两种变体均优于各自对应的全注意力和混合注意力基线，同时保留了混合注意力的低 KV 缓存占用。

项目概览与代码：https://github.com/Nanbeige/Depth-Hybrid-Attention

原文

We introduce Depth Hybrid Attention (DHA), which incorporates depth-wise value mixing into hybrid architectures with very little additional compute and cache overhead. By allowing layers to mix information across depth, DHA broadens each layer’s view and increases the model’s expressive capacity.

Our DHA method adapts to multiple hybrid architectures, including Depth Window Attention (DWA) for GQA + SWA and Depth Delta Attention (DDA) for MLA + KDA.

Across loss curves, short-context benchmark results, and long-context retrieval evaluations, both variants outperform their corresponding full-attention and hybrid-attention baselines, while retaining hybrid attention’s low KV-cache footprint.

06｜Exa索引320万期播客供Agent检索

以后研究一个 AI 创始人，可能得先把他过去几年上过的播客全部搜一遍。

Exa 最近干了件我觉得很有价值的事，把播客变成了可以被 AI Agent 大规模检索的数据库。

目前已经收录了 11.9 万档播客节目的 320 万期内容，覆盖约 220 万小时音频、237 亿个单词，而且提供完整的逐字稿，每天持续更新。

我一直觉得，播客是科技圈信息密度非常高，但长期没有被充分利用的一种信息源。

很多硅谷的创始人、投资人、高管，会在一两个小时的访谈里讲出大量细节。包括他们怎么判断竞争对手，为什么放弃某个业务，对某项技术的态度什么时候发生了变化。

这些内容往往比新闻稿、财报电话会有意思得多。但过去想从几百期节目里找到某个人说过的一句话，几乎只能靠人工逐集听。

Exa 现在让 Agent 可以直接检索这些内容。

比如，你可以让 Agent 整理某位投资人在过去三年对 AI Agent 的所有公开判断，按照时间排列，看看他的观点是怎么变化的。

也可以追踪一家 AI 实验室在不同播客中的被提及频率，找出它什么时候开始进入硅谷投资圈的讨论，最早是谁在反复提起它。

对于深度报道、人物研究和投资研究来说，这个能力非常实用。尤其是那些散落在不同节目里、从来没有被媒体单独报道过的细节，现在终于有机会被系统性地挖出来。

我甚至觉得，这会改变科技圈很多人对公开表达的态度。

过去在两小时播客里随口说的一句话，只要没被剪成短视频，可能就慢慢淹没在音频里了。

以后，任何一句话都可能被 Agent 找出来，和你三年前、五年前说过的话放在一起对照。

互联网已经记录了人们写过什么，现在开始系统性地整理人们说过什么了。
