05｜CNEquity整合55类A股金融数据

来源（X） · @_zheergen · 2026-10-18 13:45

卧槽！A 股量化最折腾的数据源整合，居然有人直接做成了开源工具！

55 类金融数据集，行情、财报、资金流全覆盖，连 Codex、Claude Code 都能直接接入做 AI 量化研究！

这个开源项目叫 CNEquity。

它是一套专门面向 A 股的金融数据整合工具，支持沪深京市场的数据采集、自动更新、本地存储和统一查询，基础采集无需 API Token。

以前做 A 股量化，光是找数据源、处理复权、整理财报和维护数据库，就够折腾了。

现在这些基础工作，CNEquity 已经提供了现成的解决方案。

核心亮点：

1️⃣ 55 类金融数据集：覆盖股票行情、财报、资金流、行业板块及宏观数据。

2️⃣ 自动采集更新：支持多数据源、每日增量更新和断点续传。

3️⃣ 专业回测数据：支持复权、历史指数成分和 PIT 财报查询，辅助减少未来数据泄漏。

4️⃣ AI Agent + MCP：接入 Codex、Claude Code、Gemini，直接查询本地 A 股数据。

5️⃣ 本地数据管理：采用 Parquet 存储，支持 Python、DuckDB、Polars 查询分析。

6️⃣ 可视化管理：内置 Web 控制台，查看数据覆盖、更新任务和质量检查结果。

我觉得最有意思的，是它把 A 股数据和 AI Agent 真正连接起来了。

比如让 Codex 查询宁德时代的历史行情，再结合财报、资金流和行业数据，辅助研究量化选股策略。

数据采集 → 本地存储 → AI 分析 → 量化研究。

原本需要自己搭建的数据采集和管理系统，现在已经有现成的开源实现。

不过 55 类是已登记的数据集，不代表安装后全部可用，部分数据需要额外启用。它也不是自动交易系统。

做 A 股量化、Python 选股，或者想让 Codex 接入金融数据的，这个项目值得收藏。

https://github.com/rootSunc/CNEquity

07｜用LiteLLM集中管控API key

来源（X） · @bojie_li · 2026-10-18 11:49

API key 的管理严格程度应该参考 Web3 钱包。我个人和服务的几个公司的 API key 都被盗刷过不止一次，每次都损失几千美金。原因包括但不限于服务器被入侵 key 泄露，实习生泄露等。

除了盗刷，还有很多浪费，比如 harness 死循环浪费，CI 跑 eval 用例过多浪费。

拿着厂商的 API key 裸跑太不安全了，更合理的是用 LiteLLM，厂商 API key 只放进安全机器的 LiteLLM。LiteLLM 不仅可以记录请求做可观测性，还能检测和防止 API key 滥用。

首先，LiteLLM 仅内网可访问，这就消除了 key 被别人拿到之后随便乱用的最大风险。

顺便说一句，AI 挖漏洞越来越强、越来越多服务用 AI 部署的今天，传统的 VPN 内网反而成了更靠谱的方案。只要服务器暴露在公网上，就有被入侵的风险。我有一台服务器用 AI 部署了一个目录服务，它说是走了 Cloudflare tunnel，但它不小心监听了 0.0.0.0，结果家目录里的 API key 就暴露出去了。

其次，很多开发者会到处复制粘贴 API key 导致管理混乱。LiteLLM 可以检测一 key 多用。给每个 key 配套一个 canary 字符串，每种线上服务、CI 测试系统、coding agent 等在 system prompt 里面都预设一个 canary 字符串，如果 LiteLLM 发现请求缺少这个 canary，就说明被滥用，拒绝请求并告警。

开发者测试可以用不做 canary 检查但额度比较小，泄露了也问题不大的 key。
