01｜Harness自修将任务完成率提至40%

来源（X） · @undefinedKi · 2026-11-20 05:19

中文译文

两位 Google 工程师刚刚分享了他们的设置，让一个 agent 能够修复自己的 harness。
它从解决 5% 的任务提升到了 40%，同时 token 消耗减少了 2.5 倍。以下是它的工作原理。

这个设置从一个很小的 harness 开始，4 个文件共 142 行。一个用于记忆，一个用于 turn loop，一个用于工具，一个用于 agent 停止前的检查。

第二个模型获取失败运行的日志并修复那些代码。

每一轮是这样的。模型读取失败的运行，寻找反复出现的错误。它选择一个文件并写一个小修复。这个修复在模型从未见过的任务上运行。如果分数下降或 token 超过限制，它就被丢弃。如果不是，它就进入 harness。

主要的洞见是一次只改一个文件。一次性重写所有东西效果差不多，但 token 消耗多了近 10 倍，而且更容易崩溃。

几轮之后，模型写了 4 个修复，它们留在了 harness 里：

1. 旧的轮次被压缩成简短的笔记。
2. 长的终端输出被截断。
3. 如果 agent 没有改变任何代码，它就不能说它完成了。
4. 只有代码编译通过并且测试通过后，agent 才能停止。

你可以对任何 agent 重复这个过程。把你的 harness 拆分成几个小文件，保存失败运行的日志，让一个模型一次修复一个文件，只保留那些在新任务上通过的修复。

原文

Two Google engineers just shared their setup that lets an agent fix its own harness.
It went from solving 5% of tasks to 40% while using 2.5x fewer tokens. Here is how it works.

The setup starts with a small harness, 142 lines in 4 files. One for memory, one for the turn loop, one for tools, one for checks before the agent stops.

A second model gets the logs of failed runs and fixes that code.

Each round goes like this. The model reads the failed runs and looks for errors that keep repeating. It picks one file and writes a small fix. The fix runs on tasks the model never saw. If the score drops or tokens go over the limit, it gets thrown out. If not, it goes into the harness.

The main insight is to change one file at a time. Rewriting everything at once solved about the same but used almost 10x more tokens and broke more easily.

After a few rounds, the model had written 4 fixes that stayed in the harness:

1. Old turns get squeezed into short notes.
2. Long terminal output gets cut.
3. The agent can't say it's done if it didn't change any code.
4. The agent can only stop after the code compiles and the tests pass.

You can repeat this with any agent. Split your harness into a few small files, save the logs of failed runs, and let a model fix one file at a time, keeping only the fixes that pass on new tasks.

03｜Baseten按需加载工具降本62.5%

来源（X） · @Xudong07452910 · 2026-11-20 08:59

不换模型、不改 Harness，Agent 成本可以降 62.5%。

Baseten 这篇讲的是「按需加载工具」。平时挂的 MCP 越多，每次请求塞进上下文的工具说明就越多，他们只挂了 3 个 MCP，就多出约 14 万 token。

换成按需加载以后，一开始只给工具名和一个搜索工具，约 1.3k token，模型用到哪个再加载哪个。

他们用 GLM 5.3 测下来，编码任务成本降了 62.5%，速度快了 26.2%。另外有个小坑，Claude Code 和 Codex 接第三方开源模型时会默认关掉这个功能，要记得打开。

工具越挂越多的时候，先别急着换模型，可以先看看上下文里装了多少用不上的东西。
