01｜Cordis插件化框架重构Agent循环

来源（X） · @antiAIvo · 2026-11-04 11:12

DeepSeek Harness， Github上的代码库一百多万行代码
官方说法叫“一切皆插件”，连 Agent 循环都是插件
刚听到时我不太理解
这两天开始学习它底层那个叫 Cordis 的框架
慢慢搞懂了是怎么实现这一切的
画了张图，按图从上往下说

左上角是没有主板的写法
自己从零写 Agent，基本都是这么开始的：
一个 http://agent.py 把循环写死，模型、工具直接 import 进来
想加个审批，只能打开循环往里塞 if
主流的 Claude Code、Codex也基本是这个做法

右上角是 Cordis 的思路
插件之间谁也不 import 谁，只认一块主板 ctx
模型插件把自己挂成 ctx.llm，循环要用模型就按名字去拿
背后是 DeepSeek 还是别家，循环根本不关心

中间那一大块是主板本身
左边是一张张插件卡，经过 Loader 挂到 ctx 上
装机清单里先写谁后写谁无所谓，插件只说“我要 llm 和 tools”
没到齐就等，到齐了自己启动
右边绿色的三块值得多看一眼：Agent 接口和 Agent 循环是分开的
别的插件只认接口，所以循环能整个换掉

左边中间那个洋葱，是工具调用要走的路
一次调用从外往里穿过审批、日志，最里面才是真正执行
每一层都能改参数，也能不往下传，直接拦掉
审批就是这么实现的，不用碰循环一行代码

右边那块讲拔卡和换卡，我觉得是整个设计最精巧的地方
拔掉模型时，不是模型先走，而是依赖它的循环先收尾
收尾时还能再调一次模型，模型最后才撤，改模型配置也一样

04｜MySQL与PostgreSQL选型指南

来源（X） · @nicoster · 2026-11-04 12:37

MySQL 真的是清朝数据库吗
原始链接：https://x.com/realchendahuang/status/2117710533428465909

X 上有一条帖子劝大家别再用 MySQL 这种清朝数据库，赶紧换成 PostgreSQL（下文简称 PG）。这话传得很广，我觉得只说对了一半。

先说 PG 强在哪。它的 SQL 能力更完整，DDL 可以放进事务，出错整体回滚；部分索引、表达式索引、数组和范围类型都是现成的，JSONB 也比 MySQL 的 JSON 好用。更大的优势是扩展，PostGIS 管地理数据，pgvector 管向量检索，TimescaleDB 管时序数据，一个库能顶好几个系统。复杂的多表查询，PG 的优化器也更成熟，MySQL 到 2019 年的 8.0.18 才支持 hash join。许可证方面，PG 采用宽松许可，没有单一厂商控制。

但是，MySQL 并不老。2018 年的 8.0 补上了 CTE（公用表表达式，你可以想成 SQL 里的临时变量）、窗口函数、原子 DDL 和秒级加列。8.0 今年 4 月停止维护，现在的长期支持版是 8.4 和 9.7。

MySQL 也有 PG 比不了的地方，最典型的是 VACUUM。PG 更新一行时，旧版本留在表里，要靠 VACUUM 清理，更新频繁的表容易膨胀。MySQL 把旧版本放进 undo log，没有这个负担。2016 年 Uber 从 PG 迁回 MySQL，写放大就是主要原因之一。连接模型也不同，PG 每个连接起一个进程，连接一多就得加 PgBouncer 这样的连接池；MySQL 用线程，扛连接更轻松。复制和分库分表，MySQL 的生态更成熟，Vitess、TiDB、OceanBase 都兼容 MySQL 协议，国内熟悉 MySQL 的 DBA 也多得多。

帖子后半段说，生产环境不要随手用容器跑数据库。这一点我同意，但问题不在 Docker 本身，而在存储卷、备份和高可用有没有人管。这件事和选 MySQL 还是 PG 无关，买云厂商的托管实例，或者自己搭三节点的高可用集群，两边都适用。作者推荐的 Pigsty 是一个开源的 PG 集群部署工具。

我的看法是，新项目没有历史包袱，需要复杂查询或扩展，默认选 PG 没错。已经稳定跑着 MySQL 的系统，没必要因为一句清朝数据库去迁移，更值得做的是把还停在 8.0 的实例升到 8.4。

05｜20家单位发布智能体自律公约

来源（X） · @bytelee_trade · 2026-11-04 16:04

11月4日，中国信通院、华为、阿里、腾讯、小米、百度、火山引擎等20家单位在乌镇联合发布《智能体发展自律公约》。八条措施里最具体的是两条：建立分层次、可验证的智能体身份标识；共建注册解析、能力描述与发现、路由连接等互联基础设施。

同一天，天融信发布“三域一平面”智能体安全框架，把安全对象拆成对象、身份、行为、数据四个维度；蚂蚁集团则披露旗下医疗AI“阿福”的四层治理体系，从价值原则、医学伦理一直排到模型数据治理和组织保障。三件事放在一起，指向同一个变化：厂商的注意力正从“模型能干什么”转向“它干了事，责任算谁的”。

这个转向有现实原因。智能体开始代替人登录账号、下单、支付、读取病历，出错成本由用户承担，责任却容易落在链条最模糊的一环。身份标识和互操作协议本质上是责任分配的基础设施：谁签发身份、谁记录行为、谁有权熔断，决定了事故之后能不能追溯。

需要保留的判断是，自律公约没有强制力，条款多为“共建”“提升”这类方向性表述，身份标准、审计接口、跨平台互认都还没有可查的落地文本；蚂蚁的四层体系目前也只覆盖自家产品。真正的考验是接下来有没有公开的技术规范和第三方合规测试，而不是发布现场站了多少家单位。
