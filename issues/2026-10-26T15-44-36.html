09｜Agentgateway 聚合 MCP 与模型

来源（X） · @AISuperDomain · 2026-10-25 22:00

发现一个值得关注的开源项目：Agentgateway，专门为 AI Agent 打造的统一网关！

项目采用 Rust 开发，隶属于 Linux Foundation，核心目标是解决 AI Agent 生态中日益复杂的模型调用、MCP 工具管理和多 Agent 通信问题。

它最大的亮点是将三种能力整合到一起：

🔹 LLM Gateway：统一接入 OpenAI、Claude、Gemini 等模型，支持智能路由、负载均衡、限流和成本管理。

🔹 MCP Gateway：将多个 MCP Server 聚合为统一入口，集中管理工具权限、身份认证和调用日志。

🔹 A2A Gateway：支持 Agent-to-Agent 协议，让不同 AI Agent 能够安全地发现、调用和协作。

此外，还支持 OAuth、JWT、OpenTelemetry，以及与 Kubernetes 的集成。

对于个人开发者来说，可能有点大材小用，但如果你正在构建多 Agent 系统、AI SaaS 或企业级智能体平台，它的价值就非常明显了。

简单来说，Agentgateway 想做的就是 AI Agent 时代的 Nginx！

GitHub：https://github.com/agentgateway/agentgateway

来源（X） · @Sumanth_077 · 2026-10-26 21:29

中文译文

Claude Code、Codex 和 Hermes 现在可以作为一个团队协作了！

BAND 让你本地的 coding agent 们协同工作：它们共享上下文、交接任务、并互相解除阻塞。

通常，运行多个 coding agent 意味着运行多个独立的会话。Claude Code 可能处理后端，Codex 处理前端，另一个 agent 负责审查，但最终你仍然需要在它们之间手动传递上下文。

BAND 给这些 agent 围绕任务创建了一个共享的协作空间。

一个 agent 可以制定计划，将工作拆分为任务，并把各个部分交给其他 agent。这些 agent 可以直接互发消息，随工作一起传递上下文，并将当前状态保存在任何单个 coding 会话之外。

你的 coding 会话仍然在你已有的工具中本地运行。BAND 作为协调层围绕它们，所以你可以看到每个 agent 正在做什么、哪里被阻塞、以及哪里真正需要人工决策。

这也意味着规划者或审查者不必在实施开始后就消失。他们可以留在同一个空间里，随着工作进展随时介入。

核心能力：

- 跨 coding agent 的共享上下文
- agent 之间的直接消息传递和任务交接
- 共享的计划、任务和工作归属
- 本地 coding 会话配合集中化的可视性
- 工作流内部的人工决策和审批

这里有趣的部分在于，添加更多 coding agent 是容易的。真正难的问题是让 Claude Code、Codex、Hermes 或其他 agent 在同一个任务上真正协同工作。

BAND 正在构建围绕它们的共享层。

我把链接放在评论区了！

原文

Claude Code, Codex and Hermes can now work as a team!

BAND lets your local coding agents work together: they share context, hand off work, and unblock one another.

Normally, running multiple coding agents means running multiple separate sessions. Claude Code might handle the backend, Codex the frontend, and another agent reviews the work, but you still end up being the person carrying context between them.

BAND gives those agents a shared room around the task.

One agent can create the plan, split the work into tasks, and hand pieces off to other agents. Those agents can message each other directly, pass the context with the work, and keep the current state outside any single coding session.

Your coding sessions still run locally in the tools you already use. BAND sits around them as the coordination layer, so you can see what each agent is working on, what is blocked, and where a human decision is actually needed.

That also means the planner or reviewer does not have to disappear once implementation starts. They can stay in the same room while the work progresses and step back in when something changes.

Key capabilities:

- Shared context across coding agents
- Direct agent-to-agent messaging and handoffs
- Shared plans, tasks, and work ownership
- Local coding sessions with centralized visibility
- Human decisions and approvals inside the workflow

The interesting part here is that adding more coding agents is easy. Getting Claude Code, Codex, Hermes, or other agents to actually coordinate around the same task is the harder problem.

BAND is building that shared layer around them.
