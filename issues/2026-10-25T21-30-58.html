02｜grok bot多端登录跨平台操作

来源（X） · @Chris_Defi · 2026-10-25 18:19

最近深度使用了几周 grok @bot 和 @Muse 写个测评

1，bot最牛逼的地方是多端登录，这个我看x没几个人提到，同时登录mac、linux、ios、windows，可以通过ios跨平台的操作其他同时在登录的系统，这不是龙虾、Hermes可以做到的程度。

2，现在用bot全自动的在自媒体起号，从选题、视频生成、发布、自动评论，一条龙每天像个勤恳员工，200u订阅必须拉满。

3，很多人担心ai起号封号的问题，我用几台手机外接了linux dgx，让bot用adb操作安卓手机，所有操作都在手机完成，上传、发布、评论。整个过程蒸馏成skill，其他任务复用。

4，muse毕竟免费白嫖的，送还外送一台kvm机器，大概等值约300人民币一个月，十亿token每周免费重置。muse的优势是免费，光这点确实秒杀市场其他同类产品。

5，muse干工程类代码类的活稍微差点意思，比如让他选题让剪个视频，还得外接个api，不然像个呆瓜。远程操控的体验不如grok bot，和gpt的dot在一个水平。

6，他们送的机器都没有外接端口，要本地起个服务接外网访问，最佳实践是常驻进程走cf tunnel，其他方案都不如这个，这个还支持走cf的ssh。其他静态ip的优势就不赘述了。

7，最舒服的用法是给bot和muse都装上claude cli、codex cli，让bot操作他们干活。尤其复刻视频，在网上刷到比较好玩的视频直接让bot拆解、复刻、审核、然后发布。

8，muse现在除了免费还没有发现其他比grok bot体验上做的好的地方，muse差不多就是低配的bot，我猜测是kvm配置的原因+muse模型聪明度综合原因。也许muse对美国本土应用有比较好的适配是我没发现的优势。

9，muse暂时不支持跨平台操作，本地执行权限比较低，高权限全部放在它的远程服务器上。日常的一些简单任务需求可以让muse做，涉及工程、代码、跨平台高权限协作、多端混合协作，bot是目前最能打的没有之一。

10，关于交易，bot挺适合用来盯盘和策略执行的，但策略定制还得靠人。投资交易更像是抽象哲学艺术，ai只能解决工程类问题，解决不了艺术审美，策略好坏本身就是个主观审美问题。很多人给grok bot 100u 让它赚钱，就好比你给ai一百张图，让它挑出好看的，只许好看不许丑。

11，目前个人最佳实践组合是paseo+grok bot+claude cli+codex cli，可以说是opc最舒服的状态。手机随时vibe和运营，电脑也是全平台同步上下文。

05｜HarnessRouter统一切换框架

来源（X） · @AISuperDomain · 2026-10-25 19:01

最近发现一个值得关注的开源项目：HarnessRouter，它试图解决 AI Agent 生态中的一个痛点——不同 Agent 框架之间缺乏统一的调用接口。

目前，HarnessRouter 已支持 Claude Code、Codex、OpenCode、Gemini CLI、Hermes、DeepSeek Harness 等 26 种 Agent Harness。

它最大的特点不是切换大模型，而是切换整个 Agent 执行框架。

通过统一的 Unified Harness Protocol（UHP）协议，开发者只需要一个 API，就能调用不同 Agent 执行任务，并统一管理会话、实时输出、文件读写、任务取消和错误处理。

例如，开发者可以将 Claude Code 或 Codex 作为自己产品的后端，让 AI 自动编写代码、生成文档、制作幻灯片，甚至参与视频制作。

项目兼容 OpenAI Responses API，支持 Docker 一键部署，社区版采用 Apache 2.0 开源协议，可以使用自己的模型 API Key，在自有基础设施上运行。

它真正的价值，是让 AI Agent 像大模型一样，成为可以自由接入和替换的基础设施。

GitHub：https://github.com/HarnessRouter/harnessrouter

06｜AI写码速度超过人读代码

来源（X） · @real_doctormin · 2026-10-26 01:44

我觉得我能理解Anthropic的内部工作流以及Git版本爆炸的原因、还有他们员工感慨的“大家对AI用的还不够激进”。

因为我们公司用的非常激进，人不光不写，甚至也不看代码了。日均上百个 commit。人正常下班，AI工作日夜不停。人只报需求与反馈BUG，AI session 自己开 Issue、跟进度、通知协作方，对方的 AI 收到后接着处理、反馈。协作靠 Issue 流转，不用人来回传话。

代码质量不一定很高，但是需求实现极快、性能迭代极快、人力需求极少，其他公司很难竞争。同时，这这带来两个变化：

第一，AI 写代码的速度，已经超过人看代码的速度。程序员的工作也变了，更像产品经理加测试：把需求说清楚，盯住关键节点，最后把功能、交互、性能验收充分。实现细节，不必事事过问。

第二，AI 提需求的能力还远不如人，而人也不可能什么都想到。所以，不同分系统仍然需要不同的人负责。每个人都在带自己的 AI 干活，某种程度上就是 AI session manager，管的是一组 AI 员工。但是，人类员工分工还是要清楚，职责尽量少重叠。一个人的 context，装不下整家公司。

所以现在招人，我对背景、写代码能力已经不在乎了，越来越看重审美、判断力和感知力：能不能发现问题，知道什么值得做，也看得出做出来的东西到底好不好。
