01｜月之暗面被曝租用英伟达B300

来源（X） · @0xLogicrw · 2026-11-10 17:42

月之暗面（Kimi）已经在国内成功租到英伟达顶级 B300 芯片。

彭博找到两份提交给监管数据库的融资合同，显示 32 台搭载 B300 的美超微服务器位于甘肃庆阳，总估值 4.32 亿元。B300 属于英伟达 Blackwell Ultra 系列，是美国严格限制对华出口的顶级 AI 芯片。32 台服务器平均估值 1350 万元，比美国同类产品的市场价格高出约 350%。

合同签署于今年 8 月。服务器由凌美芯（北京）科技持有，该公司向北京中关村银行贷款 2 亿元，抵押物除了服务器，还有一份与月之暗面签订的算力服务合同，涉及 3.456 亿元预期收入。

凌美芯早年从事无人机、计算机视觉等业务。它从北京春菊科技一家新成立的子公司购买了这批服务器，而北京春菊科技此前主要经营茅台等酒类电商，后来才拓展 AI 业务。文件没有交代这些受美国出口管制的服务器最初从哪里采购。

彭博在 11 月 3 日向月之暗面、凌美芯及银行求证后，数据库中的相关文件不再出现月之暗面的名字。

月之暗面同时否认参与或授权相关融资和担保安排，称目前与凌美芯没有业务关系，也不知晓这些安排。英伟达和美超微则表示，涉及采购的企业并非其客户。

02｜Magpie长期内存泄漏集中在渲染进程

来源（X） · @jeff_liz · 2026-11-10 16:16

似乎 magpie 开久了，会比较占内存。跑了一天多，加起来 2.76 GB，占了一台 16 GB Windows 机器的 17%。

拆开看是八块：agents 窗口的渲染进程 2,098 MB,浏览器进程 110 MB,第二个渲染进程 97 MB! GPU 进程 94 MB,两个辅助进程 37 MB 和 19 MB,崩溃处理器 15 MB,主进程 293 MB。

问题几乎全在第一个渲染进程上——它一个就占了 76%。主进程只有 293 MB,而且一天多只从 204 涨到 293,很稳。所以漏的不是 magpie 本体,是 agents 那个页面。

看着像页面跑久了没释放数据:会话、模型列表、日志这类东西越攒越多,或者定时拉数据时反复建对象没回收。

命令是 magpie-windows-amd64.exe gui agents，renderer-client-id 6，版本 0.1.3336。只能手动重启收回来。

07｜六仓库补齐Agent抓取记忆与图谱

来源（X） · @0xluffy_eth · 2026-11-10 10:44

玩 agent 的，这 6 个 GitHub 仓库必看：

1. Firecrawl
把实时网页抓下来，转成 agent 能直接用的干净文本。
https://github.com/firecrawl/firecrawl

2. claude-mem
记录 agent 做过什么，压缩之后把有用的部分带进下一次会话。
https://github.com/thedotmack/claude-mem

3. Graphify
把代码库、文档、SQL schema 和 PDF 变成本地可查询的知识图谱。
https://github.com/Graphify-Labs/graphify

4. Ponytail
让 agent 像团队里最会偷懒的资深开发那样思考：最好的代码是没写出来的代码。
https://github.com/DietrichGebert/ponytail

5. Taste Skill
给编码 agent 补上美术方向、参考图和浏览器检查，页面终于不那么像 AI 生成的。
https://github.com/Leonxlnx/taste-skill

6. ECC
面向 Claude Code、Codex、OpenCode 和 Cursor 的技能、记忆和安全配置。
https://github.com/affaan-m/ECC
