01｜Home Repo统管多仓库Agent

中文译文

很多人问我："你是怎么同时在多个代码仓库中与 agent 协作的？"

我有一个非常简单的方案——Home Repo（主仓库）

我有一个单独的仓库（主仓库），里面存放我所有的技能、引导文件、wiki 等内容。

我在主仓库中运行我的 agent，然后在 AGENTS.md 中写入指向其他仓库的指引：

```
关于技能，将 mattpocock/skills 克隆到 ~/repos/skills。
关于 Sandcastle，将 mattpocock/sandcastle 克隆到 ~/repos/sandcastle。
```

这极其简单，同时效果非常好。主仓库让你可以：

1. 把所有引导文件和工具集中在一个地方
2. 有一个统一的位置来运行你所有的 agent
3. 在多个仓库上做全面性的改动

我昨天在课程中讲了这个方法，大家非常喜欢（见下方）。

我相信你也会喜欢的。享受吧！

原文

A lot of folks ask me "how do you work with agents in multiple repos at once?"

I have a very simple solution - the Home Repo

I have a single repo (the home) where all of my skills, steering files, wiki etc live.

I run my agent in the home repo, and then inside AGENTS.md I have pointers to the other repos:

```
For skills, clone mattpocock/skills to ~/repos/skills.
For Sandcastle, clone mattpocock/sandcastle to ~/repos/sandcastle
```

This is extremely simple and incredibly effective. The home repo lets you:

1. Put all your steering files and tooling in one place
2. Have a single spot to run all your agents in
3. Make sweeping changes over multiple repos

斯坦福CS329Z — Engineering AI Agents（2026 秋季）这门课程现在终于在youtube上线了。

这是一门全新的斯坦福研究生课程，由 Diyi Yang、Michael Ryan（DSPy 核心贡献者）和 John Yang（SWE-bench 共同创建者）共同授课。⁠

核心定位是：从单一大模型转向复合 AI 系统（Compound AI Systems） 的工程实践。也就是把 LLM、检索器、工具、优化器、记忆等组件组合起来，构建从简单流水线到自主 Agent 的完整系统。

课程强调动手工程能力，而不是只讲概念：

先从零实现核心组件（RAG、工具调用、Agent Loop），再学习框架（如 DSPy）如何抽象这些模式。
重点训练：问题拆解、组件选型、数据收集与整理、评测体系搭建、设计权衡、可靠性与安全。

主要内容覆盖
Agent 基础与解剖结构（LLM 核心、推理、记忆、工具、环境）
RAG（索引、检索器、Agentic RAG）
工具使用与函数调用（包括 MCP）
框架与编排（DSPy、LangGraph 等）
Agent 设计模式（ReAct、Reflexion、CodeAct 等）
记忆架构、多智能体系统
优化（提示、权重、系统级）
评测（LLM-as-Judge、benchmark 设计、pass@k 等）
安全与防护（prompt injection、沙箱、权限模型）
专项主题：编程 Agent、主动式 Agent

还有嘉宾课，包括 Terminal-Bench、SWE-bench 团队，以及与 Andrew Ng 的 fireside chat。

作业与实践（已公开）

HW1（Michael Ryan 设计）：从零搭建 Agent Harness（类似迷你版 Claude Code）。要求不用现成框架，只用 chat completion API + 自己写代码。基于真实公司邮件语料做检索、摘要、工具调用、终端、记忆、人工审批等。成本很低（参考实现跑完测试大约不到 1 美元）。⁠
仓库：https://github.com/cs329z/assignment1-harness

HW2（John Yang 设计）：使用 Harbor 框架构建接近 Terminal-Bench 风格的真实 Agent 评测任务。学生要自己设计问题、运行环境和验证器。
仓库：https://github.com/cs329z/assignment2-evals

课程网站：https://cs329z.stanford.edu/

YouTube 播放列表已开始更新（Lecture 1 已上线）：https://www.youtube.com/watch?v=DGI4vucR71w

整体来说，这是目前斯坦福最系统、最偏工程实践的 AI Agent 课程之一，重点在“怎么真正把 Agent 系统做出来并可靠运行”，而不是只调用现成框架。材料正在全面公开，现在是跟着学的好时机。

04｜Agent记忆系统设计的九个问题

来源（X） · @Suercha007 · 2026-11-11 10:18

做 Agent 开发的看过来了，有朋友经常问 Agent记忆系统怎么设计。

其实记忆系统只回答三个问题：记什么、怎么存、怎么用。其余的都是围绕这三点的工程约束。

1. 何时记，你应该考虑的问题有，触发时机、触发延迟、背压、同步异步等。

2. 记什么，需要考虑写入门槛、消息识别与过滤、记忆来源等

3. 存哪里，存储介质、数据模型、索引策略、数据版本等等

4. 冲突与一致性，需要考虑的问题有语义冲突策略、冲突检测、崩溃恢复等等

5. 生命周期，记忆时效管理、淘汰策略、合并策略、遗忘策略等等

6. 何时读，召回时机与粒度、前缀缓存问题、注入策略

7. 检索，主要是召回策略

8. 怎么注入，注入位置和形态、预算分配策略、防注入策略、权限边界等。

9. 安全隐私与权限，认证边界、记忆投毒、用户攻击等安全问题。

解决的上面的问题，一个完整的记忆系统就完成了，至于每一步怎么实现，用什么框架，这个因人而异。

05｜Cursor项目支持多智能体协作

来源（X） · @Gorden_Sun · 2026-11-11 09:44

Cursor又走在了前面。

之前是一个主Agent协调你的智能体群来完成工作，但是只是你个人用。现在推出了项目合作空间，团队的Agent可以共享上下文、互相沟通，仿佛真人协作的工作机制，有影响他人的变动，Agent就会彼此告知。

例如，一位工程师正在为产品页面添加评价功能，而一位设计师正在重新设计这个页面，他们的协调智能体会及早发现两者的工作存在重叠，并主动同步，让评价功能直接融入新设计，免去日后的代码重构。又如，你的功能需要从数据库读取数据，而你的团队成员正在修改数据库架构，此时你们的智能体会预先商定工作顺序，这样你们谁都不会在最后遇到合并冲突。
