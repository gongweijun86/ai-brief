05｜Coding Agent 管理六条要点

来源（X） · @NFT_Chen · 2026-11-08 16:59

🔥必读！Claude工程师最新文章指出AI代理时代，拉开差距的不是Prompt，而是管理能力！

你每天跟Coding Agent干活，本质就是在管团队。选任务、写指令、授权、验收、决定什么能上线，这些才是核心竞争力。

从Claude工程师视角浓缩的6个高杠杆要点：
1️⃣先给它验活的能力：必须让它自己跑测试/构建/截图，别当人工测试机。没验证，它只会停在“看起来做完了”。

2️⃣只补它看不见的上下文：目标、为什么做、边界、成功标准必须写清。代码里能读到的别废话。

3️⃣纠错要复利：同一个错误改两次以上，立刻写进CLAUDE.md或做成Skill。

4️⃣默认放权，只锁死不能弯的：让它自己决定实现方式，只有绝对不能做的事才硬约束。

5️⃣先对齐计划再动手：Plan模式聊透假设，再写代码。并行任务必须无重叠。

6️⃣任务可委托，判断权绝不外包：产品决策、安全边界、能不能上线必须自己拍板。看diff要像自己会被叫醒一样认真。

不会管理的工程师会被Agent反噬；会管理的，一个人就能当一个小队。实践成本极低，反馈以分钟计。

06｜ljg-card 文字转长图白板漫画

来源（X） · @Morry4AI · 2026-11-07 18:23

最近发现一个很适合内容创作者的开源 Skill：ljg-card。

它可以把一段文字，直接转换成知识长图、视觉笔记、漫画、白板等不同形式的图片。

这 3 张配图是我用这个 Skill 把之前的文字内容转换成了不同的视觉表达形式。

我觉得可以从下面 3 个场景使用。

——

01｜把文章、笔记变成知识长图

可以直接把文字交给 ljg-card，让它先分析内容结构，再生成一张完整的知识长图。

比如：
● AI 工具教程 → 操作步骤长图
● 学习笔记 → 知识总结长图
● 长篇文章 → 重点内容可视化

它不是简单地把文字截图，而是会重新组织信息层级，搭配插画和视觉排版。

——

02｜把复杂知识变成可视化白板

可以让 ljg-card 使用白板模式，把接收任务、分析需求、调用工具、执行任务等环节，通过手绘元素和文字组织成一张视觉白板。

比较适合：
● 解释复杂概念
● 制作知识科普
● 梳理工作原理

相比纯文字，读者更容易看清楚整个过程。

——

03｜把文字变成漫画

这是我觉得比较有趣的一个功能。

同样是一段文字，还可以让 ljg-card 用漫画形式重新表达。

让它把人物、场景和操作过程拆分成多个画面，制作成一组连续的漫画。

除了知识科普，也可以尝试用来制作产品介绍、教程故事和社交媒体内容。

——

04｜怎么使用？

ljg-card 是开源 Skill合集中的一个Skill，可以通过 Codex 等 Agent 安装和使用。

安装时，可以只装这1个Skill。

打开 Codex，直接告诉它：

「
帮我从下面的 GitHub 仓库安装 ljg-card Skill，只安装这个 Skill，不需要安装整个合集。
项目地址：
」

安装完成后，就可以把自己的文字交给 Codex。

需要注意，生成效果会受到内容长度、模型和本地环境影响，复杂内容最好检查一下文字准确性和排版。

——

我觉得 ljg-card 最有价值的地方，是可以把同一份文字内容，转换成不同的视觉表达形式。

写好的文章可以变成长图，复杂的知识可以变成白板，有趣的故事可以变成漫画。

09｜ERP AI化：上层叠加而非重做

来源（X） · @HavenZhao · 2026-11-08 11:30

传统的信息化系统，有没有必要都改成AI系统？

答案未必是肯定的。

ERP、财务、生产这些核心系统，最重要的是稳定、准确、可审计。一笔账、一张单据，结果必须确定。这恰恰不是大模型的强项。为了"AI化"去动它们的核心逻辑，风险往往大于收益。

AI真正有用的地方，是这些系统做不好的部分：数据散在多个系统里，要跨系统汇总分析；大量的文档、合同、报告，靠人去读；需要经验和判断的环节，规则写不全。

所以更值得问的不是"要不要改成AI系统"，而是三个问题：

有没有一个具体的痛点，是AI能解决、而现在的系统解决不了的？

数据准备好了吗？口径乱、版本多，接上AI只会把问题放大。

投入和收益算得过来吗？模型、算力、维护都是长期成本。

三个问题都有答案，再动手。

动手的方式，也更推荐"在上面加一层"，而不是"推倒重做"：老系统继续管数据和事务，AI负责跨系统的理解、分析和协助执行。

信息化系统解决的是"把事记下来、管起来"，AI要解决的是"把事看明白、办得更快"。两者是叠加，不是替代。

你们公司的老系统，最想让AI帮忙的是哪一块？
