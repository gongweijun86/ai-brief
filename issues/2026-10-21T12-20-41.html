01｜BitKindle 演化出 C 编译器

来源（X） · @python_xxt · 2026-10-21 13:48

TK教主的推特账号要复活了

引用内容

Yang Yu @tombkeeper

刚开始接触生物学的时候，我经常想象原始海洋里的有机分子构成核糖核酸，然后诞生了最早的单细胞生物，单细胞生物又聚在一起变成黏糊糊的原始多细胞生物，最终一步一步演化出各种生灵。我也经常想，如果能在实验室里加速重现这一过程，完整观察整个生物演化史就好了。

刚开始接触计算机的时候，我想过一个问题：程序是从哪里来的？后来我知道了编译器，程序从编译器来的。编译器自然也是从其它编译器来的。那么最早的编译器是从哪里来的？后来我逐渐搞清楚了这个问题的答案。但偶尔还是会想一些相关的问题，比如：如果现在全世界的编译器都忽然消失，人类要怎么重建整套体系呢？

最近几年研究 AI 安全问题的时候，我经常想：如果只给予 AI 完成特定工作所需的工具，那么 AI 的能力是不是就会被限制住？是不是就可以阻止 AI 获得强大的网络入侵能力？

2026 年 2 月，我看到马斯克预测到年底 AI 就可以绕过编译过程直接创建二进制文件。当时我做了一些实验，发现虽然 AI 还不能创建完整可运行的程序，但已经可以生成正确的机器码片段了。到了 9 月，我再次实验，发现此时 AI 已经可以用直接创建二进制文件的形式输出不太复杂的程序了。

但用直接输出二进制文件的方式去写大型程序显然不是好的选择，即使能写出来，也难以维护。那么，是不是可以让 AI 重演现代编译器的诞生过程？就像重演从核糖核酸到哺乳动物的生物演化史？

下面这个视频里超级马里奥游戏就是从核糖核酸开始构建的。

AI 先是通过直接输出二进制的方式构建了一个 3584 字节的机器码装配器 A0。然后用 A0 生产了一个更类似汇编器的工具 A1。又用 AI 生产了最基础的 C 编译器 C0。再一步一步迭代，最终演化出了一个完整支持 C89 标准并部分支持 C99 标准的编译器。有了这个编译器，就可以写出超级马里奥游戏，或者是任何网络攻击程序。

对 AI 说：“要有光”，然后整个世界就一步一步诞生了。所以我把这个项目命名为 BitKindle。感兴趣可以测试一下：https://github.com/tombkeeper/BitKindle

03｜RAG 被长上下文和 Agent 吸收

来源（X） · @kafkaup · 2026-10-20 22:31

去年人人都在搭的知识库，为什么今年不火了？

去年，“企业知识库”是 AI 落地阻力最小的一个项目，各家都在搭建自己的知识库，米哈游、银行、政企机构都在做。但到了今年，这个词突然没人喊了。

这是怎么回事？ RAG 凉了吗？

RAG 没死，但它被拆分并吸收进了现在模型的各个环节：

1. 长上下文的挤压：
上下文把很多中小型知识库整个吞掉了。去年 128k 上下文还是个奢侈品，但今年所有主流通用模型里，1M 上下文已经成了标配。几十万字的中型知识库，现在可以直接整本塞进上下文中，不用检索、不用调分、不用抗索引。

这样一来，RAG 的价值区间被压缩成了两类：一是大到装不下的知识库，二是需要极其精准命中的知识库。

2. Agent 架构的吸纳：
今年流行 Agent（Agent = Model + Harness）。在今年的 Agent 化趋势下，RAG 已经降级成了 Agent 的一个工具，或者说记忆检索插件。该不该搜，由 Agent 自己来决定。比如阿里的 Qoder，或者 DeepSeek 的 Harness，记忆检索与知识检索本来就是众多插件中的一个，在架构上被天然吸纳了。因此在独立叙事上，RAG 天然就熄火了。

今年还有一个新词：持续学习与 AI 的自我进化。

这就是所谓的新叙事，也是新的投资方向：知识到底应该存在哪里？以前我们的知识都是写在知识库里，而现在 know-how 类的知识，很可能会直接写进权重里。

这方面的代表就是 SSI 那一套 TTT（Test-Time Training）快速权重机制：每次使用时都会快速更新自我权重，不用检索，也不用塞上下文。这种自我进化的新叙事，比单纯的 RAG 吸引力大太多了。我自己也搭建过知识库，对此深有体会。

04｜BeatDesign 接入 MCP 剪辑

来源（X） · @ai_suxiaole · 2026-10-21 19:38

用 Claude Code 剪视频，终于可以可视化操作了！

之前分享过用代码控制视频时间线的方案，但光靠代码调整画面、字幕和素材，还是不够直观。

GitHub 上有个开源项目 BeatDesign，把 AI Agent 和可视化视频剪辑结合到了一起。

1、无限画布，直接拖入图片、视频、音频，连接节点组织素材。

2、可视化时间线，裁剪片段、调整字幕、混合音频，实时预览并导出 MP4。

3、支持 MCP，可以让 Claude Code、Codex 直接操作项目。

4、Agent 修改的内容，会显示在浏览器里，哪里不满意就手动调整。

本地部署也简单，准备 Node.js 22+、pnpm 10+ 和新版 Chrome。

进入项目目录后运行：

```bash
pnpm install
pnpm db:push
pnpm dev
```

浏览器打开 http://127.0.0.1:3020 就能使用。

如果要同时启动 MCP 服务，把 `pnpm dev` 换成 `pnpm dev:agent`，再按文档接入 Claude Code 或 Codex。

本地导入素材、剪辑、预览、导出都不需要 API Key，调用远程 AI 模型生成素材则需要自己配置。

经常用 AI 制作短视频的朋友，这套方案可以把 AI 自动剪辑和人工调整结合起来。

GitHub：https://github.com/BeatAPI/BeatDesign

07｜Eka 用 VFA 力控模型做灵巧操作

来源（X） · @alacheng · 2026-10-21 18:30

前Google DeepMind研究员创办强化学习和机器人公司，专注于解决机器人领域最难的问题之一：灵巧操作（dexterous manipulation），刚刚融资1.5亿美元，估值达14.5亿美元。其中创始人Tuomas Haarnoja之一是著名的强化学习算法Soft Actor-Critic（SAC）的主要发明人。

相比其他世界模型，两位创始人强调其技术特点是“力（force）是操作的母语”，而不是单纯依赖视觉或模仿人类演示。

核心技术：Vision-Force-Action（VFA）模型
与当前主流的Vision-Language-Action（VLA）模型不同，Eka的VFA将视觉与力反馈（来自定制的力敏感夹爪）结合，作为控制回路的一部分。机器人能“感觉”到物体是否滑动、接触阻力如何，并实时调整抓取力度和动作。

训练方式是大规模仿真 + 强化学习（类似AlphaZero的路径），在仿真中快速生成成千上万小时的经验，再迁移到现实（sim-to-real）。

目标是打破“通用性 vs 性能”的传统权衡：既要能处理未见过的物体和任务，又要达到工业级速度与可靠性。创始人多次提到，力控是解决“最后一毫米”问题的关键（纯视觉往往不够）

团队：
Pulkit Agrawal（@pulkitology）：MIT电气工程与计算机科学副教授，Improbable AI Lab负责人。UC Berkeley博士（与Haarnoja在研究生时期相识），此前联合创办SafelyYou（跌倒预防技术）。

研究重点是机器人学习、仿真到现实（sim-to-real）、自我监督学习与力控操作。

Tuomas Haarnoja（@haarnoja）：前Google DeepMind研究员，Soft Actor-Critic（SAC）算法的主要发明者。SAC是过去十年最具影响力的强化学习算法之一，以最大熵框架著称，在连续控制和真实机器人任务中表现稳定高效。他也是UC Berkeley博士。

08｜只测用户可感知行为，少写单元测试

来源（X） · @intentplex · 2026-10-21 05:44

我们之前招的10年经验DevOps，也会自动化测试。花了2个月，给我们公司一个只有二十多万行的webapp产品，生成了5000多个单元测试。只查出来几不痛不痒的bug。
因为单元测试依赖于实现，每次开发们改代码，都要花几十分钟，删除老的单元测试，重新生成新的单元测试，怨声载道。
这个DevOps离职以后，我不让老板再招人，我自己接手这个自动化测试。我定了一个原则，测试用例只测用户能感知到的东西，绝对不基于任何内部实现写测试。我还写了一个通用测试技能，只让GPT生成150个测试用例，就抓到了15个bug。
我的结论是：一般的产品不要再写单元测试。多人长时间vibe coding出来的东西，可能核心功能能用，但是用户可见的边边角角的bug率非常高，如果没有专门的工作流去测试，很难发现。

10｜PINOC 用三视图生成 3D 骨骼角色

来源（X） · @Pluvio9yte · 2026-10-21 17:08

前几天看了赛克（@Saccc_c）用 Opus 5.5 做《小王子》的教程，我尝试把陶渊明的《桃花源记》做成一个明亮的第三人称探险小游戏，Opus 5.5 加 3D 模型确实能够做出可玩的游戏了

用到的工具：Claude Code（Opus 5.5）、@ViggleAI 的 PINOC（JST-2），再加一个网页 3D 引擎。

大体是这么做的👇

① 先写策划
五幕直接对着原文：缘溪行 → 忽逢桃花林 → 山有小口，仿佛若有光 → 豁然开朗，桃源村 → 处处志之，不复得路。

② 再出概念图
用 AI 出全景设定、关键画面和角色三视图，这里我用的是 Codex 内置的生图功能。画面参考《小王子》的明亮感，人物参考《风之旅人》《光·遇》：渔郎戴竹斗笠、披稻草蓑衣，再加一条桃红色的长围巾。

③ 角色交给 PINOC
渔郎、老翁、小孩，把正、侧、背三视图丢进 PINOC，出来就是自带骨骼的 3D 高斯泼溅角色。
走、跑、挥手、点头直接从动作库里拿；坐下吃饭、作揖、小孩蹦跳这些用文字生成。
PINOC MCP 接进 Claude Code 之后，这些都是 Claude 自己去调。

④ 搭场景
远处的桃花山谷用 PINOC 的场景生成。近处的小溪、小路、桃树，还有几万簇随风摆动的草、雏菊、薰衣草、蕨类，都是 Claude 写程序搭出来的。

⑤ 对标迭代（最关键的一步）
学赛克的做法：固定几个机位，每改一轮就截图，和《小王子》并排对比，看差在哪，再改下一轮。光溪畔桃林这一个小场景就迭代了八轮，从一开始的"塑料感"改到现在这样。

最大的感受：一个人加上 Claude 和 PINOC，一天就能做出一个明亮、能玩的小世界
