05｜K2 Horizon 开源训练全流程

来源（X） · @alacheng · 2026-11-22 20:05

K2 Horizon （华人团队为主）发布的LLM训练技术报告，主要特色在于极致透明度和系统化的训练细节披露，远超多数开源LLM报告。它遵循LLM360标准，把“怎么做出来的”完整公开，而非只给最终权重。

-极致开放性与可复现性：发布全部训练历史（380个中间检查点、覆盖各阶段）、21.6TB预训练数据、58次训练运行日志、17个代码仓库（含生产级xLLM框架、RL360强化学习栈、Eval360评估等）。不仅给数据，还详细公开生成约10T合成token的完整管道与决策过程，这是多数开源报告最回避的部分。

-架构与推理创新：提出Mixture-of-Value Attention（MoVA，将MoE应用于注意力值投影）和softplus注意力门控，用于增强推理。

-其中有个技术比较有特色，在后训练阶段采用了论文 ISO: An RLVR-Native Optimization Stack里的方法。把同一基础模型上训练出的多个 RL 专家（specialists）在固定谱的帧坐标下合并。无需后合并数据、rollout、梯度或蒸馏，效果优于 Task Arithmetic、TIES、RAM 等常见无数据合并方法。https://iso-rlvr.github.io/

06｜LoopX v2.4 结构化任务语义

来源（X） · @huangruiteng · 2026-11-21 20:51

正式向大家汇报一下 LoopX 从 1.x 到 v2.4 的大版本跨越——自 1.0 以来全仓走过 4,100+ 个合入 PR，10 月切入 2.0 架构后一直埋头打磨没正式官宣。今天借社区 @lemomo_ai 做的这支 3D 无穷轨道短片，把从 1.x 到 2.4 的三件核心进化一起交个卷：

1. 从 1.x 自由脚本/笔记到 2.0 结构化通用任务语义：不再靠易漂移的 Markdown 或纯机械队列硬撑，抽象出领域无关的 Goal / Acceptance / Todo / Claim & Lease / Gate / Evidence 状态协议，落进 TypeScript + SQLite / 自托管 PostgreSQL 原子事务底座（含默认拒绝 ACL），跨 Codex、Claude Code、Gemini、DeepSeek 中立混编。

2. 同周期 3.0% 首读差分与 18h 真长程标尺：把同压缩周期续跑的首读上下文压到原包 3.0%（失配自动回退完整快照）；针对 10h 后模型爱改局部测试“刷分”的通病，引入同父反事实标尺（Yardstick）与证据驱动步幅（Stride v2），在 LHTB（46 题 +17.3%）和 EdgeBench 18h（ANN 7,159 QPS 等）跑出扎实对照，并在 HuggingFace 开源了 68 个检查点。

3. 走向 v2.4 与 22 位社区开发者共创：我现在家里一台 Mac 常驻挂着十来个 7×24h agent（主控轨迹刚过 11.15 GB / 3,598 turns），配合社区近期共建的一句话建 Goal、LooChat 多 CLI 工作台与飞书管家门禁，出门手机点一下就能放行。日常英文进展与每周「开源场景 Loop」也会同步更在官号 @LoopXAgent 👇
