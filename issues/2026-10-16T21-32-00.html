01｜Claude Code 三模型分工降本

来源（X） · @laobaishare · 2026-10-16 17:13

这可是真干货

Anthropic 刚分享了 Claude Code 的一个超好用技巧。

思路是：同时用 Sonnet、Haiku 和 Opus 5.5，各干各最擅长的事。

效果更好，token 还省很多，因为每个任务都交给了合适的模型。

只要这样启动 Claude Code：

claude --advisor opus --subagents haiku

逻辑是这样的：

→ Sonnet 5.5 负责主持会话、写代码
→ Haiku 5.5 并行去翻文件和文档
→ Opus 5.5 当顾问，只管重要决策
→ 不需要 Opus 的任务就不占用它的上下文

只有要审计划、卡在反复报错上，或者收尾前想确认没漏东西时，才叫 Opus 出场。

Sonnet 干活，Haiku 探路，Opus 把关。

03｜magpie 精简系统提示词省token

来源（X） · @yetone · 2026-10-17 03:34

magpie 的 Claude 订阅为什么更费 token？这次改了什么、省了多少：

以前：magpie 用真的 Claude Code 跑你的请求。每个请求都带着 Claude Code 自己的系统提示词，你 agent 的指令只能塞进第一条用户消息里。等于每次请求都多付一份 Claude Code 的提示词，约 1K token。

现在：设置里新增「精简 Claude 系统提示词」开关（默认关）。打开后，Claude Code 启动时用 --system-prompt-file 把你 agent 自己的指令作为系统提示词，替换掉 Claude Code 那一份，第一条消息只剩对话本身。

真实订阅实测（Sonnet 5.5）：
· 每个请求固定省约 0.9–1.2K token
· 轻量聊天客户端，3 轮：输入 10,048 → 6,580 token（−35%）
· claude -p 这种自带大提示词的客户端，4 个请求：85.4K → 81.9K（−4%）

客户端自己的提示词越小，省得越多。注意：发请求的仍是真的 Claude Code，但不再带它自己的提示词，看起来没那么像 Claude Code 本身，账号风险请自己权衡。下个版本发布。

04｜MAI-Base-2 预训练2.8T参数

来源（X） · @Kay2289123 · 2026-10-17 01:23

微软这篇讲 3T 级模型预训练的技术博客，真的值得认真看，很少有人愿意把这么大的模型到底怎么训，讲得这么细、这么清楚。链接我放在后面

这次的模型叫 MAI-Base-2，由微软 MAI 团队自主训练，总参数 2.8T，每个 token 激活 80B。目前完成了预训练，后训练还在进行

几个我觉得值得分享的点
> 参数很多，每次只用一小部分。 总共 2.8 万亿参数，处理每个 token 时激活约 800 亿。这就是 MoE，按需要调用不同的“专家”，控制计算量。

> 先用小模型探路，再放大。 他们先训练一系列小模型，推算大模型的结果。连数据重复学几遍，都要和正式训练对齐。最后实际的训练误差和提前预测的非常接近，这个我觉得很厉害。

> 怎么调参，也摸出了规律。 比如学习率，可以理解成模型每次更新参数时迈多大一步。他们根据训练量、训练步数去推算，再到更大的模型上验证，减少正式训练时的试错

> 模型越大，训练稳定性越重要。 这次用了 Muon 优化器，还加了激活梯度裁剪，减少异常更新的干扰。后面这项改动很有意思，模型越大，带来的效率收益反而越明显。

> 从预训练就开始学图像。 总训练量是 50T token，其中约 9T 来自多模态数据，是原生多模态模型。
