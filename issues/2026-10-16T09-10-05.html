02｜pstack把工程原则压缩成短指令

来源（X） · @shao__meng · 2026-10-16 14:11

pstack 作者公开她的 “工程原则” 设计思路

「Clean Code」作者 Uncle Bob 是传统软件工程方法论的宗师，他最近看到了 pstack，认为本质上是把经典工程智慧「最小改动、先删后加、验证根因、用类型系统让非法状态不可表示、幂等操作」重新编码给 AI Agent 使用。

pstack 作者 @poteto 回应并公开了这个 Cursor 官方内置插件的工程原则的设计思路，核心是：随着模型能力提升，写给智能体的指令正在从“冗长的操作步骤”压缩为“简短的命名原则”。

# 几个关键信息点

1. 原则即极简 skill。pstack 的每条工程原则只有约 10–20 行，是一段被提炼、命名过的好实践，而不是一个流程脚本。她预期随着模型变强，pstack 里大部分 skill 最终都会被压缩成这样的短原则或工作流，从而可以删掉一批。

2. /poteto-mode 的运行机制。智能体在开始多步任务前先读一份简短的原则索引；执行过程中，必须“点名每一条影响了决策的原则，以及它具体改变了哪个选择”，并在回复末尾生成一个 "Principles Named or Used" 段落。这个设计很巧妙：如果原则被引用却没有对应的实际决策，就说明智能体只是在“报菜名”而没有真正应用；强制原则与决策挂钩，让推理过程可检验。

3. 原则来自真实纠错。这些原则大多来自她今年在会话中亲自纠正智能体的场景，属于“教训的结构化沉淀”。

4. 原则可被唤起。每条原则都能以 /principle-<名称> 的形式作为 skill 调用；更常用法是用名字来“掌舵”；因为名字背后指向智能体已经读过的完整规则，一个短语比一段指令更能精准地重定向工作。比如对着一堆旧适配器说 "subtract before you add"，智能体就知道先删过时的、再设计剩下的。

04｜OptMem用426 token提示词实现长期记忆

来源（X） · @kafkaup · 2026-10-16 16:57

这是我最近看到把 agent 记忆做得最省的一个方案：整套集成就是 426 个 token 的提示词，加一个无依赖的 Python 单文件。

OptMem 的定位很明确——让记忆活得比会话更久。原话是它能熬过每一次 compaction、每一次换模型和换厂商，而没有它，agent 不知道自己是谁，也不知道什么已经决定过、试过。

▸ 装：跑一行 curl 脚本，它会打印一个 Memory 段，粘到 AGENTS.md 或 CLAUDE.md 顶部就完事，再跑一次就是更新。

▸ 记：memo note 写一条，一行、上限 280 字节。memo wake 是每个 session 的第一个命令。

▸ 找：memo recall 对全部记忆做逐词搜索；记忆同时组成一棵二分树，#0-1、#2-3 这样的摘要节点可以用 memo zoom 展开到原始条目。

▸ 存：LOG.txt 只追加、永不改写，TREE 目录里的摘要只是缓存，随时能从日志重建；摘要坏了用 memo forget 丢掉，下次 nap 会重算。

▸ 快：记录定长，位置即身份，每次查找一次 seek。百万条记忆占 608MB，wake 仍是 0.03 秒。

▸ 挪：设 MEMORY_DIR 就能把 memory 目录放进同步盘或 git 仓库。

设计上有两点我觉得值得留意：没有任何后台进程，压缩合并是跟在 note 的输出里一条条送过来的，由 agent 顺手做掉；以及它明确要求 subagent 不要碰 memo，因为子代理判断不了什么已经记过，写进去就是重复。

适合已经在长期用一个 coding agent、受够了每次开窗重新交代背景的人。不适合想要开箱即用图形界面的——它全部交互都在命令行和提示词里，且依赖模型老实执行那几条 mandatory 指令。
