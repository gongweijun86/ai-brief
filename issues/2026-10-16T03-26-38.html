02｜特斯拉Roadster用压缩空气喷气腾空

来源（X） · @dotey · 2026-10-16 10:22

特斯拉新 Roadster 发布：靠压缩空气喷气在空中翻正落地，马斯克说 2028 年投产，售价未公布

10 月 15 日晚，特斯拉在得州 SpaceX 的 McGregor 试验场直播发布了第二代 Roadster 跑车。这辆车 2017 年就亮过相，当时说 2020 年交付，之后一推再推，拖了将近九年。

演示里，车开上一段弯曲的大坡道，倒挂着往上跑，然后从坡道尽头冲出去，在空中把车身转回正面，四个轮子落地。之后它又从一排特斯拉车（包括 Semi 电动卡车）上方翻跳过去。马斯克在现场说：“飞行汽车是真的。”

它靠的是冷气推进器。原理跟吹满的气球一松手就乱窜差不多：碳纤维高压罐里存着压缩空气，从喷口猛地放出去就产生推力，不烧燃料，也没有火焰。特斯拉说推进器的推力是轮胎抓地力上限的四五倍，所以它起步能比只靠轮子快得多。倒挂不掉下来靠的是另一套系统：风扇把车底的空气往外抽，把车吸在坡面上。

所以这里的“飞”只是几秒钟的喷气跳跃，气放完就没了，离能载人飞一段路的飞行汽车还远。据科技媒体 Glitchwire 报道，演示车把后排座位换成了一个装 260 公斤压缩空气的高压罐，车身四周有 10 个喷口；The Information 此前报道，因为推力和噪音太大，演示车是远程遥控的。这几点特斯拉官方没有确认。

翻跟头的是最激进的 Rocket 版：单座，只接受邀请购买，不能上公路。零到 60 英里/小时（约 97 公里/小时）加速不到 0.59 秒，极速超过 370 公里/小时。

普通人能订的是另外两个双座版本。Performance 版没有推进器，靠主动空气动力学和风扇吸地增加抓地力，加速不到 1.6 秒，订金 5 万美元。Thrust 版在车尾加了推进器，加速不到 0.9 秒，限量发售，订金 25 万美元。三个版本续航都超过 480 公里。

特斯拉没公布售价，订金不等于车价，2017 年说的起步价是 20 万美元。Performance 版的 5 万美元订金分两次付：先付 5000 美元（特斯拉说可全额退），10 天内再补 4.5 万美元，否则订单取消。

投产时间是马斯克在现场说的 2028 年，特斯拉官方帖子里没有写日期。这辆车的交付时间此前已从 2020 年先后推到 2021、2022、2025 和 2027 年。

03｜Grok Bot搭建多模型自动化开发流

来源（X） · @vikingmute · 2026-10-15 21:24

最近把技术开发基本都挪到 Grok Bot 上了，分享一下现在的工作流：

1 一个产品一个 bot 每个项目各有专属 bot，记自己的 repo 测试规则和上下文，不搞写作 设计 review 测试拆一堆

2 写代码不用 Cursor cloud agent，慢没必要，直接在 bot 电脑上跑 Cursor CLI，我是老的 plan，bot 和 grok model 和 other models 是分开算的，还有 Codex CLI 作为辅助。

3 按任务换模型，安装到了全局 skill 当中

代码：
规划大任务用 Opus 5.5
写具体实现用 Grok 4.7
review 用 Sol 6.1

文案/文档：
用 Gemini 3.8

设计：
定首页方向大设计用 Opus 5.5
日常改设计用 Sonnet 5.5
设计落代码再回 Grok
产品更新视频用 Opus 5.5

这样按照 Cursor 三种不同的额度可以比较平均的分配

4 Bot 负责协调拆任务 盯 CLI 看 diff、跑项目测试（TinyShip 现在每次改完都跑全量的 E2E + smoke），最后给我总结。代码基本不看了，靠其他模型 review，大改动我会用 review-forge 选两个模型分别看，验收全靠全量 E2E。

5 自动化任务包括：
* 扫描 Issue 并且提出方案
* 周计划可以全自动定时跑，现在需求都是 AI 替我想的，保证产品持续迭代，每周至少都会上 2-3 个点，所以最近项目升级都很频繁

现在感觉整个流程非常舒服，挺喜欢 Grok Bot 的，觉得是现在做的最好的，可惜就是 Linux 主机，做网站最好，对于一些Mac 的原生应用就没法测试了。

05｜SPACE沙箱开源108次测试零逃逸

来源（X） · @ScarletKc · 2026-10-16 02:05

Perplexity 把 Computer 背后的沙箱平台 SPACE 开源了，Apache 2.0。我觉得这对写 agent harness 的人意义挺大。harness 里最难自己做好的，就是给 agent 跑代码的环境，现在可以直接把 Perplexity 线上在用的那套拿来自己部署。

以前要么接 E2B 这类商业沙箱，要么拿 Docker 自己凑合，隔离、状态恢复、密钥管理都得自己扛。SPACE 现在跑着 Computer 的全部会话，每天创建几百万个沙箱。

每个沙箱是一个 Firecracker microVM，有自己的内核。他们拿 Opus 5.0、GPT-5.6 Sol、Kimi K3 这些模型专门去尝试逃逸。agent 在 guest 里有 root，有的还给了源码和网络，108 次没有一次逃到宿主机。网络限制倒是被绕过了 11 次。一种是在 guest 里伪造 DNS 响应，另一种是借 CDN 的共享 IP 访问被禁的服务。两个洞都补了，复测没再成功。

Opus 其实也想到了共享 IP 这条路。但任务说明要求不碰其他外部系统，它觉得借第三方服务绕过去违反了约束，就没试。它最后是靠伪造 DNS 绕过去的。

他们还用同样的方法测了另外 10 家沙箱平台，8 家都能绕过网络限制。有的已经修了，E2B 还在处理，Modal 和 Vercel 认为这是已知限制。VM 逃不出去和网络关得住是两回事，自己配个 egress allowlist 不一定真拦得住 agent。

SPACE 的凭证也不进沙箱。key 放在外面的 credential store，在网络层注入，出站流量全部过 gateway 按策略放行。agent 就算中了 prompt injection，沙箱里也读不到 key。

suspend 会把内存、进程和文件系统一起做成快照，之后换个节点也能恢复。agent 停下来等人确认，回来可以接着跑。长任务中途崩了，也能从最近的 checkpoint 接上，不用从头重建环境。

还支持回滚和 fork。agent 跑了破坏性命令可以直接退回去，也可以复制出两份工作区，让它分别试两种方案。

它还带了一个 E2B 兼容层。用 E2B Python SDK 写的 harness，客户端改下 domain 和 API key，就能切到自己部署的 SPACE。

门槛是要 Linux x86_64 加 KVM，官方教程走 Kubernetes。Mac 上跑不了，没有 /dev/kvm 的 VPS 也不行。

07｜OpenUI 1.0让模型直接生成界面

来源（X） · @tvytlx · 2026-10-16 08:57

三十年来，软件一直在做一件事：把信息变成好用的界面。
结果我们造出了史上最聪明的软件，又退回到了一个输入框。

这是 OpenUI 创始人的一句话，我觉得挺扎心的。

现在大部分 AI 应用都是这个路数：
agent 吭哧吭哧查了半天资料，
最后甩给你一大坨文字。

ChatGPT 的 Intelligent UI 已经能在回答里直接长出图表、表单、看板。
问题是，这玩意只能在 ChatGPT 里面用。

OpenUI 1.0 今天发布，就是把这个能力开放给所有人：
在你自己的产品里，用你自己的组件，让模型直接生成图表、表单、dashboard。
不绑定模型，完全开源。
半年前开源的版本，已经有 1 万多 star、600 多万下载。

我觉得聊天框可能只是 AI 应用的过渡形态。
模型会越来越像，大家接的都是同几家。
最后能拉开差距的，是答案以什么样子出现在用户面前。

同样一份调研，
一屏文字，你得自己读、自己提炼；
一张能点的图表，三秒就知道下一步该干嘛。

当然也有边界。
简单问答、写东西，文字本身就是最好的界面。
要比较、筛选、填信息的场景，生成式 UI 才真的有用。

做了这么多年软件，看着整个行业花两年把 UI 重新发明一遍，
感觉兜了一大圈又回来了。
我那几本落灰的前端书，好像可以翻出来了。
