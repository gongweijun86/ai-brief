03｜DeepSeek dsh 插件与事件溯源

来源（X） · @jakevin7 · 2026-11-05 14:23

深度研究了下 DeepSeek Harness 的开发经验和演进，有很多技巧值得Infra的项目学习。
在调研Raft里支持dsh，对agent的调研了下，于是做了一些手工的挑选和打磨来分享下

让A经特总结了好多个工程经验，里面很值得学习的几个点
●AI Agent 作为一等公民，开发过程重度依赖 Git Worktree 并行并发；沉淀的 2,692 篇 .agents/notes 成为 Agent 的永久记忆。
●实验先行+验证后收编：新特性均先以 experimental-* 插件存在，经多轮迭代成熟后才收编为内置能力。这里面很有趣的一点是系统还做了功能外拆，0.2.0的时候，自动化任务从内置包降级为插件包，

架构精髓：
●插件三大支柱：Service 注入、Typed Events（强类型事件通信）、Reversible Effects（插件卸载时生命周期与注册项自动撤销回滚）。这里面有很多关于 编程语言 相关的设计与理论，非常有学习价值， @pocket_js 我记得也有很多类似相关的设计。
●Seam / Implementation 双层解耦，可以降低复杂度和方便项目维护：任何能力均拆解为 抽象（Seam） 与 实现（Implementation）。例如 dsh-fs（抽象）对应 fs-local 与 fs-sandbox。换实现无需改动任何调用方。
●Profile / Bundle / Patch 系统：单一启动器可通过 Profile 加载不同 Bundle；配合 cordis.patch.yml 与 dsh --dump-config，用户与 AI Agent 可直接按配置行精准 Patch 任何插件行为。
●会话事件溯源与不可逆单向迁移：会话不存snapshot，全为 append-only 的 SessionEvent。这一块理论很类似于数据库存储或者是OS里面的设计。
格式升级独立拆包（v0-to-v1 至 v3-to-v4），旧版本代际提交后冻结不回写覆盖，从架构保证数据0丢失。

04｜OpenAI 收购 Pierre 审查代码

来源（X） · @dotey · 2026-11-04 23:59

OpenAI 宣布收购 Pierre，给 Codex 补上“看代码、审代码”的工具

OpenAI 宣布将收购开发者工具公司 Pierre Computer Company（下称 Pierre）。如果你在 Codex App 里浏览过项目文件、看过代码改动，你用的就是 Pierre 做的两个开源组件。收购金额官方没说。

先补一点背景。Codex 是 OpenAI 的编程智能体，也就是能自己写代码、改代码的 AI 助手。程序员管理代码普遍用 Git，它会记下每一次改动，谁在什么时候改了哪一行都能查到。代码合进正式版本前，通常要有人审一遍：对着改动前后的差异逐行检查，有没有写错、有没有隐患。

Pierre 做的就是这一块。它的开源组件 Trees 用来在项目里快速翻找文件，Diffs 用来展示改了哪些地方，两者在代码量很大时也能保持流畅。Diffs 还有个编辑模式，审代码的人看到问题可以当场改那一行，不用切回编辑器。

Pierre 最近还发布了语法高亮工具 Highlights，AI 一边往外输出代码，高亮一边跟着更新。另外它有一项服务叫 Code Storage，让其他 App 能用 Git 的方式存代码、记录修改历史。

OpenAI 为什么要买它？AI 写代码越来越快，还能同时开好几路任务，人要审的改动量跟着暴涨，看代码、审代码成了新的瓶颈。

OpenAI 这周早些时候刚公开了内部自研的代码管理后台 Pando，供工程师和 AI 智能体一起使用。OpenAI 说，收购 Pierre 是想把从 AI 新建第一个分支（在代码副本上单独修改，改好再合并回去）到代码正式上线的整条流程，都放进 Codex 里完成。

对现有用户的影响：Pierre 的开源项目会继续开源，OpenAI 表示会继续参与贡献。Code Storage 的客户在收购完成后可以接着用，OpenAI 会逐步把它的功能并入 Codex；这项服务之后会单独保留多久，官方没说。

这笔交易还要等监管审批等常规条件，完成前两家仍是独立公司。
