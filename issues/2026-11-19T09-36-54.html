02｜Karpathy:小模型配闭环才是关键

来源（X） · @hhp121222 · 2026-11-19 14:37

Karpathy 开炮了。

这位前 OpenAI 联合创始人、前特斯拉 AI 负责人，在一段 16 分钟的对谈里，把当下 Agent 热潮的底裤扒了个干净。

他说得很直接：Agent 的本质就是大规模蒸馏。你花大价钱跑的那个大模型，99.99% 的容量都浪费在了它压根用不上的数据上。听起来刺耳，但你仔细想想，事实就是这样。

然后他给出了一条真正能跑通的技术路线：先用大模型把能力蒸馏到小模型里，再给小模型配上正确的工具，最后用一个闭环把整个系统串起来。小模型、正确的工具、一个闭环，三件事，够了。

这里面最关键的一环，是闭环。

小模型本身并不可怕，可怕的是它一旦接入闭环，就能自我校正、自我改进，越跑越强。模型的参数量可以小，但只要反馈回路搭对了，它就能长出远超参数规模的实战能力。

所以别再为更大的模型交税了。真正让一个 Agent 变得危险的，从来都不是参数量，是闭环。

这 16 分钟的信息密度，比今年市面上任何一门 500 美元的 AI 课都高。看完之后，再去读那篇 Harness, Loops, Graphs，你就会明白：闭环就是那副马具，套上了，小模型才能真正跑起来。

03｜ffmpeg-skill 助手本地剪视频

来源（X） · @dapeng667 · 2026-11-19 16:35

你让 Codex 把访谈剪成 60 秒竖屏，它拍脑袋写一串 FFmpeg 命令，帧率编错、时长对不上，还跟你说已经做好了。

kajisho5/ffmpeg-skill，约 8095 星，日增约 338。一句话：在自己电脑上给 Codex 这类助手装一套本地 FFmpeg 工具，切开、裁竖屏、加字幕、导出短视频，它会先探测再验收，不用上传，也不另外买转码接口。

以前要么自己死磕 FFmpeg 参数，要么把原片丢进在线转码网站，排队又按分钟付钱。现在本机先装好 FFmpeg。Ubuntu 或 Debian 可以运行 sudo apt install ffmpeg，Windows 用 winget install Gyan.FFmpeg，macOS 要用 brew install ffmpeg-full，普通的 ffmpeg 配方缺字幕和缩放这些滤镜。然后运行 npx ffmpeg-skill --codex，会装到 ~/.agents/skills/ffmpeg-skill。如果要用 Claude Code，运行 npx ffmpeg-skill 即可；Cursor 加 --cursor，三个一起装就加 --all。装完先跑 npx ffmpeg-skill doctor，确认 ffmpeg、ffprobe 和要用的组件都在。

之后直接跟助手说：把 interview.mp4 里 0:45 到 1:20 和 5:00 到 5:25 留下来，做成 60 秒的 Reel。它会按探测、剪切、裁成 9:16、导出、检查这条链路走完，再把成片的时长、分辨率和帧率告诉你。不想经过助手，也可以自己在终端运行 python3 ~/.agents/skills/ffmpeg-skill/scripts/probe.py input.mp4 --compact，或 python3 ~/.agents/skills/ffmpeg-skill/scripts/export.py input.mp4 --preset reels --json。

能干嘛：
- 把横屏访谈裁成 9:16，按 Reels、TikTok、Shorts、YouTube 这些模板导出
- 按时间段切开、去掉静音、把响度压到平台要求
- 在本机从语音生成字幕，做成逐词高亮，音轨不用上传
- 一份素材一次渲染出多个平台的成片，并检查是否合格

剪视频不一定要再买一家云转码。本地已经有 FFmpeg 了，缺的是一套助手用得懂、还会自己核对成片的工具。提醒一句：本机要先装好 FFmpeg；从语音出字幕需要另外安装 faster-whisper 这类本地引擎，不装的话其他剪辑功能还能用。开源许可是 MIT。需要 Node 16 或更高版本才能用 npx 安装。

https://github.com/kajisho5/ffmpeg-skill

05｜Anthropic 六层 harness

来源（X） · @thedelost · 2026-11-19 06:37

中文译文

这篇 harness 论文简直他*的金矿

Anthropic 的工程师们详细说明了是什么真正让 Claude Code 表现得如此出色。剧透：不是模型。

秘密在于：harness。这就是全部差距所在。

prompt engineering → context engineering → harness engineering。

harness 的 6 层：

第 1 层 → 工具

更少的工具，每个只做一件事。
每个错误都会告诉 agent 下一步该尝试什么。

第 2 层 → 上下文

简短的 claude-md → 按需加载文件 → 填满时进行压缩。

第 3 层 → 权限

读取 + 测试 → 自动执行。
部署 + 删除 → 询问人类。
所有操作 → 沙箱。

第 4 层 → hooks

工具运行前 → 拦截密钥和受保护的文件。
每次编辑后 → 格式化、lint、类型检查。没有例外。

第 5 层 → 验证

新的审查者阅读 diff，而不是摘要 → 运行测试 → 失败？修复 → 重新运行。

第 6 层 → 评估

每次 harness 变更都被评分 → 成功率、token 数、轮数 → 保留获胜的那一个。

模型是引擎。harness 是整辆车。

他们甚至把全部 6 层打包成了一个 prompt。粘贴到 Claude Code 里，它就会为你设计 harness。

6 层。1 个 prompt。0 个无限循环。

layer 3 → permissions

reads + tests → auto.

before a tool runs → block secrets and protected files.
after every edit → format, lint, typecheck. no exceptions.

layer 5 → verification

fresh reviewer reads the diff, not the summary → runs the tests → fail? fix → rerun.

layer 6 → evals

every harness change scored → success, tokens, turns → keep what wins.

the model is the engine. the harness is the whole car.

they even packed all 6 layers into one prompt. paste it into Claude Code and it engineers the harness for you.

6 layers. 1 prompt. 0 infinite loops.
