01｜Magpie用MCP路由实现工具懒加载

来源（X） · @yetone · 2026-11-18 11:32

推荐大家用一下 Magpie 自带的 MCP 路由功能，不仅方便管理海量的 MCP servers，而且完美支持海量 MCP 工具的懒加载和智能编排调用

引用内容

Jeffrey.W @JeffreyCalm

DSH 用了快一个月，有一个问题一直非常头疼，就是它不支持 MCP 懒加载。

直观体验就是，如果你用社区插件连个 Notion 或者是 Codegraph。一次会话里工具说明会吃掉 90K 的窗口上下文。

用 Deepseek 1M 模型会感受不到，但如果是桥接了 273K 的 Codex 订阅，就会导致非常频繁的压缩，根本干不了活儿。

实际上你真用 1M 模型也不是没影响，只是影响的是钱包不是体验，总之其他主流 Harness 现在都没有这么干的了。

我先在 DSH 社区里找了一圈，目前没有找到一个足够成熟、方便的通用方案，能让所有 MCP 工具都按需加载。因为到目前的 DSH 0.2.2-RC3 为止，deferred 机制在 DSH 主程序里还没生效。

针对单个 MCP 做优化也许可以，但我的需求是以后接入更多 MCP 时，都不用再为每个服务单独折腾一遍。

最后找到的办法是用 Magpie 做一层 MCP 网关，让 Magpie 负责管理和调用工具。DSH 平时不必把所有工具的完整说明都带上，需要时再查找、调用。

很多人对 Magpie 的认知就是把各种订阅、Key 那边的模型，桥接到本地不同的 Agent 里。但它其实还有很多其他功能，比如在中转的过程中注入 MCP 工具和技能。

然后在 MCP 这，Magpie 就支持把你所有接入的 MCP 都折叠起来，只暴露给 Agent 两个入口：

1. find_tools：先根据需要查找工具，获取相关工具的说明和参数。
2. call_tool：再通过 Magpie 调用找到的工具。

这样，模型需要查 Notion 时才去找 Notion 工具，而不是每次都带着全部工具定义出门。

怎么配置？以 Notion 为例。

我用的是同一台 Mac 上运行 Magpie 和 DSH，基本可以在界面里完成，不需要手改配置文件。

1. 在 Magpie 添加 Notion

打开 Magpie 的 资源库 → MCP，然后直接在 MCP 列表里搜索 Notion，添加。

2. 登录 Notion

在 Magpie 的 Notion MCP 配置页面，点击登录，跳转到 Notion 界面，在浏览器中选择工作区、确认授权，再回到 Magpie 检查登录状态。

3. 打开 MCP 路由和按需工具

在 MCP 页面打开 MCP 路由，确认按需提供工具已开启。再到 Notion 条目里确认勾选了通过 MCP 路由提供，而不是直连。

大功告成。

在 DSH 那边什么都不用操作，你选择一个经 Magpie 路由进来的模型，就自动生效了。

实测只有当你提到 Notion，或模型判断需要 Notion 的时候，Notion 的 MCP 才会被加载。

记得如果你之前在 DSH 里配置了 Notion 插件，要停用并删除，不然 Notion 的完整 MCP 说明还是会被注入到对话里。

其他家的 MCP 也是一样，都可以配置在 Magpie 上，无论配置多少，Magpie 默认都只暴露给 Agent 那两个用于查询工具的 MCP，极致省 Token。

02｜Kokoro发布账号被过期域名接管

来源（X） · @ChantoziQ · 2026-11-18 12:43

一个过期域名，竟然能威胁到下载量超过千万的 AI 模型！

研究人员发现，Hugging Face 上热门语音模型 Kokoro 的发布者账号存在安全隐患。

他们通过注册一个过期域名，接管了相关发布者账号。

更夸张的是，只用一块游戏显卡和 87 秒，就能修改模型权重，让模型说出与输入文字不同的内容。

整个过程甚至不需要修改代码，传统杀毒软件也未必能发现。

好在研究人员没有上传被篡改的模型。

这件事提醒我们：AI 模型能不能信任，不只取决于代码，还取决于它从哪里来、由谁发布。

03｜Vercel给Agent评测设陷阱任务

来源（X） · @Xudong07452910 · 2026-11-18 08:30

一个 Agent 什么都没做，Eval 却判它通过了

Vercel 给一个模拟咖啡下单 CLI 写了个陷阱任务。附近没有一家店满足用户的条件，正确做法是告诉用户买不到，而且不能下单。Codex 几乎每次都过了，翻 Trace 才发现，每 10 次通过里有 9 次它根本没搜索，直接就放弃了

问题出在 Verifier，它只检查了「没有下单」，没检查「先搜过再放弃」。不读 Trace 的话，这些都会被算成成功

这是 Vercel 新发的《Agents are users, so your software needs evals》，拿这个咖啡下单场景完整走了一遍怎么搭 Agent Eval

他们按调用 LLM 的次数，把 Agent 测试分成三层：确定性测试、单轮 Eval、跑完整任务的 E2E Eval。能用低层抓到的问题，就别放到高层去测

搭环境用的是 Harbor + Vercel Sandbox，让 Agent 在隔离环境里反复跑同一批任务，再结合 Verifier 打分和 Trace 去找失败的根因。另一个失败也挺典型，Codex 一直把 sfbeans 当成已连接的工具去找，从没试过在 shell 里直接运行

这篇实践性很强，从定目标、选指标到写任务、分析失败都讲到了，文末还附了一段可以直接丢给 Coding Agent 的搭建 Prompt

越来越多 Agent 会通过 API、CLI、MCP 来用软件，自己的产品能不能被 Agent 可靠地用好，值得认真测

没想到 Jason Wei 已经离开 Meta，去 AI 数据公司 Mercor 当首席科学家

美国时间 11 月 17 日，Mercor CEO Brendan Foody 宣布，Jason Wei 出任首席科学家，负责组建研究团队，主管数据和评测。Jason Wei 随后发帖确认：在 Meta TBD 实验室待了一年，“训练 AI 模型的公司比以往任何时候都多，数据会决定下一个前沿”。

Jason Wei 在 Google Brain 时是思维链论文的第一作者，让模型先写推理步骤再给答案，这个做法后来被广泛使用。之后他在 OpenAI 参与了 o1 和深度研究，2025 年 7 月被 Meta 重金挖走。

他另一个强项是给 AI“出题”。他主导的 SimpleQA 测模型会不会瞎编，BrowseComp 测 AI 能不能翻遍网页找到冷门答案，都成了各家发模型时常用的评测，他还参与了医生打分的 HealthBench。他在博客里写过一条“验证者法则”：一项任务越容易验证，就越容易训练 AI 学会。

Mercor 做的正是这门生意：平台上有 500 多万名医生、律师、工程师，帮 AI 公司出题、写标准答案、给模型打分。11 月 10 日它刚融了 7.5 亿美元，估值 200 亿美元，一年翻倍。现在不只大实验室，越来越多企业拿开源模型自己训练，都需要这类数据和评测。Mercor 10 月起组建研究团队，LoRA 作者 Edward Hu 已经加入。

05｜Claude Code的AI改动验证清单

来源（X） · @Xudong07452910 · 2026-11-18 09:23

Claude Code 团队约 90% 的代码由 Claude 来写、来审。Addy Osmani 这篇新文章讲的是，到了这个比例，他们怎么让 Agent 拿出证据证明自己改对了。

我觉得最值得抄的有两个做法。

一：是改动碰不到判它的规则。Code Review 读的 REVIEW.md 永远取自主分支，不读 PR 里的版本。新的提交门禁也会先开 observe 模式跑一段，把误拦看清楚了再强制执行。

二：是一份 39 条的可靠性清单，每条都写明从 diff 里怎么识别、背后是哪次事故。Claude 读完 diff 只查触发到的那 3～10 条，谁都不用把历史事故背下来。

想同时跑很多个 Claude，前提是验证这一层足够可靠。这篇把这层当成正经系统来做，挺值得做 Agent 工程的朋友细读。
